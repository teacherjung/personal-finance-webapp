# UI3 投資持股表森林工作面

## 目標

把正式 App 的投資組合持股表整理成溫暖、清楚、適合長時間查閱的森林工作面。這一支只調整持股表的資訊層級、HTML 語意與頁面專屬樣式；所有金額、排序、持股分層、研究入口與寫入流程都沿用既有契約。

UI3 的高密度頁面分三支處理：

1. 銀行收支（已完成）
2. 信用卡費（已完成）
3. 投資組合持股表（本支）

## 預約範圍

- `public/modules/portfolio-tables.js`：只調整持股表 HTML 結構、語意屬性與專屬 class；保留資料輸入、分層、排序、格式器、研究入口與操作 data attribute。
- `public/styles.css`：新增以 `.portfolio-holdings-workspace` 為根的持股表專屬樣式，不改全站 token，也不改共用 `.stat`、`.num`、`.empty`。
- `test/portfolio-tables.test.js`：沿用並補強持股表固定輸入輸出考題。
- `test/portfolio-forest-ui.test.js`：鎖住森林工作面結構、操作入口、空狀態與樣式邊界。
- `prototype/forest-ui-lab/UI3-PORTFOLIO-PLAN.md`：本施工契約與驗收紀錄。

不修改 `public/modules/portfolio.js`、API、後端、資料庫、持股模型、金額公式、匯率、IBKR 同步、報價更新、持股表單或風險上限。

## 必須保持不變的資料契約

- 輸入仍是頁面算好的 `rows` 與 `total`；本模組不重算市值、成本或損益。
- 分層仍使用 `LAYERS` 與 `LAYER_ORDER`；未知 layer 仍歸入 `satellite`。
- 排序仍只在各層內進行，支援 `value`、`pnl`、`ret`、`weight`；非法鍵仍退回市值且不讀原型鏈。
- 降冪仍只反轉該層排序結果；不改其他表格的排序慣例。
- 金額、百分比仍由頁面注入 `formatMoney`／`formatPercent`；價格仍保留幣別，單價小於 10 時保留一位小數。
- 個股研究入口只給 `layer:'stock'`，並保留 `normalizePortfolioSymbol`、`encodeURIComponent`、`target="_blank"` 與 `rel="noopener"`。
- 所有使用者文字與資料 id 仍先經 `escapeHtml`。
- `data-edit-h`、`data-del-h`、`data-hsort` 必須原樣保留，讓 `portfolio.js` 的既有事件接線繼續工作。

## 版面契約

### 桌機

- 持股表前有獨立段落標頭，使用專業名稱「持股明細」，並顯示目前持股檔數。
- 表頭、分層、價格、市值、損益、報酬率、佔比與操作欄保持完整。
- 每個投資分層使用清楚的紙帶分隔，沿用既有分類色圓點；紙帶標籤在表格左右捲動時保持可見，不另創資料色。
- 表格維持自己的橫向捲動容器；長名稱截斷但保留完整欄位寬度。

### 手機

- 段落標頭與持股檔數上下排列，不擠壓標題或說明。
- 表格不改成會遺漏欄位的卡片；仍在自身容器內左右捲動。
- 操作按鈕保持固定尺寸，編輯與刪除不因欄寬改變而位移。
- 整頁不可水平溢出。

## 視覺規則

- 專業術語維持「持股／市值／損益／報酬率／佔比」，不改成樹木成長比喻。
- 使用暖白紙、深褐線與金色硬陰影；分類色只沿用 `LAYERS` 提供的既有色票。
- 不加大型森林背景圖，不降低數字密度，也不把每一列改成卡片。
- 小森森只在真正沒有持股時出現，並指向頁首既有「新增持股」入口。
- 不新增拖曳、縮放、聚焦、版面保存、動畫或新的資料摘要公式。

## 固定考題

1. 依層分組與組內排序結果保持不變；非法排序鍵仍安全退回市值。
2. `0` 成本、正負損益、手動報價、低價股格式與總額為 0 的佔比都有固定輸出。
3. 只有個股代號能開研究頁，其他 layer 維持純文字。
4. `data-hsort`、`data-edit-h`、`data-del-h` 與排序方向標示全部保留。
5. 所有持股文字、研究網址標籤與資料 id 都經過消毒。
6. 空資料顯示小森森與「尚無持股」，並只引導本頁既有的「新增持股」。
7. 所有新增 CSS 都鎖在 `.portfolio-holdings-workspace`，不得改共用 `.stat`、`.num`、`.empty`。
8. 桌機 1280×900 與手機 390×844：頁面 overflow 0、console error 0、表格可獨立橫向捲動。
