# UI3 信用卡費森林工作面

## 目標

把正式 App 的「信用卡費」整理成溫暖但仍適合查帳的森林工作面。這一支只改資訊層級、呈現結構與頁面專屬樣式，不新增財務功能，也不改退款歸屬或任何金額口徑。

UI3 的高密度頁面分三支處理：

1. 銀行收支（已完成）
2. 信用卡費（本支）
3. 投資組合持股表（下一支）

## 預約範圍

- `public/modules/transactions.js`：只調整信用卡費主畫面的 HTML 結構與 class；保留資料取得、退款歸屬、月份、排序、匯入、店家檔案、編輯、刪除與所有對話框流程。
- `public/styles.css`：新增以 `.credit-workspace` 為根的頁面專屬樣式，不改其他路由的版面。
- `test/transactions-forest-ui.test.js`：固定資料口徑與頁面接線契約。
- `prototype/forest-ui-lab/UI3-CARDS-PLAN.md`：本施工契約與驗收紀錄。

不修改 `transactions-import.js`、API、後端、資料庫、退款配對純函式、分類器或帳單解析器。

## 必須保持不變的資料口徑

- `isCardTx` 仍是信用卡帳本的唯一入口判準；銀行收支不可混入。
- 「本月消費」仍由 `consumptionCategoryTotals` 與退款配對結果加總，不能改成明細列直接相加。
- 「本月筆數」仍是帳單原貌的列數，包含退款；不得冒充淨消費筆數。
- `refundData` 讀取失敗時仍顯示帳面口徑退路與明確說明，不可靜默假裝退款已歸屬。
- 未配對退款仍不計入分類統計，且原有說明入口與金額保持可見。
- 分類長條仍使用 `topSpendCategories` 的前六名與既有正負色彩；0 淨額分類不捏造長條。

## 必須保留的操作入口

- `uploadStmt`：信用卡帳單上傳。
- 條件式 `stmtBatches`：已有匯入批次才顯示。
- `monthSel`：月份切換。
- `lensInfo`：退款月份口徑說明。
- 條件式 `unmatchedInfo`：未配對退款說明。
- `data-edit`／`data-del`／`data-store`：編輯、刪除與店家消費檔案。
- `bindSortClicks`：表頭排序。
- render 開頭的 route seq guard：慢請求不可蓋掉新頁面。

## 版面契約

### 桌機

- 頁首保留「信用卡費」專業名稱與上傳／匯入紀錄操作。
- 月份控制獨立成完整工具列，不與分類圖卡硬擠成兩欄。
- 本月消費、本月筆數與分類分布排成同一個總覽網格；摘要卡較窄，分類面板取得較多寬度。
- 明細表保留七欄與自身橫向捲動，並在表格上方顯示目前帳單列數。

### 手機

- 摘要改成兩列緊湊資訊列，標籤與數字不互相遮蔽。
- 分類面板與月份控制改為單欄滿寬。
- 表格維持自身橫向捲動；整頁本身不可橫向溢出。
- 空月份使用小森森中性表情，旁邊保留真正可採取的「上傳信用卡帳單」下一步。

## 明確不做

- 不新增信用卡額度、繳款日、預算、圖表引擎或新的資料來源。
- 不把信用卡消費算進銀行收支。
- 不改退款配對條件，也不把未配對退款自動猜配。
- 不改帳單預覽、匯入批次管理或 PDF 密碼流程。
- 不改店名學習、分類套用、表單 payload 或刪除確認。
- 不提供拖曳、縮放、聚焦或版面保存。

## 固定考題

1. 信用卡帳本在進入頁面統計前仍先經 `isCardTx` 篩選。
2. 本月消費仍由退款歸屬分類加總產生；本月筆數仍取當月明細列數。
3. `refundData` 失敗退路、未配對退款與兩個說明入口仍在。
4. 上傳、批次、月份、排序、店家、編輯與刪除入口全部保留。
5. 桌機總覽為兩張摘要加一個寬分類面板；手機摘要改成兩列，不壓縮成過窄小卡。
6. 空月份文案只引導本頁可用的信用卡帳單上傳，不跨帳本誤導。

## 驗收

- `node --test test/transactions-forest-ui.test.js` 與信用卡／退款／月份既有定向考題。
- `npm run typecheck`、`npm run lint`、`npm test`。
- 隔離 SQLite 實跑信用卡費：有資料、空月份、退款配對資料讀取失敗退路、未配對退款說明、月份切換、排序、店家檔案、編輯／刪除入口。
- 桌機 1280×900、手機 390×844；破圖、console error、整頁橫向溢出皆為 0。
- 其餘正式路由各做桌機與手機重載回歸，避免共用 `styles.css` 影響別頁。
