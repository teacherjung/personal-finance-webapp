# 榮祥森森林 UI 美術規格

這份原型只用合成資料，目的不是重畫正式 App，而是先驗證「完整資訊可以住在卡通森林裡」。在 William 確認前，不修改 `public/`、API、資料庫或既有頁面模組。

## 一、畫面原則

1. **天候輔助數字，不取代數字**：第一眼同時看到本月報酬率與對應天候，財務判斷仍以明確數字和專業術語為準。
2. **資料仍是 HTML**：金額、標題、按鈕、表格與圖表不畫進插圖，確保可搜尋、可讀取、可更新。
3. **插圖負責情緒與方向**：森林主場景承載狀態；工作區仍用清楚的紙張、表格與控制項。
4. **卡通感不靠犧牲對比**：深褐描邊、白紙工作面、綠／珊瑚／霧藍／金黃四組訊號色並用。
5. **手機不是縮小桌機**：主場景改成直向構圖，表格保留橫向捲動，控制項換行但不重疊。

## 二、視覺語彙

| 元素 | 規則 |
| --- | --- |
| 世界背景 | William 提供的投資森林：樹木、花石與中央路徑；天候可變，但不放文字 |
| 工作表面 | 暖白紙張、2px 深褐線、6–8px 圓角、硬邊金黃陰影 |
| 常用操作 | 沿用專案既有線條圖示；按鈕不另畫成圖片 |
| 數據圖 | Chart.js；線色與面積色沿用既有六色盤方向 |
| 角色 | 以 William 提供的森森嚮導為角色原型，只出現在提醒、空狀態與完成狀態，不遮住表格 |
| 動效 | 150–220ms 的按壓、展開、輕微上下浮動；不做持續大幅移動 |

## 三、素材分層

- `場景`：總覽、收支、投資、研究、設定各一張寬景；WebP／PNG。
- `角色狀態`：平靜、提醒、完成、思考、空狀態、載入、錯誤、歡迎共八張透明圖。
- `裝飾零件`：葉片、花、石頭、木牌、紙膠帶、印章等；只補空白，不承載功能。
- `功能圖示`：沿用 `public/modules/icons.js`，未來若換 Lucide 也維持同一個介面。
- `資料圖表`：Chart.js 與 HTML/CSS，不生成點陣圖。

## 四、本月報酬情境素材

- `assets/forest-return-positive.webp`：William 提供的晴朗投資森林原圖。
- `assets/forest-return-neutral.webp`：保留原構圖的陰天版本。
- `assets/forest-return-negative.webp`：保留原構圖的溫和雨天版本。
- `assets/guide-return-positive.webp`：微笑表情，用於正報酬情境。
- `assets/guide-return-neutral.webp`：中性表情，用於接近持平情境。
- `assets/guide-return-negative.webp`：審慎思考表情，用於負報酬情境。

原型暫以 `+0.5%`、`−0.5%` 作為純視覺切換門檻：高於 `+0.5%` 為晴朗，介於兩者之間為陰天，低於 `−0.5%` 為雨天。這不是新增財務公式；正式接線時只讀既有系統算出的本月報酬率，門檻須另行確認並補固定考題。

森林原圖與嚮導表情由 William 提供；陰天、雨天版本由 Codex 內建影像工具依原森林構圖製作。財金文案不得把報酬率寫成「長高」、把風險寫成「生病」；森林語彙只負責導覽與視覺情緒。

## 五、分段施工

1. **F0 森林 UI 實驗室（本 PR）**：合成資料總覽、桌機／手機、首批素材與互動元件。
2. **F1 外殼與 token**：只搬側欄、背景、字體、色票，不碰頁面資料流程。
3. **F2 正式總覽**：把既有 dashboard 資料接到森林狀態，不改公式。
4. **F3 高密度工作面**：銀行收支、信用卡與持股表；逐頁固定輸入輸出考題。
5. **F4 個股研究**：沿用既有頁籤契約，替換外觀與空狀態。
6. **F5 全站狀態素材**：載入、空白、錯誤、完成與危險提醒。
7. **F6 收官**：手機、鍵盤、對比、列印與所有路由瀏覽器回歸。

每一步一支獨立 PR。Codex 不自行合併；Claude 優先複審。若正式功能同期施工，該頁 UI 延後，不共改同一檔。
