# UI3 銀行收支森林工作面

## 目的

把正式 App 的「銀行收支」改成溫暖、清楚的森林工作面，同時保留它作為現金流真相的專業密度。這一支只改資訊層級與外觀，不新增財務功能，也不重算任何金額。

## 這一支只做一頁

UI3 的高密度頁面分三支處理：

1. 銀行收支（本支）
2. 信用卡費（下一支，需重新從最新 `main` 開始）
3. 投資組合持股表（再下一支，需另寫 money-critical 接縫契約）

三頁不共用同一支 PR，避免同時碰多個資料流程與大量表格。

## 預約範圍

- `public/modules/cashflow.js`：只調整銀行收支主畫面的 HTML 結構與 class；保留資料取得、計算、排序、篩選、事件與所有對話框流程。
- `public/styles.css`：新增以 `.cashflow-workspace` 為根的頁面專屬樣式，不改其他路由的版面。
- `test/cashflow-forest-ui.test.js`：固定輸入輸出與接線契約。
- `prototype/forest-ui-lab/UI3-CASHFLOW-PLAN.md`：本施工契約與驗收紀錄。

## 不改的資料契約

- 資料仍取 `GET /transactions`、`GET /accounts`、`GET /categories`、`GET /income-categories`、`GET /transfer-subcategories`。
- `!isCardTx(t)` 仍是銀行收支的唯一帳本判準。
- 本月收入只加 `type === 'income'`；本月支出只加 `type === 'expense'`；`transfer` 不進兩者與結餘。
- 金額仍使用 `wan()`／`money()`，負號仍是 U+2212。
- 月份退路仍走 `deriveMonths()`／`fallbackMonth()`，不新增月份公式。
- 排序仍走 `tx-sort.js`；篩選仍是全部／收入／支出／內轉。
- 上傳、預覽、確認匯入、匯入紀錄、編輯、刪除與「同類一起改」流程完全保留。
- 不改 API、後端、資料庫、schema、分類樹、帳本或匯入器。

## 固定版面

### 桌機

1. 頁首：頁名、專業說明、三個既有動作。
2. 月份摘要紙張：本月收入、本月支出、本月結餘；三個數字保持同一視覺層級，結餘不做英雄式放大。
3. 工具列：月份選單與金流 segmented control，保持單行可掃描。
4. 明細工作表：表頭、排序、數字右對齊、列動作全部保留；只有表格容器可以橫向捲動。

### 手機

1. 頁首動作可換行，但按鈕文字不可被裁切。
2. 三張摘要改成一列可讀的小卡或單欄；不得造成頁面水平溢出。
3. 月份與金流控制上下排列；每個控制都有可見標籤。
4. 明細仍使用既有橫向表格，不改成會藏欄位的卡片清單。

## 視覺規則

- 專業術語維持「銀行收支／收入／支出／內轉／結餘」，不把金流改叫溪水、果實或成長。
- 工作面使用暖白紙、深褐線與金色硬陰影；收入、支出與內轉沿用既有語意色與文字標籤。
- 不加大型森林背景圖，避免高密度查帳頁被插圖壓縮；小森森只在真正的空狀態出現，而且不遮表格。
- 不新增拖曳、縮放、聚焦、版面保存、月份重播或裝飾性動畫。
- 所有使用者資料仍須經 `esc()`；既有 icon 與 tooltip 保留。

## 固定考題

1. `0` 是合法收入／支出，不因真值判斷消失。
2. 內轉不進收入、支出或本月結餘。
3. 舊資料缺 `ledger` 時仍依 `isCardTx` 排除信用卡帳本。
4. 全部／收入／支出／內轉四個篩選都保留既有按鈕與事件入口。
5. `monthSel`、`uploadBank`、`bankBatches`、`addCf`、`data-edit`、`data-del` 接線仍存在。
6. 空月份文案只說「本月尚無銀行收支」，不引導使用者去信用卡頁上傳銀行對帳單。
7. 桌機 1280x900 與手機 390x844：頁面 overflow 0、console error 0、表格可獨立橫向捲動。

## 回復與合併後

純前端頁面改版；若視覺驗收不通過，整支 PR 不合併即可。沒有資料搬家，不需重啟後端，重新整理頁面即可。
