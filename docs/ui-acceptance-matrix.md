## 狀態定義

| 狀態 | 意義 |
|---|---|
| 已驗收 | William 已確認目前設計可保留，且有相稱的自動或瀏覽器驗證。 |
| 有基礎 | 已有實作與部分驗證，但尚未完成本表要求的整頁驗收。 |
| 待整理 | 功能存在，但尚未完成該階段的集中 UI 整理。 |
| 待決定 | 需要 William 決定產品方向或是否需要這項能力。 |
| 已退回 | 現行設計已被 William 明確否決；即使程式與考題存在，也不能算完成。 |
| 不適用 | 該頁沒有這項使用情境；需在備註說明理由。 |

## 全站驗收門檻

一頁只有在下列適用項目都完成後，才可在「目前結論」標成「已驗收」。

| 面向 | 驗收方式 |
|---|---|
| 視覺語言 | 背景維持暖米色；理財中心錢幣橘用於邊線、底線、排序、focus 與選取文字；綠色只用於主要動作與正向財務語意。 |
| 元件一致性 | 按鈕有圓角；卡片邊線、陰影、間距與標題層級一致；圖示與文字不擠壓、不重疊。 |
| 桌機 | 以 1280×900 實際操作主要流程；內容不被截斷，表格、圖表與動作列保持清楚。 |
| 手機 | 以 390×844 實際操作主要流程；頁面本身沒有水平溢出，需要寬度的表格只在自己的容器內捲動。 |
| 狀態 | 載入、首次空白、篩選後空白、錯誤、成功與必要引導各自可辨識；錯誤可重試，成功不被晚到的舊畫面覆蓋。 |
| 鍵盤 | Tab 順序合理、focus 清楚；按鈕與連結可用 Enter／Space 操作；彈窗可關閉且焦點不迷失。 |
| 列印 | 只有確定有列印需求的頁面才驗；A4 不重疊、不截字，畫面按鈕不進列印內容。沒有需求時標「待決定」或「不適用」，不可假裝全站都完成。 |
| 回歸 | 正式路由逐頁重新載入，瀏覽器 console error 為 0；既有操作入口、數字格式與資料口徑不因外觀調整而改變。 |

## 更新方式

- UI 實作合併不等於自動改成「已驗收」；需同時留下驗證證據與 William 對目前畫面的確認。
- 現行設計被退回時，直接標「已退回」，不要因已有大量程式或考題而保留完成標記。
- 新增正式路由時，需在本表增加一列；移除路由時一併移除，不保留幽靈頁面。
- 本表是進度視圖，不取代 `AGENTS.md` 的 UI 慣例、領域契約或 PR 協作規則。
