## 〇、定位與已鎖定的決定

**定位**：在總覽用一句白話回答「照這速度，我離淨值目標還有多久」。屬洞察引擎「有感解讀第二批」，但它是**常在型統計**（每次都在），不是事件型差異——所以放**常駐小字/小卡**，不塞事件新聞牆，才不會破壞平靜日安靜（洞察哲學原則 1/2）。

| 決定 | 拍板 |
|---|---|
| 速度口徑 | **兩個都給**：①存錢速度（純現金流存入、你能控制）②淨值成長（含市場漲跌、會變動），並列、標清楚 |
| 目標形態 | v1＝**單一淨值目標**（一個數字）；里程碑清單（100/500/1000 萬）列為 future（拍板點，見文末） |
| 目標口徑 | **淨資產（資產−負債）、台幣**，釘死 |
| 輸入單位 | 設定頁用**萬元**輸入，後端仍存台幣元；旁邊顯示換算後完整金額 |
| 落點 | 併進總覽最上方「淨資產」區，做精簡進度條，不另增大卡 |
| 資料不足 | 目標已設定就顯示目前進度；速度欄寫「資料累積中」，不讓功能像消失 |
| 達標 | 目標區顯示「已達成」；v1 不進新聞牆，避免把好消息誤當待處理提醒 |
| 速度窗口 | 最近六個**已結束月份**，至少三個月；採中位數，降低一次性大額月份干擾 |

## 一、使用者需求

- **使用者**＝老師本人。**要回答**：「照我最近的狀況，離我設的淨值目標還要多久？」
- 為什麼「兩個速度」：淨值成長含市場漲跌，會讓達成日忽快忽慢、過度樂觀（把行情當努力）；純存錢速度是你能控制的、誠實但偏保守（忽略投資成長）。**兩個並列＝把估計「夾」在保守與含市場之間，最誠實。**
- **v1 不做**：里程碑清單、走勢圖上的目標線（候選 3-6，future）、拆解「市場 vs 匯率 vs 存錢」（候選 1-5，future）。

---

## 二、操作流程

1. **設定頁**新增「淨值目標（萬元）」輸入。留空送 `null`＝不啟用；送出前換回台幣元保存。
2. **總覽淨資產區**顯示目標進度（目標一經設定就出現）：
   - 「距離目標 [target] 還差 [gap]。」
   - 「依你的**每月現金結餘**：約 **X 個月**」（旁 .info-link）
   - 「依**整體淨值變化**：約 **Y 個月**」（旁 .info-link，含市場、匯率與帳戶更新）
   - 該速度資料不足時，原位置顯示「資料累積中」。
3. **達標**（現值≥目標）：同一區塊顯示「已達成」，不建立提醒事件。

## 三、資料來源與計算口徑

**全部現成、無需外部抓取**（與 ②大盤 不同——這也是先做 ③ 的原因）。

| 要素 | 來源 | 依據 |
|---|---|---|
| 現值（現在位置） | `computeAssets(db).netWorth`（台幣） | [derive.js:154-182](../lib/derive.js) |
| 目標 | **新** `settings.netWorthTarget`（正數或 `null`、台幣元） | 需加 schema＋emptyDb＋設定頁；`null` 才能真的清除舊目標 |
| 每月現金結餘 | 最近六個已結束月 `computeCashflow(db,mk).net` 的中位數（income−expense，transfer 不計） | [derive.js:189](../lib/derive.js)；只算有現金流資料的月份 |
| 整體淨值變化 | 最近六個已結束月 `snapshots` 的每月 netWorth 變化中位數 | [snapshot.js:37-52](../lib/services/snapshot.js)；相鄰快照先除以實際相隔月數 |

**新純函式 `computeGoalTracking(db, now)`（放 `lib/derive.js`）**
- 目標未設或 ≤0 → 回 `null`（整段不啟用）。
- `current = computeAssets(db).netWorth`；`current ≥ target` → 回 `{reached:true, target, current}`。
- `gap = target − current`。
- `savingsSpeed`＝最近六個已結束月的現金流 net 中位數（只算有資料月）；`netWorthSpeed`＝最近六個已結束月的月快照變化中位數。
- 快照缺月時，每段變化先除以實際相隔月數。例如一月 1,000 萬、三月 1,200 萬＝每月 100 萬，不是 200 萬。
- `monthsSavings = savingsSpeed > 0 ? gap/savingsSpeed : null`；`monthsNetworth = networthSpeed > 0 ? gap/networthSpeed : null`（**≤0 一律回 null，絕不算 −N 或 ∞**）。
- **樣本門檻**：現金流有資料月 <3、或不同月份的月快照 <3 → 該速度回 null（不硬估）。即使兩個都不足，也照樣回目前進度與 `{insufficient:true}`。

**接線（刻意避開洞察書籤，繞過最大風險）**
- ETA 是**常駐統計**（可重算、無「自上次」差異）→ 放 `buildSummary` 新增 `goalTrack` 欄位（[derive.js:704-728](../lib/derive.js)），總覽渲染。**不動 `insightState`／`sanitizeInsightState`**（避開 grounding 點名的最大坑：書籤欄位漏白名單被靜默剝除）。
- **達標不進 reminder**：現有新聞牆把提醒消失顯示成「已解除」，好消息若混入，日後清除或調高目標會出現錯誤語意。v1 只在目標進度區顯示「已達成」。

## 四、可能讓數字算錯／誤導的風險（money-critical）

| # | 風險 | 防法 |
|---|---|---|
| R1 | **把市場漲跌當成存錢速度**（淨值含持股市值，單月大盤漲→速度暴增→過度樂觀達成日） | 這正是「兩個都給」的用意：存錢速度**用現金流 net、不含市場**；淨值速度**明標「含市場、會變動」** |
| R2 | **負成長/趨平算出荒謬 ETA**（−N 個月、∞） | 速度 ≤0 一律回 null，改誠實文案（見下），絕不顯示負月數/∞（比照 `computeWindows` 守則） |
| R3 | **樣本太少硬估**（新使用者 0–2 月） | 有資料月 <3 / 快照月份 <3 → ETA 顯示「資料累積中」 |
| R4 | **匯率波動被當資產成長**（外幣持股，`settings.usdTwd/fxTwd` 一改 netWorth 就跳） | 存錢速度天然不含匯率；淨值速度標「含市場與匯率」；文案不宣稱是「你的努力」 |
| R5 | **分母誤用 assets 而非 netWorth**（有房貸/融資者被高估） | 一律用 `netWorth`（資產−負債）；目標也釘死 netWorth、台幣 |
| R6 | **單月離群點讓外推爆走**（一次大額進出/崩盤月） | 最近六個完整月採**中位數**，不讓單一特殊月份主宰結果 |
| R7 | **近月現金流不完整**（帳單未匯入→存錢速度偏低） | 只算「有現金流資料的月份」（比照 `avgMonthlyExpense`）；文案可帶「依已記錄的月份估」 |
| R8 | 目標值 0/負/非數字、還原舊備份無此欄位 | schema `posnumopt` 只收正數或 `null`；還原舊備份→欄位安全預設、不報錯 |
| R9 | **把未結束本月當完整月**（月初只記幾天，速度被嚴重拉歪） | 兩種速度都只看已結束月，本月只用於「目前位置」 |
| R10 | **快照缺月卻按列數平均** | 相鄰快照先按真實月份間隔換成每月速度，再取中位數 |

**誠實文案（速度≤0 時）**：存錢速度≤0→「最近沒有淨存入，暫時估不出到達時間」；淨值速度≤0→「最近淨值在下滑（含市場）」。生存優先＝報憂但不假樂觀、也不嚇人。

## 五、邊界情況

- 目標未設定 → 整段不出現。
- 現值已達成/超過 → 顯示「已達成 🎉」，不出現負月數；（future 里程碑版才自動投影下一個）。
- 只有一個速度算得出（例如有快照無現金流）→ 顯示算得出的那個、另一個標「資料累積中」。
- 兩個速度都算不出 → 仍顯示進度條、目前與目標；兩個速度都標「資料累積中」。
- 兩個速度差很大（市場大漲/大跌）→ 正常，正是要讓使用者看到「靠存錢 vs 含市場」的差距。
- 目標設得比現值小很多（打錯字）→ 顯示已達成，不報錯。

## 六、頁面上要就地解釋的事（.info-link／openInfo，產品鐵則）

文案草稿、老師審字：
- **《「存錢速度」和「含市場」差在哪？》**：存錢速度＝你每個月實際存下/投入的錢，是你能控制的；含市場＝連投資漲跌一起算，會忽快忽慢。兩個都給你，是因為市場不該被當成你的努力。
- **《為什麼「含市場」那個會變來變去？》**：它把最近的股市漲跌算進去了。市場好時看起來很快、市場差時很慢，甚至倒退——所以只當參考，別當保證。
- **《為什麼有時候不顯示到達時間？》**：資料還太少、或最近沒有淨成長時，硬算會給你一個假的精確數字，不如先不顯示。

## 八、應補的測試題目（隔離 DB）

- ✅ 目標未設 → `computeGoalTracking` 回 null、總覽不出現。
- ✅ 樣本 <3（現金流/快照）→ 該速度 null、不硬估，但進度仍存在。
- ✅ 速度 ≤0（趨平/下滑）→ 回 null，不產生 −N 或 ∞。
- ✅ 現值≥目標 → reached=true、不出現負月數，也不污染 reminders。
- ✅ 分母用 netWorth：有負債者不被高估（assets vs netWorth 對照）。
- ✅ 單月離群（一次大額進出）→ 六月中位數不被它拉歪。
- ✅ 本月有巨額收入／淨值跳動 → 不進速度樣本。
- ✅ 快照缺月 → 依實際月距正規化後再取中位數。
- ✅ 存錢速度只算有現金流資料的月份（半記錄月不拉低）。
- ✅ 外幣持股＋改 usdTwd → 存錢速度不受影響（不含匯率）；淨值速度會變（含市場，符合預期）。
- ✅ 目標 0/負/非數字 → schema 擋；還原無此欄位的舊備份 → 安全預設、不報錯。
- ✅ 端到端：設目標＋種近 6 月快照與現金流 → `GET /api/summary`（或 goalTrack）兩個 ETA 正確。
