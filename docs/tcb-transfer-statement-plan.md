# 合作金庫電子化轉帳明細施工計畫

## 目標與範圍

讓本機銀行帳單入口讀取合作金庫電子綜合對帳單的「電子化轉帳交易明細／網路銀行（含行動網銀）轉帳交易明細」。此區只提供文件明列的轉帳，不代表整月完整存款流水。範圍依 [2026-10-11 裁示](https://github.com/teacherjung/personal-finance-webapp/pull/671#issuecomment-6109434602)。

版型表頭包含交易日期、交易時間、摘要、轉出帳號、轉入行／轉入帳號、轉出與轉入幣別／金額、手續費幣別／金額、備註。區名與交易表可分在前後頁；金額、手續費與備註會分行。表格沒有逐筆餘額。原始文件與開檔密碼不進版控，考題只用全新合成資料。

## 施工順序

1. 用正式 PDF 抽字工具核對欄位位置與分行；建立合成 PDF 與獨立手寫答案。合成多筆／跨頁題只作壓力情境，不宣稱已驗證銀行所有版型。
2. 在 `lib/bank-statement.js` 內新增私有合庫辨識與解析函式，由 `parseBankStatement` 分流；沿用抽字、密碼處理、資源限制與既有回傳欄位，不新增端點或資料欄位。
3. 只讀指定區內有依據的台幣交易。逐筆餘額維持缺值，不從概要倒推；未見明細不能回報零交易匯入成功。非零手續費、外幣、欄位缺漏或歧義明確拒收，不能猜測或靜默遺漏。涉及金額口徑或欄位歸屬的額外需求另提具體問題。
4. 概要只讀台幣綜合存款的基準日餘額，供來源帳戶配對；不宣告涵蓋定存、不由缺席推定定存到期。交易時間與收款帳號併入既有備註，保存同日同額不同時間的辨識資訊。接上既有預覽、分類、帳戶配對、去重及確認後寫入流程；不把轉入對方自動當本人帳戶、不放寬不同銀行相同末碼的比對。
5. 以合成材料驗證正式 PDF 入口及隔離資料庫的預覽／套用，做有效突變、舊版型回歸與三關，依專案流程複審、掃描、合併及驗收。

## 核准的匯入補強

依 [2026-10-12 裁示](https://github.com/teacherjung/personal-finance-webapp/pull/678#issuecomment-6116958755)，合庫帳單 accounts 與 accountCurrency 的末碼至少四位才作本人轉帳證據，四位以上保留整段比對，不把六碼裁成四碼。依[範圍裁示](https://github.com/teacherjung/personal-finance-webapp/pull/678#issuecomment-6118181784)，其他銀行保留既有短末碼判斷，包含台新三碼外幣自有戶的內轉辨識。「合作金庫」與「合作金庫銀行」沿用銀行別名機制正規化為「合作金庫」，不回寫既有機構戳或去重鍵，不合併其他法人或猜英文別名。共用檢查階段採「正在檢查可驗算的資料…」「檢查完成，正在整理預覽…」，弱驗證說明保留。

## 驗證與邊界

- 解析：欄位位置、民國日期、方向、金額、換行備註、區名與表頭跨頁、同日同額不同筆；缺表、壞日期、壞金額及不支援格式明確失敗。
- 概要限制：台幣概要若含非「綜合存款」的存款種類，整份拒收；首次需要支援時另裁範圍，不從該列猜測種類或到期狀態。
- 匯入：預覽唯讀、確認後寫入、重匯不加倍、異銀行同末碼不誤配、既有交易保留。
- 驗算：內建解析沿用缺數字時的弱驗證，畫面沿用既有驗算限制提示；AI／規則卡仍要求強驗證。不得用同一個數字與自己相比灌出覆蓋率。
- 回歸：既有台新銀行與富邦／台新信用卡版型保持既有輸出。
- 突變：移除版型限制、破壞分欄／分行、強制錯誤方向／金額等，各自必須使對應考題失敗。保存型題保留受測操作，只破壞保存機制。

## 改檔與復原

候選路徑：`lib/bank-statement.js`、`test/tcb-transfer-statement.test.js`、必要的合成夾具、`docs/contracts/income-expense.md`、`docs/test-coverage-map.md`，以及本計畫與 [開源研究](statement-parser-research.md)。若新增契約責任檔，依既有生成流程更新路由清單。

匯入及金額解析列高風險。失敗最糟可能錯記交易或配錯帳戶，因此沿用預覽→確認→原子寫入；驗證只用隔離假資料。程式復原為回復本支合併提交。整批刪除只移除該批交易，不會復原帳戶：新建的帳戶須確認沒有後續使用後另行刪除，既有帳戶的餘額與基準日須依匯入前紀錄回復。驗收的確認寫入與重匯在隔離假資料庫進行，不由施工腳本操作使用者資料。前端累積畫面修改與雲端功能不在本支範圍。

## 有限拒收條件的獨立回歸補題

本階段只補現行限制的考題與證據，不修改解析器、匯入服務、銀行別名、帳戶身分或契約判準。施工路徑限 `test/tcb-transfer-statement.test.js`、本計畫及 `docs/test-coverage-map.md`。

各題先讓本題的完整合成 PDF 走正式 `parseBankStatement` 成功，再只破壞一項條件；拒收核對 status、code 與目標原因。涵蓋摘要與存款種類、概要正負金額邊界及交易金額上限、基準日缺漏／不同行重複、單獨重複轉帳區、必要表頭齊全但多未知字樣、跨頁交易只缺續頁表頭，以及結尾後各自單獨出現的已知表頭、民國日期、遮罩帳號或網銀摘要。

突變逐項撤除對應保護，先核替換位置唯一、基準綠，再確認預定題因目標判準失守而紅，還原後綠；準備失敗、無題執行、語法錯或其他拒收均不採計。結尾後各證據分支分開撤，不用整列交易讓其餘分支代打。既有隔離庫預覽／套用與拒收保存題保留，本階段不新增資料寫入能力。

真實多頁頁尾、續頁頁首、重印基準日、備註行距、其他存款種類、銀行別名與本人帳戶認定仍需實際來源；合成反例只證明現行限制，不替銀行全版型背書。覆蓋圖的抽字與落盤總稱按現有合庫題收窄，其他分支未全面盤點。執行結果與有效突變證據由本階段 PR 保留；未取得結果前不宣稱補題完成。
