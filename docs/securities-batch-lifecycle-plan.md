# 證券匯入紀錄晚回應保護施工計畫

## 目的與有限範圍

承接既有 GS-F04 與 AGENTS.md「理財優化續作」授權，Codex 實作、官方 Grok 複審，掃描暫停。本支只處理 `securities.js` 的匯入紀錄初載、批次刪除接續、原批次窗重讀及必要的主列表呈現資格，不改後端刪除規則、帳務、金額、外觀或 IB 同步。設定與信用卡批次入口另支承接。

## 基線與證據界線

基底為 #741 合併提交 `0d5ac3d1ca1a12710c1caf014ec4307ea3c9e2c8`。以 AST 擷取正式 `openSecBatches`，有限 DOM 外殼與 API 替身延後初載，期間另開視窗並填入本題專屬輸入，放回 GET 後新窗遭替代、輸入消失。此為隔離函式重現，不是全模組、真 HTTP 或原生瀏覽器證據；正式回歸另補。

## 擬採修法與待核邊界

- 初載以唯讀彈窗觀察、完整 hash／換頁世代及開啟代次保護，不提前搶占現有視窗。
- 窗內操作核原節點與目前資格；同批次確認及請求在途防重。關窗或換頁不撤回已送出的刪除。
- 有效刪除成功後，批次內容在原窗更新，不由舊回應另開外殼；主列表與批次內容的重讀分開資格及錯誤處理，不將 GET 失敗說成刪除失敗。
- 過期成功／失敗不干擾新視窗、輸入、通知或其他頁面；同頁背景重繪不等於換頁。主列表同頁多次讀取須防止舊讀取覆蓋新讀取。
- 正常成功流程與各域失敗的精確交接、多批次交錯，待指定 Sol 技術裁示公開後定稿，不以本計畫代替裁示或驗證。

## 驗證與交付

正式考題使用每題獨立合成帳本、完整正式模組及 LOCAL HTTP；請求在入口認領延遲屏障，不能依回覆到達順序挑請求。涵蓋初載、刪除及雙域重讀成功／失敗、取消與各關窗手勢、新窗與開後關、立即導航與離開返回、同頁背景讀取、有效重試及防重。檢查正常刪除與兩域更新確實發生、其他資料保存及 IBKR 批次不提供刪除。

逐點有效突變前先確認替換目標存在及基線通過，撤守衛後必須由行為斷言失敗，不將語法錯、載入錯或逾時當證明。既有接線形狀題若需配合合法寫法調整，保留實際刪除後重讀的行為證據。

型別、格式、完整考卷及原生桌面合成驗證完成後才送正式 Grok；逐項核收、公開留痕、正式合併關卡及合併後工具驗收。不讀真帳本、不觸發真 IB 同步、不宣稱本人實看。
