# qs 安全修補計畫

目的：處理 GHSA-6pq8-jhm2-2vcw，將 qs 的安全下限及鎖定結果升至公告修補版，保留其他相依的既定範圍。

## 來源與範圍

- [上游公告](https://github.com/advisories/GHSA-6pq8-jhm2-2vcw)列受影響版本為 6.7.0 至 6.16.0、修補版為 6.16.1。
- [既有技術裁示](https://github.com/teacherjung/personal-finance-webapp/pull/748#issuecomment-6514104671)要求下一個可依程序開工的後端相依修補優先處理。
- 預計變更：`package.json`、`package-lock.json`、本計畫與 `PROJECT.md` 的該項狀態。全面待辦整頓另支處理。
- 不改應用的 API、欄位、公式、畫面或正式檢查判準。相依圖如出現 qs 修補所需的直接相依變更，逐項核上游宣告；無關升版拒收。

## 實作與證據

1. 保留原有相依，使用 npm 的 `--package-lock-only --ignore-scripts` 更新鎖檔；這一步不代表本機已安裝修補。
2. 核對完整鎖檔差異、所有 qs 解析位置、公開 tarball 的完整性與相依宣告。
3. 在樹外以公開新舊產物和合成輸入核一般序列化、解析及公告反例；同一個防止例外的斷言須能區分舊版與修補版。此項只證指定 qs 行為，不證本應用存在可利用終點。
4. 完成三關、自審及當版 CI 核對；本機若沿用舊相依，與 CI 從新鎖檔乾淨安裝的相容證據分開記錄。
5. 依官方入口交 Grok 正式複審，不改提示或接線；掃描依本人停止指示記未執行。正式複審及所有合併閘均須通過。

## 交付與復原

- 純相依修補可回復該支提交；不做資料搬移。
- 依正式分級執行 B 級交付。本機安裝、重啟與本人核心流程未做時須保留未完成；不將 CI 成功寫成本機修補已生效。
- 不刪除或重裝既有 `node_modules`。若正式程序仍須本機新相依映像，先留下可審成果，再就具體安裝動作交本人決定，不以技術裁示解除此限制。
