# 測試覆蓋率地圖

> 目的：找出「重要財務邏輯有沒有考題」，不是追求漂亮的總百分比。
> 沿革：Codex 建立（2026-07-22 基準）→ 系統優化階段三全面更新（2026-07-24，三路查證＋缺口獵捕）。

## 怎麼執行

```bash
npm run test:coverage
```

這個命令使用 Node 內建的 coverage，不新增套件。它會先跑完整測試，再列出被測試載入之檔案的行、分支與函式覆蓋率。

## 怎麼讀報告

- 報告只包含測試過程中**曾被載入**的檔案。沒有出現在表內的前端頁面，不能解讀成已完整覆蓋。
- 全庫百分比適合觀察突然大幅退步，不適合當合併門檻；新增幾行說明或載入另一個大檔都可能改變數字。
- 財務 App 的優先順序是：金額公式、資料搬家與備份、整批原子寫入、機密欄位投影、外部帳單與券商資料解析。
- coverage 輸出裡的 `[schema] 剝欄位`、store 搬家衝突錯誤堆疊等訊息是**守門考題故意餵壞資料的迴聲**，不是測試失敗（以「fail 0」為準）。

## 誠實缺口（已知、有記錄，非疏漏）

1. **pdfjs 抽字層三胞胎**：`statement.js extractLines`／`bank-statement.js extractBankLines`／`taishin-securities.js extractSecuritiesLines` 逐字或近似重複、所有解析考題都從「合成座標列」進場——pdfjs 升級只會在使用者實際上傳時暴露。三份為**刻意分工**（AGENTS 同步點有列），日後若歸戶可一併補一條合成 PDF 端到端考題，順帶蓋住 `parseTaishinSecuritiesPdf` 的 async 包裝。
2. **匯入落盤薄殼**：`applyBankStatement`／`importTaishinPdf` 這種「解析→套用→saveDb」的接線零直測（純函式層全測過）；接線回歸＝按匯入回 ok 但資料沒落盤。需要合成 PDF 端到端，與第 1 條同根因、留待歸戶時一併補。
3. **證券兩個 POST 路由殼**（import／batch-delete）缺的是**成功路徑**的 HTTP 煙霧測（服務層有完整直測；失敗與防線路徑已有 HTTP 級考題打到 `/api/securities/import`——大檔分流 `test/request-limits.test.js`、未登入 401 `test/hosted-auth.test.js`、名額 back-pressure `test/heavy-admission.test.js`）；漏的是「成功時路由接線」一類錯，價值中等。

## 維護規則

1. 改到金額、日期、幣別、方向或分類口徑，必須補一條能重現錯誤的考題。
2. 改到整批更新，至少考「成功全寫」與「中途失敗全不寫」。
3. 改到資料搬家或匯入，使用暫存 `STORE_FILE`，考舊格式、壞格式與衝突情境。
4. 改到 API 回傳，確認一般讀取不外洩機密，備份還原仍可完整往返。
5. 每次大型重構後重跑本命令，更新本表的判斷與真正缺口；不因單一百分比下降就補低價值考題。**明確不追的低分支率清單**：store.js（錯誤處理）、secret-fields.js（遮蔽 fallback）、monthly-review-card.js／portfolio-report.js（呈現支線）、server.js（開機接線）。
