# 測試覆蓋率地圖

> 目的：找出「重要財務邏輯有沒有考題」，不是追求漂亮的總百分比。

## 怎麼執行

```bash
npm run test:coverage
```

這個命令使用 Node 內建的 coverage，不新增套件。它會先跑完整測試，再列出被測試載入之檔案的行、分支與函式覆蓋率。

## 怎麼讀報告

- 報告只包含測試過程中**曾被載入**的檔案。沒有出現在表內的前端頁面，不能解讀成已完整覆蓋。
- 全庫百分比適合觀察突然大幅退步，不適合當合併門檻；新增幾行說明或載入另一個大檔都可能改變數字。
- 財務 App 的優先順序是：金額公式、資料搬家與備份、整批原子寫入、機密欄位投影、外部帳單與券商資料解析。

## 2026-07-22 基準地圖

| 風險區域 | 主要程式 | 現有安全網 | 判斷 |
|---|---|---|---|
| 淨資產、訂閱攤提、提醒、槓桿 | `lib/derive.js` | 單元測試與邊界考題；行覆蓋約 99% | 強 |
| SQLite 搬家、備份、交易寫入 | `lib/store.js`、`lib/repo.js` | 搬家衝突 fail-closed、必填驗證、交易 rollback、備份回歸 | 強；錯誤處理支線不追百分比 |
| 整批修改不得半套 | `lib/routes/crud.js`、服務層 worker | G3 原子寫入與失敗回滾考題 | 強 |
| API 機密欄位投影 | `lib/secret-fields.js` | 一般 GET 遮蔽、備份匯出保留的整合測試；行覆蓋 100% | 強 |
| 信用卡／銀行帳單解析與分箱 | `lib/statement.js`、`lib/bank-statement.js`、兩套 import service | 合成帳單、方向、去重、學習與分類回歸 | 強 |
| IBKR Flex 持倉、現金與損益 | `lib/ib.js`、`lib/services/ib-sync.js` | 合成 Flex 報表鎖住持倉、期末現金、多幣別現金流、成交損益、缺匯率略過 | 中強；真實網路重試不列入單元覆蓋目標 |
| 前端互動與版面 | `public/modules/*.js` | 部分純函式測試與人工瀏覽器驗證 | 較薄；日後拆檔時逐步增加可測純函式 |

## 維護規則

1. 改到金額、日期、幣別、方向或分類口徑，必須補一條能重現錯誤的考題。
2. 改到整批更新，至少考「成功全寫」與「中途失敗全不寫」。
3. 改到資料搬家或匯入，使用暫存 `STORE_FILE`，考舊格式、壞格式與衝突情境。
4. 改到 API 回傳，確認一般讀取不外洩機密，備份還原仍可完整往返。
5. 每次大型重構後重跑本命令，更新本表的判斷與真正缺口；不因單一百分比下降就補低價值考題。
