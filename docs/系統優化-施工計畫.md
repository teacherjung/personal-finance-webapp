- **兩份地圖文件過期**：安全健壯地圖有六項狀態已變（SQLite/白名單/投影已完工）；覆蓋率地圖漏列台新解析器、securityTrades 雙寫等新區域。

## 階段四：健壯性收尾（等 Codex 個股研究 P2 合併後開工）

**A. 本機滾動備份**（防誤刪/錯誤匯入/App 寫壞——與異地備份是兩種保險，分清楚）：
- 啟動時檢查「今天是否已有備份」，沒有才建（App 不整天開著，不需背景計時器；實作時評估順手加「寫入時發現跨日且今日未備份→先備份」的懶檢查）。
- 沿用 `VACUUM INTO`＋原子改名；保留最近 **30 天**。
- 考題五條：同日不重複建立／超過 30 天正確清理／備份失敗不影響正式庫／備份檔可重新開啟／清理失敗不誤刪正式檔。
- **備份失敗的行為（裁決 2026-07-24）**：App 仍可開啟與操作；**畫面必須顯示明顯警告**（不可只記 server log）；**連續失敗應提高警告強度**。
- **宣稱範圍（裁決）**：本機備份只宣稱能防**誤刪、錯誤匯入與程式寫壞**，不宣稱能防硬碟／電腦損壞。
- **iCloud／外接碟自動備份維持暫緩**：資料庫含 IB token 與 PDF 密碼**明文**，直到有**加密備份格式＋明確使用者同意**；現階段保留手動匯出（Codex 修訂＋裁決確認）。

**B. 異常輸入防線**（裁決改名，原「文字長度上限」；分級，不設全站單一數字）：
- 名稱/分類/代號等短欄位＝**合理上限**；備註/論點/研究內容＝**極寬鬆技術上限**；**帳單原文等匯入內容不得被一般表單上限誤傷**。
- **不干涉正常寫作**；超過時**明確拒絕並說明**（CRUD／匯入＝明確 400），**不可靜默截斷**；strip／搬家模式對舊資料另行定義（合法舊資料不可因升級被刪）。
