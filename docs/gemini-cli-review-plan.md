# Gemini CLI 複審與 Grok 隔離掃描施工計畫

## 授權與交付

依[本人施工授權](https://github.com/teacherjung/personal-finance-webapp/pull/702#issuecomment-6248836328)，候選分工為 Codex 實作、Gemini 官方 CLI 複審、Grok 隔離掃描。先完成接線、驗證與獨立複審，再由本人確認正式啟用。Gemini 網頁掃描已由本人中止；本支保留其歷史工程與失敗證據，不追認為完成掃描。

另一工作線完成當前 PR 後，下一支預定採新分工，但須等本線驗收與本人啟用確認；預定角色不等於已有可用複審入口。現有正式角色與 scanner 設定不因本計畫改寫而自動切換。

## Gemini 複審邊界

- 使用固定官方 Antigravity CLI，登入由官方程式處理。不擷取或複製登入秘密，不把個人帳號狀態寫進公開材料，不開額外付費用量回退。
- 採可信任協作者的工作樹與工具權限紀律：受審樹供讀取，修改只在獨立突變副本；允許必要測試與唯讀版本核對。禁止主目錄、真實資料、私人認證的工具讀取，禁止 Git／GitHub 寫入、安裝、任意提權，以及不需要的網頁與 MCP 操作。
- 這是 Claude／Codex 類型的協作保護，不宣稱 OS 層單一憑證隔離。獲准執行的測試程式仍是可信任執行內容，工具規則不能保證攔住程式內所有存取。
- 每場以獨立設定及明確模型、推理啟動，不使用自動選模或全面略過權限。固定執行檔、設定及來源須有啟動前原件與雜湊，結束後再比對；只有事後雜湊不能證明啟動時用了哪份設定。

## 接線與收件契約

1. 沿用共用送審產生器的既有參數與 `launch.json`，另接專案自有 Gemini 入口；不改套件工具或 F3 範本。模型、來源與參與者僅在候選入口具備完整拒收與驗證能力後登記。
2. 候選政策的正式啟用值預設為關閉。資格場不能產生可發布的正式複審收據；正式用途缺本人啟用依據時，須在呼叫 CLI 前停止。不得以環境變數或臨時參數跳過。
3. Gemini 使用自己的收件契約，保存完整 stdout、stderr、原生事件及雜湊；核對固定來源、明確模型／推理、單一新對話、版本、輪次、提示與唯一完整末尾回覆。不裁切模型答案，不冒用 Grok 收據或舊掃描 findings 格式。
4. 工具日誌僅私存；待發布的完整結論另作機密、路徑與完整性核對。外層取得公開 GitHub 材料並代貼完整結論，貼後依 F7 核對。資格場不貼正式結論。

## Grok 恢復方式

沿用既有 `scripts/grok-scan.js`、OS 隔離、盒外真憑證中繼、盒內假憑證及掃前後檢查。整合另一工作線已合併的執行時限修正，不降低隔離。恢復候選設定與正式切換分開；資格驗證須標明掃描用途，不把 review 用途或合成場計為 G1。正式啟用前核對發射者實際能力，不直接沿用歷史人名與能力登記。

## 驗收與停止條件

- 合成資格須證明實際讀檔與測試、正常基線通過、突變失敗、受審樹寫入拒絕、外部合成檔讀取拒絕、未列指令拒絕，以及受審來源前後一致。拒絕控制須有實際嘗試的事件；檔案沒出現不等於操作曾被攔截。
- CLI 退出零或原生 `SUCCESS` 不代表完成複審；空回覆、未跑測試或缺必要證據均不通過。設定選取與權限行為未證明前，不以全面放行或取消保護換取成功。
- 遇到失敗先保留原件並查具體原因；只有可核對的修正依據才重驗，不反覆變更參數碰運氣。能力未過時停在候選，不登記為可用的正式入口。
- 能力、收件與隔離驗收完成後，才做必要考題、有效突變、型別、格式、完整測試與獨立複審，最後提出具體成果讓本人確認啟用。

## 回復

候選驗證失敗時保持正式啟用關閉，保留失敗證據與原角色設定。正式切換另有本人確認；若後續已切換的入口驗收失敗，先停用並回復該次設定提交，不改登入秘密或追認失敗場。
