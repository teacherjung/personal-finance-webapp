# 信用卡消費說明與桌機列表調整

## 需求與範圍

原需求為消費說明可選擇只改單筆，或同步修改前相同說明的信用卡明細與相關原文的未來匯入；分類與說明分開選擇。桌機消費日顯示月日、欄寬跨月一致，銀行收支主頁明細隨容器伸縮。

本輪依理財待辦處理及推薦代選委任接續保存草稿；保留原草稿歷史，不把過去只留本機的紀錄倒寫為已送審。正式技術裁示、產品代選與審查結果由本支 PR 留痕；代選不等於本人實看。

## 說明修改的資料界線

- 服務層擁有 `noteMode:'custom'|'auto'`。單筆修改保留文字，單筆清空回自動名稱，共用名稱規則保持；分類傳播、整理及重新讀取須尊重單筆意圖。缺欄位的舊資料沿用舊語意，不批次猜測本人是否曾手改。
- 同步按修改前的完整顯示說明逐字選取現有卡帳，跨月份與卡片，排除銀行現金流。表單帶本次選擇所依據的原說明，在同步 `beforeSave` 內用 fresh prev 驗證；來源已變更時回衝突，要求重載核對，不沿新名稱擴群。
- 控制欄位不落庫；`applySameNote` 只認布林 true，與分類 `applyAll` 獨立。前端不能指定 `noteMode`。本筆、其他受選列、名稱及分類學習在同一次同步 `beforeSave` 完成，錯誤整筆不寫。
- 未來名稱只依具有合法帳單原文的目標建立，`nameScope:'original'` 限制名稱而不改分類優先序。服務費、沒有可驗證原文的手動卡帳不建立未來名稱；同原文但不同顯示說明的未選列須保留文字。去重鍵保持。
- 同步清空只清此次涵蓋原文的名稱規則，分類學習保持；設定頁明確整批改名／還原是另一個覆寫入口。
- 同步選項旁在送出前解釋跨月跨卡、未來學習、單筆／同步清空及資料限制。回應不完整或連線中斷只能說結果待核，不聲稱未寫入、不自動重送。

## 桌機界線

消費日標籤與資料分開：編輯、儲存、排序及完整日期資訊保持。銀行主頁與信用卡表格依同一容器寬度維持跨月欄寬；長摘要可換行，九位數金額須清楚可讀且不擠入操作鈕。檢查窄桌機與一般桌機實際畫面。匯入預覽、手機排列與斷點不重設計。

## 已核實的施工前證據

保存草稿套上當時主幹後，型別檢查與 148 題相關測試通過，這不是新版本的完整三關或正式複審。

正式 LOCAL PUT 的隔離反例：A、B 同為舊說明，C 原為新說明；A 同步改成新說明時學習兩個原文，同內容重送卻擴為三個原文，C 被改成單筆保留。須以來源前置條件修正，並用破壞該條件的突變證明考題有效。

記憶體合成 PDF 經正式預覽及正式匯入，兩個受選原文帶入新名稱，同品牌的另一原文保持；合成 PDF 只驗文字及服務接線，不代表未見銀行版型已校準。

IAB 的 901／1024／1280／1440 像素桌機量測沒有頁面橫向溢出，1024 像素的跨月欄寬相同；901 像素的九位數金額會從數字中間換行，仍待修。預覽只使用本題合成資料。

## 驗證及收官

正式回歸涵蓋單筆保存、同步跨月跨卡、同原文異顯示名、同品牌異原文、原文等於品牌鍵、分類與說明選擇組合、清空、設定頁還原、保留字回滾、備份還原、過期表單及重送。預覽與匯入走正式入口；每題種獨立值並證明受測操作執行。修法生效型移除接線、保存型保留操作破壞保存機制，都須得到對應 assertion 失敗。

正常完整三關、當版雲端檢查、風險分級、正式 Grok 複審與合併依共同流程；接續各輪的實際證據在 PR 對帳。驗收代選採推薦做法、使用隔離資料代驗，不要求刪改真實帳務。

原 `storeRulesHash` 交錯缺陷仍未修；既有可重現證據限 HOSTED／假 Postgres。本次 LOCAL 同檔修改不恢復雲端停線，不改 CAS 或跨寫入排序。手機、Gemini 及複審後掃維持既有停止線。
