# 安全與健壯性 — 待辦地圖（邁向多人服務）

> 這是一次自我體檢的結果，對照「終點＝多人註冊使用的服務」。
> ⚠️ **先讀這段，它決定下面每一項怎麼解讀**：這份地圖寫成時**只有一種模式**（你的 Mac，
> 綁 `127.0.0.1`、單人）。現在有**兩種**：
>
> | | **LOCAL**（預設＝William 的 Mac） | **HOSTED**（`NOTEASY_HOSTED=1`，Render 上的 noteasy.com.tw） |
> |---|---|---|
> | 誰連得到 | 只有本機 | 網際網路（受邀者登入） |
> | 帳號與隔離 | 沒有（也不需要） | ✅ Supabase Auth＋Postgres RLS＋租戶隔離（C2／C4b 已上線） |
> | 傳輸加密 | 沒有傳輸可攔 | ✅ Render 強制 HTTPS |
> | 速率限制 | 不掛 | ✅ `lib/rate-limit.js`（登入按 IP、上傳解析按帳號） |
>
> **所以「未完成」要問「哪一種模式的未完成」**——下面 🔴 那節已按這個重寫。
>
> 沿革：初版寫於階段 A（當時 34 題）→ **2026-07-24 系統優化階段三逐項查證後全面更新**（B 階段實質完工、多項升格或拆半）。
> **2026-08-02 再校正**：兩項標「未開工」的（異常輸入防線／每日滾動備份）**其實都已上線、考題都在**，移出待辦。
> **2026-08-02 二次校正（Codex #381 r2 抓到）**：整份還停在「只有 LOCAL」的世界——
> 🔴 那節把已經上線的帳號隔離／HTTPS／速率限制都寫成未來式。（凍結的待辦清單是安全判斷的輸入，失真代價最高。）

## 🟢 已完成

- **自動守門**：考試**全綠**（`npm test`）＋型別校對＋格式糾察；pre-push 與 CI 兩道自動關卡。
  （⚠️ 這裡**刻意不寫題數**。這句話自己就是活教材：初版寫「791 題」，改寫時抄了「1,354 題」，
  到後來又變了——**連「示範過期」的替代數字也會過期**，所以規則收成兩類：
  **帶日期的歷史快照**可以留數字（那是「當時」的事實、不會過期）；**現況一律不留數字、只指向指令**。
  要看現值就跑 `npm test` 或看 PR 的 CI。）
- **壞檔不覆蓋資料（⚠️ LOCAL）**：已從舊文字檔版升級為 SQLite 健檢版——開機 `PRAGMA quick_check` 不過就明確報錯＋指引 `.bak` 還原，絕不默默回空庫（`lib/store.js`）。
  **HOSTED 沒有這一段**（那是 SQLite 的指令）：雲端的資料完整性由 Supabase Postgres 負責。
- **B1 併發寫入 → SQLite ✅**：資料已搬進 SQLite（WAL＋交易，寫到一半斷電也不壞檔），所有讀寫走單一櫃檯 `lib/repo.js`。⚠️ **「換引擎只改 `store.js`」這句已經過時**（C4b 之後）：`repo.js` 現在**按模式分流**——LOCAL→`lib/store.js`（SQLite）／HOSTED→`lib/store-pg.js`（Supabase Postgres＋RLS＋樂觀鎖）。單一櫃檯的好處還在（路由與業務邏輯一行都不必知道差別），但**要改的是兩顆引擎**，其他程式不動。
- **B2 欄位白名單 ✅**：後端對每種資料都有「只收這些欄位」清單（`lib/schema.js WRITABLE_FIELDS`＋`pickWritable`；settings 另有子白名單）。前端多塞的欄位一律擋掉；服務層擁有的欄位（G5）連前端都寫不進。
- **B4 錯誤處理 ✅**：所有 API 出錯走同一套規矩——全域錯誤中介（使用者看得懂的訊息、伺服器留紀錄、不洩堆疊路徑）＋共用包裝 `lib/routes/route-helpers.js`。
- **機密不進瀏覽器（C2 的前半）✅**：機密投影 `lib/secret-fields.js`——帳單 PDF 密碼、IB Flex Token、完整帳號、台新證券密碼、來源參照**一律不送到瀏覽器**（備份匯出**分模式**：**LOCAL 保留完整、可原樣還原**；**HOSTED 剝除機密與完整帳號**（`stripSecretsForBackup`，`lib/routes/core.js:97`）——還原後要重輸 IB token 與 PDF 密碼各一次，這是刻意的）。舊敘述「GET /api/db 回整包含 token」已不成立。

## 🟢 拆成兩半的項目（**前半與後半皆已完成**——原標「後半排程中」，2026-08-02 校正）

### B3. 輸入驗證 → 前半 ✅／後半＝「異常輸入防線」（系統優化階段四 B）
- **已完成**：型別／真實日曆日期（`isRealDate`，2026-02-31 這種進不來）／必填欄位／跨欄位規則的驗證，三個強制點（CRUD 400、匯入整份 400、寫入櫃檯 throw）；單次請求大小分流（`lib/http-body.js`）：一般 **1MB**／帳單**檔案上傳** **15MB**（兩種模式都是）／備份還原 **50MB**；⚠️ **解析出來的「列」那個端點（`/api/cards/:id/statement/import`）分模式——LOCAL 15MB、HOSTED 1MB**。判準寫在該檔檔頭且值得記住：**這道牆保護的是誰的資源？**保護 Supabase 的容量／帳單→只套 HOSTED；保護解析器的記憶體→兩種模式都套（畸形檔案在本機一樣會遇到）。
- **✅ 已完成**（2026-08-02 校正：原標「未開工」，實際 #297 已上線）：單一欄位的**文字長度上限**＝「異常輸入防線」——短欄位合理上限（`LEN_SHORT = 200`）、長內容極寬鬆（`LEN_LONG = 20000`）、不靜默截斷、超過明確拒絕（`lengthErrorOf`，`lib/schema.js`）。考題 `test/input-guard.test.js`。

### B7. 備份自動化 → 前半 ✅／後半＝每日滾動備份（系統優化階段四 A）
- **已完成（⚠️ LOCAL）**：每次開機自動 `VACUUM INTO` 產完整快照 `.bak`（原子替換）。舊敘述「目前靠手動匯出」已不成立。
  ⚠️ **這裡曾另有一句「不可逆整批操作前自動再存一顆」——那一層（店名規則儲存／開 app 自動整理，也就是使用者按下去的整批操作）已於 2026-08-08 由 William 裁決整層移除**（不做、不擋、不問；畫面只寫「儲存後沒有「復原」可以按」）。裁決與沿革見 `docs/contracts/data-storage.md` 的「不可逆整批操作刻意沒有操作前備份」節——**那是拿掉的，不是漏掉的，不要當成待辦補回來。**（開庫時的一次性 schema 搬家仍各自備一顆，見該節的誠實劃界。）
- **✅ 已完成**（2026-08-02 校正：原標「未開工」，實際 #295 已上線）：「每天一顆、保留 30 天」的滾動備份（`KEEP_DAYS = 30`）——**失敗會在畫面明顯警告、連續失敗加強、不只記 log**（考題 `test/backup-alert.test.js`）；範圍到誤刪／錯誤匯入／程式寫壞。考題 `test/daily-backup.test.js`。
- **iCloud／異地自動備份維持暫緩**：⚠️ **限 LOCAL**——`data/store.db` 裡的 IB token 與 PDF 密碼仍為**明文**（見 C2 後半），須等加密備份格式＋明確使用者同意。
  **HOSTED 不是這樣**：機密欄位在 C5 已加密落庫（`NOTEASY_MASTER_KEY` envelope encryption），別把這句話讀成「雲端也是明文」。
- ⚠️ **上面整節（開機快照／每天一顆／保留 30 天）只適用 LOCAL**：
  `dailyBackupIfDue()` 在 HOSTED **刻意什麼都不做**（Render 的檔案系統是暫時性的，
  備份寫完就隨下次部署消失＝假的安全帶）。**HOSTED 的備份在資料庫層**——
  Supabase Pro 的 `Daily backups` ＋7 天保留（見多人上線-施工計畫 裁決①②）。

## 🟢 多人化項目：HOSTED 已上線（2026-08-02 校正，原本整節掛在 🔴）

> 這幾項在寫這份地圖時確實是未來式。**階段 C 的 C2／C4a／C4b／C5 上線之後就不是了**，
> 但這節沒跟著改，於是「安全待辦清單」一直在說已經做好的防線還沒做。

### C1. 帳號與資料隔離 → ✅ HOSTED 已上線
- Supabase Auth（邀請制、關閉公開註冊）＋**Postgres RLS 第二道**＋租戶交棒點 `lib/tenant.js`
  （`AsyncLocalStorage`，不是模組級變數——那會把 A 的資料送給 B）。
- 跨租戶對抗考題逐集合列舉（C4b）：**實際回 404／空清單而不是 403**——隔離在資料層，
  B 的列對 A 而言根本不存在（比 403 強：403 等於承認那筆資料存在）。
- **LOCAL 仍然刻意沒有帳號**（只有本機連得到，不是遺漏）。

### C3. 傳輸加密（HTTPS）→ ✅ HOSTED 已上線
- Render 強制 HTTPS；cookie `HttpOnly + Secure + SameSite=Lax`。LOCAL 綁 `127.0.0.1`，沒有傳輸可攔。

### B5. 速率限制 → ✅ HOSTED 已上線
- `lib/rate-limit.js`（記憶體版）：登入按 IP、上傳解析按帳號。**LOCAL 刻意不掛**（自己限自己沒有意義）。

## 🔴 仍未完成

### B6. 稽核日誌
- 「誰改的」在 HOSTED 才有意義，目前沒有。最接近的是匯入批次戳記（追資料來源，非追人）。

### LOCAL 的 PDF 解析沒有任何「跑不完」的上限（2026-08-29 記，**刻意先不做**）

- 三個 PDF 抽取器的 `finally { await task.destroy(); }` 是**無上限地等**。pdfjs 若因為未知原因
  停在那裡，**HOSTED 有子行程逾時兜著（30 秒 SIGKILL），LOCAL 沒有**——那次請求永遠不結束，
  已配置的資源到重啟前放不掉。
- **已知的觸發條件已於本次修掉**（取消串流沒帶 `Error` 理由，`lib/parse-limits.js` 的 `cancelStream`）；
  這條待辦針對的是**未知**的下一個。
- **William 2026-09-01 裁示：先不補**。理由：①「LOCAL 明知帶著這個洞」是 2026-07-29 就拍過板的取捨
  ②替未知加保險最容易長出下一個說謊的護欄（本次修的正是「保證做不到」那一族）。
  要做的話三個選項：給 destroy 一個上限／把行程隔離也套到 LOCAL（每次多付 250ms、推翻舊裁決）／維持現狀。

### 金鑰輪替（C5 的缺口）
- 換 `NOTEASY_MASTER_KEY` 沒有雙鑰過渡。**刻意不做**（使用者少，重輸兩個欄位比較划算）；
  貼錯還有救（`store-pg.js` 會把解不開的欄位寫回原密文，不會毀掉）。
