# 安全與健壯性 — 待辦地圖（邁向多人服務）

> 這是一次自我體檢的結果，對照「終點＝多人註冊使用的服務」。
> ⚠️ **先讀這段，它決定下面每一項怎麼解讀**：這份地圖寫成時**只有一種模式**（你的 Mac，
> 綁 `127.0.0.1`、單人）。現在有**兩種**：
>
> | | **LOCAL**（預設＝William 的 Mac） | **HOSTED**（`NOTEASY_HOSTED=1`，Render 上的 noteasy.com.tw） |
> |---|---|---|
> | 誰連得到 | 只有本機 | 網際網路（受邀者登入） |
> | 帳號與隔離 | 沒有（也不需要） | ✅ Supabase Auth＋Postgres RLS＋租戶隔離（C2／C4b 已上線） |
> | 傳輸加密 | 沒有傳輸可攔 | ✅ Render 強制 HTTPS |
> | 速率限制 | 不掛 | ✅ `lib/rate-limit.js`（登入按 IP、上傳解析按帳號） |
>
> **所以「未完成」要問「哪一種模式的未完成」**——下面 🔴 那節已按這個重寫。

## 🟢 已完成

- **自動守門**：考試**全綠**（`npm test`）＋型別校對＋格式糾察；pre-push 與 CI 兩道自動關卡。
  （⚠️ 這裡**刻意不寫題數**——原本寫「791 題」，實際早就是 1,354 題。
  會自己過期的數字不該手抄進文件，要看現值就跑 `npm test` 或看 PR 的 CI。）
- **壞檔不覆蓋資料**：已從舊文字檔版升級為 SQLite 健檢版——開機 `PRAGMA quick_check` 不過就明確報錯＋指引 `.bak` 還原，絕不默默回空庫（`lib/store.js`）。
- **B1 併發寫入 → SQLite ✅**：資料已搬進 SQLite（WAL＋交易，寫到一半斷電也不壞檔），所有讀寫走單一櫃檯 `lib/repo.js`——換引擎只改 `store.js`，其他程式不動。
- **B2 欄位白名單 ✅**：後端對每種資料都有「只收這些欄位」清單（`lib/schema.js WRITABLE_FIELDS`＋`pickWritable`；settings 另有子白名單）。前端多塞的欄位一律擋掉；服務層擁有的欄位（G5）連前端都寫不進。
- **B4 錯誤處理 ✅**：所有 API 出錯走同一套規矩——全域錯誤中介（使用者看得懂的訊息、伺服器留紀錄、不洩堆疊路徑）＋共用包裝 `lib/routes/route-helpers.js`。
- **機密不進瀏覽器（C2 的前半）✅**：機密投影 `lib/secret-fields.js`——帳單 PDF 密碼、IB Flex Token、完整帳號、台新證券密碼、來源參照**一律不送到瀏覽器**（備份匯出刻意保留完整、可還原）。舊敘述「GET /api/db 回整包含 token」已不成立。

## 🟢 多人化項目：HOSTED 已上線（2026-08-02 校正，原本整節掛在 🔴）

> 這幾項在寫這份地圖時確實是未來式。**階段 C 的 C2／C4a／C4b／C5 上線之後就不是了**，
> 但這節沒跟著改，於是「安全待辦清單」一直在說已經做好的防線還沒做。

### C1. 帳號與資料隔離 → ✅ HOSTED 已上線
- Supabase Auth（邀請制、關閉公開註冊）＋**Postgres RLS 第二道**＋租戶交棒點 `lib/tenant.js`
  （`AsyncLocalStorage`，不是模組級變數——那會把 A 的資料送給 B）。
- 跨租戶對抗考題逐集合列舉（C4b）：**實際回 404／空清單而不是 403**——隔離在資料層，
  B 的列對 A 而言根本不存在（比 403 強：403 等於承認那筆資料存在）。
- **LOCAL 仍然刻意沒有帳號**（只有本機連得到，不是遺漏）。

### C3. 傳輸加密（HTTPS）→ ✅ HOSTED 已上線
- Render 強制 HTTPS；cookie `HttpOnly + Secure + SameSite=Lax`。LOCAL 綁 `127.0.0.1`，沒有傳輸可攔。

### B5. 速率限制 → ✅ HOSTED 已上線
- `lib/rate-limit.js`（記憶體版）：登入按 IP、上傳解析按帳號。**LOCAL 刻意不掛**（自己限自己沒有意義）。

## 🔴 仍未完成

### C2 後半. 靜態加密（硬碟／資料庫裡的資料加密存放）
- 機密欄位**已不出門**（投影）且在 HOSTED **已加密落庫**（C5，`NOTEASY_MASTER_KEY` envelope encryption）。
  但 LOCAL 的 `store.db` 檔案內仍是明文，HOSTED 的一般財務資料（交易、持股、餘額）在資料庫裡也仍是可讀 JSONB
  （靠 RLS 與存取控制保護，見施工計畫「加密的是欄位不是整個資料庫」）。
- LOCAL 風險＝實體接觸電腦。與「加密備份格式」同一個設計案。

### B6. 稽核日誌
