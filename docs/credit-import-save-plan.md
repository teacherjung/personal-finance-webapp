# 信用卡匯入預覽的保存保護

## 目標與範圍

承接既有待辦 GS-F05。Codex 實作、Grok 正式複審；依本人本工作線續作授權，技術問題交實際 GPT-6.1 Sol／xhigh。所有掃描暫停，不恢復 Gemini 接線。本計畫不宣稱尚未完成的驗證已通過。

- 保護同一信用卡帳單預覽的在途匯入：連按、排序重繪與改卡不能再送一份競爭請求。
- 取消、關窗、換窗或換頁後，舊成功／失敗不得重開完成窗、改月份、關閉新窗或回報過期錯誤。
- 改卡重解析須與匯入互斥，僅有效預覽接收成功資料或顯示失敗；失敗保留原卡與原預覽。
- 正常匯入的勾選、分類、期別、金額、票、完成摘要與刷新保留。刷新失敗不得冒充匯入失敗。
- 不改 HTML 外觀、CSS、手機版、後端帳務、解析／去重判準、真實資料或雲端部署；只補本次完成窗進入改卡後的必要接續，其他批次管理入口保持。

## 設計與邊界

在途狀態屬於整個預覽實例，不屬於會被排序替換的按鈕。各次 draw 採共用外殼 close 與彈窗身分；非同步接續核對擁有權、換頁世代及完整 hash。正常成功交棒給完成窗後，以唯讀觀察戳保護頁面刷新，不搶新窗的擁有權。完成／×／Esc 關閉本次有效完成窗時，在原 close 確認關空後同步延續觀察，保留列表更新；換頁或新窗接管後失效的資格不得復活，原完成窗仍可手動關閉。整批改卡的接管不延續舊匯入刷新。

信用卡頁 renderer 增加可選 canCommit，與原 route／render 世代並用，在啟動 GET／推進重繪世代之前及成功更新頁面、失敗回復篩選／顯示錯誤前核對；一般呼叫不改行為。技術邊界以本支公開 Sol 裁示及實作證據收口。

完成窗進入改卡的載卡請求防重並核原窗／同頁資格；取消自己的有效改卡窗後另起新的受保護 GET，不延續原匯入 GET。取消、×、Esc 與合法背景手勢同路，拖出窗外不算背景取消。成功保存以表單 handoff 核排程與執行資格；過期成功／失敗不得通知或干擾目前表單。已送出改卡不因取消撤回，取消後 GET 不保證涵蓋較晚完成的改卡。其他入口未傳此脈絡時保持既有行為，不新增一般改卡全域一致性機制。

## 驗證計畫

- 先以原程式重現連按與過期回應，再驗新程式；斷言實際 POST 次數及 payload，不將既有後端去重誤報成已證實重複入帳。
- 匯入與改卡：正常成功／失敗、取消／×／Esc、開新窗（含開後關空）、切頁／返回、同頁刷新、排序與保存勾選分類、失敗後重試、新預覽獨立。
- 延後頁面 GET 的成功與失敗，核對新頁、新窗、月份與錯誤提示不被舊刷新干擾。
- 有效突變先 assert 目標存在；拿掉互斥／接續資格／刷新資格後，對應行為題必須紅。保存型保留操作，只破壞保存機制。
- 全套型別、lint、測試與必要真 HTTP 合成資料；原生桌機瀏覽器走合成帳單與獨立 STORE_FILE，依實際 ROUTES 全頁 reload。不得讀真帳本／憑證或發真 AI 解析。
- 送審前核對 stale-text、實際改檔 D5、風險分級；官方 Grok 備審與正式複審，公開原文及逐項查證。所有必過關卡完成才合併，合併後依驗收級別查證。

## 誠實邊界

關窗／換頁不撤銷已送到後端的保存；傳輸失敗不能推定後端沒寫入。此保護不承諾自動保存送出後追加的編輯，也不把單一預覽防重送當成跨預覽或跨分頁冪等性。正式複審所需的施工樹依賴已首次獨立安裝並通過型別檢查；這不等於官方備審或 Grok 複審已通過。主網頁目錄與其依賴未施工。

## 階段證據

草稿 [PR #739](https://github.com/teacherjung/personal-finance-webapp/pull/739) 已先於產品實作建立；範圍、獨立依賴與入口長度修正的 Sol 原文裁示已公開於該 PR。原程式先跑合成 HTTP 回歸矩陣，正常重讀失敗題通過，其餘在途互斥／過期回應題重現失敗；修正後擴大矩陣、型別及 lint 通過。

突變在 Node 載入正式來源時先 assert 替換目標，再個別移除匯入／排序／改卡互斥、原窗資格、hash、匯入及改卡成功／失敗接續、列表入口／成功／失敗資格；基準先綠、每個變體均由行為斷言拒收，磁碟產品原檔逐位元組保持。工具逾時或啟動失敗不當有效突變；初次工具等待編排失誤的一輪不採計，修正後重跑。

獨立合成帳本的桌機 Chrome 驗證依 app 的 ROUTES 逐頁重載，並走正常匯入及延遲匯入／改卡／列表回應保留新窗；無頁面錯誤或外部請求。截圖人工核對完成窗及新窗輸入，沒有宣稱本人驗收或手機驗收。首次工具定位撞到側欄同名屬性，修正定位後重新驗證；新預覽重送同帳單由既有去重略過，錯期待完成窗的新題依 Sol 裁示改驗零新增與原資料保留，不改產品去重。

Grok 第一輪指出：完成窗在列表讀取期間被使用者關閉，會誤撤銷刷新資格。Codex 用 LOCAL HTTP 重現關窗成功／失敗斷言，再依 Sol 裁示在本支調整完成窗的資格閉包；新增完成／×／Esc、關後新窗及導航、跨頁仍能關窗的回歸，並以移除續接、讓舊關閉事件復活的突變驗證。原生 Chrome 亦檢查關閉完成窗後的月份與匯入明細。Grok 盒內 TCP 被隔離限制，未跑通的 HTTP 考題不冒稱通過；其行程內探針與 Codex 外層 HTTP／原生證據分開記錄。

Grok 第二輪確認前項修正，另指出完成窗進入改卡後取消會留下舊列表。Codex 獨立重現取消／×／Esc／合法背景關閉，依 Sol 裁示只補此入口的取消新讀取、載卡與正常改卡接續；批次管理入口保持。補測另發現立即改 hash 尚未推進 nav 時，共用表單可能繼續自動關窗，限定 scope 的過期入口及終態遂撤銷自身擁有權而不清 DOM。驗證工具曾扣住不相關讀取、誤驗不存在的交易 cardId，均依 Sol 裁示修正為精準屏障及正式 account／stmtRef 完整交易差異斷言；失敗基準不當有效突變。

完整關卡與 Grok 當版續審仍須完成，不以此階段紀錄代替合併資格；逐版結果以 PR 公開對帳為準。
