# 銀行收支單筆刪除後的讀取恢復

## 範圍與尚待定案

接續原工程第4／6項未涵蓋的銀行收支單筆刪除；基底為 `c4a080609a7a82df4365d41526d7916d40f8cb89`。#700處理的匯入／同頁重畫及#703的重試回焦各自保持，不把它們的本人定案延伸為刪除情境的批准。

目前為開工預約計畫，技術接法交實際GPT‑6.1 Sol／xhigh裁示，提示與操作依RULES E10另請本人看具體候選後定案，完成這兩步才定稿施工及送審。

## 問題與候選結果

讀碼可見，單筆刪除交共用確認函式執行DELETE及router重畫，未將刪除確認登記到銀行模組的修訂。需要以隔離合成資料重現：真正移除本題資料後，後續列表GET失敗仍顯示舊列，卻沒有持續的刪除待更新事實。重現尚未完成，不預填測量結果。

候選結果：收到正式刪除成功回應後，後續讀取失敗與刪除失敗分開。有本次成功列表就保留原列表、摘要與篩選，標題下、列表上方說明「資料已刪除，畫面尚未更新」；無可用列表則誠實說明「資料已刪除，暫時無法載入列表」。按「重新讀取」只讀既有端點，不再DELETE。成功且讀取開始時已涵蓋確認修訂，才清除待更新提示。

尚未收到成功確認不猜已刪除、不補發或回滾DELETE；取消既有原生確認不得發出請求。單筆資料刪除不是券商交易工具操作，不新增金融能力，也不讀寫真實帳本。

## 技術與分工界線

優先在銀行模組內處理確認、修訂、讀取與原工作區所有權，不改共用確認函式、router接口、樣式、後端或資料格式。原生刪除確認文字與金額格式保持。較新讀取、換頁、新表單與較晚刪除回覆的交錯需交Sol具體核定；資料確認與呈現資格分開，不以新頁／新窗同名控制項取得舊作業資格。

本支不含銀行匯入批次刪除、其他頁刪除、外部視窗／外部寫入一致性、刪除後的新焦點目的地或全UI7。若模組內範圍不足，附反例再裁，不順手擴大共用介面。

## 驗證與程序

探針與突變在施工樹外。先以正式模組、實際刪除入口及本題專屬資料證明未修版缺口；確認DELETE確實移除資料及次數，再查讀取失敗後的持續提示、舊列表、條件、唯讀恢復與成功清除。失敗、取消、延後確認、新舊讀取與換頁／表單交錯各自獨立，不靠上一題殘留。

正常基線通過後，逐處移除修法／破壞保存機制，保留受測DELETE或GET並證明考題紅；不以語法錯誤充數。原重讀、匯入與回焦考題不刪弱。合成瀏覽器實走本支情境與全部正式路由重載，資料使用專屬外置STORE_FILE，外部來源明確停用。
