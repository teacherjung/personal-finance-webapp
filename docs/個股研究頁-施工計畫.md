## 〇、先講結論

### 產品定位

投資組合頁回答「我的整體配置與風險如何」；個股研究頁回答「我為什麼持有這家公司、原先論點還成立嗎、下一次要檢查什麼」。

點擊投資組合裡的個股代號（例如 `AAPL`）後，在**新的瀏覽器分頁**開啟 App 內部頁面：

```text
http://localhost:4321/#stock?symbol=AAPL
```

這不是外部網站，也不另開第二套伺服器。原本的投資組合留在第一個分頁，研究頁在第二個分頁，方便來回對照。

### 技術方向

1. 沿用現有 `research` 資料，不另造第二套研究筆記。
2. 沿用 `portfolio-symbol.js` 的代號身分規則，不自行處理大小寫或空白。
3. 持股、成本、交易與研究筆記以本機資料庫為準。
4. v1 先做「人工判斷＋系統整理證據」，**不讓程式自動下買進／賣出結論**。
5. 外部基本面資料分階段加入；來源失敗時仍可閱讀與編輯自己的研究。
6. 先新增獨立檔案，最後才用短 PR 接上共同路由與持股表。

## 一、現況盤點：已經有什麼

這個功能不是從零開始。現有 App 已有以下積木：

| 現成能力 | 位置 | 新頁怎麼沿用 |
|---|---|---|
| 個股研究資料 | `research` 集合 | 沿用同一筆研究，不另建重複筆記 |
| 投資論點／關鍵指標／風險 | `research.thesis / metrics / risks` | 直接搬進研究頁的核心區 |
| 檢查點 | `research.checkpoints` | 做成依日期排列的研究紀錄 |
| 研究顯示與表單 | `portfolio-research.js`、`portfolio-research-actions.js` | 抽出可共用的查找與表單規格，不複製 API 寫入流程 |
| 持股資料 | `holdings` | 股數、成本、現價、幣別與部位來源 |
| 個股層判準 | `holding.layer === 'stock'` | v1 只讓真正的個股進研究頁 |
| 代號身分 | `portfolio-symbol.js` | `aapl`、` AAPL `、`AAPL` 都視為同一家公司 |
| 成交紀錄 | `securityTrades` | 顯示該代號的買賣時間線，不重新計算來源金額 |
| 報價 | 現有 Yahoo chart 報價服務 | 顯示現價與更新時間，不拿來冒充官方財報 |
| 投資上限 | `portfolio-risk.js`＋設定 | 顯示個股占淨資產與 5% 軟上限，不另抄公式 |

依 2026-07-24 裁決審查紀錄，首版實際持有的個股層共有 4 檔；其中 AAPL／GOOGL 已有研究，TSLA／SPCX 尚無研究。畫面驗收不能只測有資料的頁面，也要實測後兩者的「請先寫論點」空狀態。既有檢查點日期同時存在 `YYYY-MM` 與新寫入的 `YYYY-MM-DD`，資料驗證必須向後相容。

### 不該重做的東西

- 不另建 `stockNotes` 或第二份 `research`。
- 不另寫一套 Yahoo 報價抓取。
- 不另寫代號正規化。
- 不在研究頁重算投資組合淨值、成本或 XIRR。
- 不讓研究頁直接修改 IBKR 持股或現金。

## 二、三種協作防撞方案

### 方案 A：完全排隊

Claude 的所有工作暫停或收官後，Codex 才從頭做到尾。

**優點**

- 衝突機率最低。
- 不需要兩邊頻繁更新基底。

**缺點**

- Codex 空檔無法利用。
- 小功能也必須等整條 Claude 主線結束。
- 審核與建造不能平行。

**適合情況**

- Claude 正在大改 `app.js`、`schema.js`、投資組合或全站 CSS。

### 方案 B：隔離建造＋短整合窗（推薦）

Codex 先在新檔案完成資料模型、評分器、畫面組裝與考題；接共同檔前先等 Claude 當下 PR 合併，再更新到最新 `main`，用短 PR 接線。

**優點**

- 大部分工作可與 Claude 平行。
- 共用檔修改量小，衝突好預測。
- 新功能每個零件有獨立契約與考題。
- Codex 接到審核任務時可以暫停建造，不影響 Claude。

**缺點**

- PR 數量較多。
- 最後仍有少數共同檔，必須安排「整合窗」。
- 每次共同檔 PR 前要確認 Claude 沒有同時修改。

**適合情況**

- 本功能有大量獨立新模組，只有路由、資料欄位與入口需要接現有系統。這正是本案的情況。

### 方案 C：另做一個獨立 HTML 小工具

建立另一張 HTML、另一套資料載入與樣式，完全不接現有 SPA 路由。

**優點**

- 初期幾乎不會撞 `app.js`。
- 可以很快做出原型。

**缺點**

- 會形成第二套路由、樣式、API 與互動規則。
- 容易和現有研究卡資料不同步。
- 長期維護成本最高，違反「單一真相」。
- 之後還是要重新整合回 App。

**結論**

不推薦。它只是把今天的 Git 衝突換成未來的架構衝突。

### William 裁決 A

**採方案 B：隔離建造＋短整合窗。**方案 A、C 保留在上方作為決策背景，不再重議。

## 四、使用者流程

### 入口

1. 使用者在「投資組合」的持股表看到個股，例如 `AAPL`。
2. 個股代號顯示為可點擊文字；ETF、債券、黃金不變成入口。
3. 點擊後以新分頁打開 `#stock?symbol=AAPL`。
4. 新頁從本機資料組合：持股、研究筆記、交易紀錄、報價與投資上限。

v1 的**新入口**只從持股表的個股層代號進入，不提供任意代號搜尋或願望清單入口；若個股之後賣光，但既有研究網址或研究資料仍存在，頁面仍可開啟並標示「目前未持有」，避免研究紀錄隨持股消失。

### 頁面內操作

1. 先看到持有狀況與資料更新時間。
2. 閱讀「為什麼持有」與「什麼情況代表我看錯」。
3. 檢視五項評分及其理由。
4. 對照關鍵指標、估值情境、風險與催化劑。
5. 新增一筆有日期的檢查點。
6. 每次財報後更新評分與論點狀態。

### 不在 v1 做

- 自動推薦買進、賣出或目標張數。
- 直接替使用者下單。
- 研究頁修改持股、現金、成本或交易來源。
- AI 自動產生「看多／看空」結論。
- 社群評分、新聞情緒與網路文章大量爬取。
- 把不同公司硬套成完全相同的產業指標。

## 五、畫面藍圖

### 頁首

```text
AAPL  Apple Inc.                         資料更新：2026-07-24
個股研究與追蹤                         [更新資料] [編輯研究]
目前狀態：持有論點成立
```

- 代號與公司名稱是第一視覺訊號。
- 顯示資料來源與更新時間，避免把舊資料當現在。
- 提供「回投資組合」連結，但不取代瀏覽器上一頁。

### 第一層：現在持有多少

一列精簡數字，不做過大的英雄區：

| 項目 | 口徑 |
|---|---|
| 股數 | 同代號持股合併 |
| 成本 | 沿用投資組合模型 |
| 市值 | 沿用現價與匯率 |
| 未實現損益 | 沿用投資組合模型 |
| 占淨資產 | 沿用淨資產口徑 |
| 個股上限 | 沿用設定值，超過只提醒「凍結加碼」 |

### 第二層：研究結論

左右兩欄、不是卡片套卡片：

**投資論點**

- 我為什麼買？
- 我想驗證什麼？
- 目前看到哪些支持證據？

**反證條件**

- 發生什麼事代表論點破壞？
- 哪些風險只是價格波動，哪些是企業本質惡化？
- 下一次何時重新檢查？

### 第三層：五項評分

用水平長條或五列評分，不用雷達圖。雷達圖面積容易讓差異看起來比實際大，也較難精準比較。

| 構面 | 權重 | 要回答的問題 |
|---|---:|---|
| 商業品質 | 25% | 公司怎麼賺錢？護城河是否持續？ |
| 財務品質 | 25% | 成長、利潤、現金流與資產負債是否健康？ |
| 估值安全邊際 | 20% | 現價相對保守／基準／樂觀情境是否合理？ |
| 論點證據 | 20% | 最近資料支持還是否定原始論點？ |
| 風險控制 | 10% | 已辨認主要風險、部位是否符合上限？ |

總分只是整理工具，不是買賣訊號。頁面必須就地說明：

> 「高分不代表現在適合買；低分也不等於必須賣。分數的用途是讓你每次用同一把尺重新檢查。」

五項評分都填妥且各有理由時才顯示總分；未完成時只顯示「已評 X／5 項」，不顯示任何總分數字，也不重新正規化剩餘項目的權重。評分長條使用 `ACCENT` 亮版單色；未完成項用灰色空條。不得用 `--pos`／`--neg` 做「高分綠、低分紅」填色。

### 第四層：關鍵指標

- 顯示使用者自己選的 3–8 個指標。
- 每列包含：指標名稱、最新值、前期值、趨勢、資料期間、來源。
- 不同公司可以有不同指標，例如：
  - AAPL：服務營收成長、毛利率、iPhone 趨勢、回購。
  - GOOGL：搜尋廣告、Cloud 成長、營業利益率、資本支出。
- 缺資料顯示「尚未取得」，不可顯示 0。

### 第五層：估值情境

使用三情境表，不給單一神奇目標價：

| 情境 | 合理價值 | 主要假設 |
|---|---:|---|
| 保守 | 使用者填寫 | 成長放慢、估值收縮 |
| 基準 | 使用者填寫 | 目前論點大致成立 |
| 樂觀 | 使用者填寫 | 成長與利潤優於預期 |

- 顯示幣別與估值日期。
- 自動計算現價相對各情境的距離，但不顯示「應買／應賣」。
- v1 估值數字與假設由使用者填寫，避免未經校準的自動模型給出假精準答案。

### 第六層：風險、催化劑、反證條件與檢查點

四個未巢狀的區塊：

- **風險**：v1 沿用既有 `risks` 文字，先把主要風險說清楚，不假裝已有逐項狀態。
- **催化劑**：可能讓論點被驗證的事件，狀態為觀察中／已發生／已過期；不代表必然上漲。
- **反證條件**：狀態為觀察中／已觸發／已解除，和催化劑使用不同枚舉。
- **檢查點**：日期、筆記、當時評分與是否改變論點。

### 第七層：我的交易紀錄

- 只讀顯示 `securityTrades` 中同代號資料。
- 保留來源原幣，不把 USD／TWD 混加。
- 欄位：成交日、買賣、數量、價格、費稅、淨應收付、來源。
- 這是查帳資料，不反推研究結論，也不改寫交易。

### 手機與桌面

- 桌面：內容主欄最大寬度約 1180–1240px，雙欄只用於可並讀的區塊。
- 手機：全部改單欄；分數、金額、長字不可溢出。
- 不使用巨大標題、不使用卡片套卡片、不讓圖表取代可讀的文字與表格。

## 六、評分方式

### 原則

1. 每項 0–5 分，只能選整數。
2. 每個分數必須附一句理由；沒有理由就視為「尚未評分」。
3. **五項全部完成才計算並顯示總分**；未完成時只顯示「已評 X／5 項」，不可顯示部分總分、把空白當 0，或將剩餘權重重新正規化。
4. 任何自動帶入的證據都要標來源與期間。
5. 評分歷史只在「五項完整且分數實際變動」時新增；同一天多次變動只保留當天最後一筆，避免無界累積無意義的重複紀錄。

### 建議量尺

| 分數 | 白話意思 |
|---:|---|
| 0 | 已有明確反證，原論點不成立 |
| 1 | 明顯偏弱，重要問題尚未改善 |
| 2 | 偏弱，仍有關鍵疑慮 |
| 3 | 普通／符合原先預期 |
| 4 | 穩健，證據多數支持 |
| 5 | 非常強，但仍不代表價格合理 |

### 加權

```text
總分
=（商業品質 ÷ 5）× 25
+（財務品質 ÷ 5）× 25
+（估值安全邊際 ÷ 5）× 20
+（論點證據 ÷ 5）× 20
+（風險控制 ÷ 5）× 10
```

五項完整時，畫面將結果顯示為 0–100 分；資料庫保留每項 0–5 原始分數與理由。五項未完整時不執行這個公式。

### 研究狀態

採用 enum：

```text
unreviewed      尚未評估
watching        觀察中
valid           持有論點成立
needs-review    待重新檢查
broken          論點已破壞
```

狀態由使用者選，程式不可僅因股價下跌或分數下降就自動改成 `broken`。

### William 裁決 B

**採五構面、0–5 分、五項完整後加權成 100 分。**

### 就地白話解釋

以下概念若不說明，容易被當成程式算錯，P3 必須使用現成 `.info-link`＋`openInfo` 就地解釋：

1. 總分是「固定尺重新檢查」，不是買進或賣出訊號。
2. 0 分代表已有明確反證，是合法評分；空白才是尚未評分。
3. 指標缺值顯示「尚未取得」，不代表數值為 0。
4. 個股上限設為 0 代表零容忍，不是設定損壞。

### 3. 驗證要求

`lib/schema.js` 現有通用 `validateField` 沒有可直接滿足本案的深層 `object` 契約，泛用 `array` 也只會排除非物件元素。因此 P2 必須比照既有分類設定前例，為 `research` 手寫專用 sanitizer，並接進 CRUD、`sanitizeDbForWrite` 與 `validateImportItem` 三條路；不可只在 `FIELD_SCHEMA` 標成泛用 `array`／`object` 就放行。

具體要求：

- 研究主狀態嚴格使用 `unreviewed / watching / valid / needs-review / broken`。
- 催化劑狀態獨立使用 `watching / happened / expired`；反證條件狀態獨立使用 `watching / triggered / cleared`，不可沿用研究主狀態。
- 新增的完整日期走真日曆驗證。既有 `checkpoints[].date` 已有合法 `YYYY-MM` 舊資料，必須相容
  `YYYY-MM` 或 `YYYY-MM-DD`；不可因新增深度驗證而把現有研究卡誤擋。若未來要統一完整日期，另做有備份的明確搬家。
- 分數只接受 0–5 的有限數字。
- 估值金額只接受有限數字，幣別走既有 `CURRENCIES`。
- 每個陣列元素必須是物件，文字欄必須是字串。
- URL 只存字串，顯示時仍要 `esc()`；連結限制 `https:`／`http:`，不可接受 `javascript:`。
- `symbol` 繼續走 `normalizePortfolioSymbol()`。
- 一個正規化代號只保留一筆研究。後端 POST 若已存在同代號研究，回 400 並指引改用編輯；PUT 若改代號後會撞到另一筆研究也回 400。不可只靠前端 `find()`。
- 寫入前後都要防原型鍵；若未使用文字當 map key，也不能因此省略輸入清理。

## 九、路由與開新分頁

### 已裁決路由

```text
#stock?symbol=AAPL
```

理由與必要改動：

- `public/app.js` 現行 router 會把 `stock?symbol=AAPL` 整串拿去查 `ROUTES`，因此 P4 必須修改 router 本體：先用 `split('?')[0]` 取得 `stock` 再查表，不能只新增 `ROUTES.stock`。
- router 呼叫頁面函式時不傳參數；`renderStock` 每次執行都必須從當下 `location.hash` 重新解析 `URLSearchParams`，不可在模組頂層快取 symbol，否則 AAPL 切到 GOOGL 會讀到舊代號。
- 不必把每個代號加進 `ROUTES`。
- 重新整理仍能回到同一家公司。
- 可安全使用 `encodeURIComponent(symbol)`。
- 不在側欄新增「個股研究」主入口，避免沒有代號時進到空頁。
- hash 帶參數時側欄沒有高亮項目可接受，v1 不為此新增假入口。

持股表個股代號：

```html
<a href="#stock?symbol=AAPL" target="_blank" rel="noopener">AAPL</a>
```

只對 `layer === 'stock'` 生效。其他層維持普通文字。

### 邊界

- 沒有 `symbol`：顯示「請從投資組合點選一檔個股」。
- 找不到持股、但有研究：仍可開啟，標示「目前未持有」。
- 找不到持股也沒有研究：顯示空狀態，不自動建立資料。
- ETF 若被錯設成個股層：頁面可以開，但顯示資料取決於來源；不在路由層猜它是不是公司。
- 所有 async render 在寫 DOM 前走 route sequence／generation guard。
- 新分頁會獨立跑一次 App 開機序列；現有報價與快照有伺服器端時間閘，屬可接受行為。
- `localStorage pf_viewCur` 會跨分頁共享，只影響新分頁的初始計價顯示，屬可接受行為。

## 十一、驗收考題

### 身分與入口

- `aapl`、` AAPL `、`AAPL` 都開同一頁。
- 同代號分散兩筆持股，摘要只顯示一家公司並合併股數／成本。
- 非個股層代號不是連結。
- 惡意代號不能插入 HTML 或 `javascript:`。
- 沒有 symbol 時顯示從投資組合進入的指引。
- 找不到持股但有研究時仍可開啟，並標示「目前未持有」。
- 找不到持股也沒有研究時顯示空狀態，不自動建立資料。
- ETF 若被錯設為個股層，路由可開但不猜資料；入口規則仍只看 `layer === 'stock'`。
- AAPL／GOOGL 的既有研究可讀；TSLA／SPCX 無研究時顯示「請先寫論點」空狀態。

### 數字

- 持股成本、市值與損益和投資組合頁相同。
- 個股占比使用淨資產分母，和紀律檢查相同。
- 個股上限明確設定 0 時顯示 0，不退回預設 5。
- USD／TWD 交易不跨幣相加。
- 缺值顯示「尚無資料」，不顯示 0。

### 評分

- 0 分是合法值，不可因 falsy 被當成未填。
- 6、負數、NaN、Infinity、字串分數被擋。
- 缺理由的分數顯示未完成。
- 五項完整時總分權重正確；缺任一分數或理由時只顯示「已評 X／5 項」，完全不顯示總分。
- 分數未變不新增歷史；同日多次變更只保留最後一筆。
- 顯示文字不把分數翻成自動買賣建議。

### 寫入與舊資料

- 現有只有 thesis／metrics／risks 的研究卡可正常開啟。
- 現有 `checkpoints[].date` 為 `YYYY-MM` 的研究卡仍可讀寫，不因新驗證被濾除或炸存檔。
- 儲存新欄位不會清掉舊 checkpoints。
- 只改評分不會覆蓋網路等待期間新增的檢查點。
- 壞巢狀陣列在 CRUD 400；備份還原 fail-closed。
- POST／PUT 都不能產生正規化後同代號的第二筆研究。
- `scorecard.reasons.*`、`catalysts[].text`、`sources[].label/url` 等自由文字經 `esc()`；`javascript:`、`data:` 等 URL 不可點擊。
- 新頁不會寫 holdings、accounts、securityTrades。

### 非同步與畫面

- 快速由 AAPL 切 GOOGL，慢回來的 AAPL 不蓋掉 GOOGL。
- 研究儲存完成時若頁面已切走，不重畫舊頁。
- 外部資料失敗時自己的研究仍可讀寫。
- 桌面 1280px、平板 768px、手機 390px 無重疊與橫向溢出。
- 新分頁可重新整理、可複製網址、可直接回到相同代號。
