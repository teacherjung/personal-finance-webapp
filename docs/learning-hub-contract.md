# 學習專區・影片線交付契約

> **這是理財 webapp 與教學影片 repo 之間的唯一接點。**
> 教學影片線 2026-08-25 分家獨立到 `../teaching-videos/`（GitHub：`teacherjung/teaching-videos`）；
> 影片線的規矩層、EPxx 腳本、詞彙短片治理**全部住在那裡**，本 repo 不留副本。
>
> ⚠️ **本檔刻意不放在 `docs/contracts/`**：那個目錄的定義是「AGENTS.md 同步點清單的**領域拆分**」
> （見 `docs/contracts/README.md` 開宗第一句），而本檔不是從同步點拆出來的，是一份**跨 repo 交付契約**。
> 硬塞進去還有一個實測到的技術阻礙：那道護欄要求「契約內文提到的 repo 路徑 ⊆ 已宣告且**存在**的檔案」，
> 而本檔的價值正在於點名**還沒建立**的 `public/modules/learn.js` 等未來檔案——兩邊夾殺，
> 只能靠拿掉路徑精確度來過閘，那等於毀掉這份規格的用途。
>
> ⚠️ **跨 repo 同步沒有機械閘**：本 repo 的考題掃不到影片 repo，反之亦然。
> 改到兩邊共用界線的人，自己負責兩邊都改。

## 一、影片線交什麼（交付清單）

**分兩條來源——因為兩條產線的成品住在不同地方**，這件事以前只寫在影片線的規則書裡，
本檔第一版把它壓成單一通道，是錯的（送審前預審抓到）。

### ① EPxx 正片（**第二節的 v0 規格要接的就是這條**）

來源＝影片 repo 的 `scripts/epXX-*.md`（每集一個腳本檔）。每集交：

| 欄位 | 來源 |
|---|---|
| `id` | **webapp 側指定**（集數識別碼，不由影片線給） |
| YouTube 影片 ID | 腳本檔的**「上架資訊」欄**（該欄＝影片 ID 的單一真相，上架後回填在那裡）；未上架時留空 |

**誰搬過來**：Claude 或 Codex，在本 repo 這側把該欄的值寫進集數 metadata（`public/learn/episodes.js`）。
影片線**不推**、webapp **主動拉**——工讀生不進本 repo，對面也沒有任何自動化會寫到這裡。
⚠️ 兩份值之間**沒有機械閘**：對面回填了、這邊沒同步，畫面就會一直是「影片還沒上架」（`Grok 掃 #4`）。
| 標題 | 腳本檔 |
| 三題測驗 | 腳本檔的「本集配套測驗」節 |

### ② 詞彙短片（**詞彙牆次階段**，累積 50–100 支後才開，不是現在）

來源＝Notion 生產看板（財金詞彙庫）。每支交：

| 欄位 | 來源 |
|---|---|
| YouTube 影片 ID | 看板「影片 ID」欄 |
| 標題 | 看板詞頁 |
| 主題領域、難度 | 看板既有欄位（詞彙牆的瀏覽與篩選用） |

**沒有三題測驗**——500 支×3 題的審題量刻意不排入主產線。

> ⚠️ **「唯一接點」這個詞兩邊的射程不同，別混用**：影片 repo 的 `AGENTS.md` 說的是
> 「**工讀生產線**與 webapp 的唯一接點」，指的只有上面第 ② 條（看板→repo）。
> 本檔說的範圍更大：**兩條產線的交付都經過本檔**。

## 二、webapp 怎麼接（v0 規格，最小可行）

> 以下整節自影片線規則書遷入（原 `docs/教學影片/製作流程與分工.md`「給 Codex 的學習專區規格」節）。
> 遷入的理由：它是**純 webapp 實作規格**，不該跟著影片線搬走；而它是學習專區唯一的成文規格，
> 留在原檔會隨分家一起被刪掉。

- **新「學習」區塊**：集數列表 → 點開＝影片播放器＋該集三題測驗＋答對亮徽章。
- **影片來源**：**YouTube 嵌入**——iframe 用 `https://www.youtube-nocookie.com/embed/<影片ID>`（隱私增強模式，按播放前不種 cookie）。不需要本機影片資料夾或新 static 路由。
- **集數 metadata**：靜態檔（如 `public/learn/episodes.js`——id、標題、**youtubeId**、三題測驗），純內容、可進 git。
- **學習進度**：存 DB 新集合（每集：是否看過、測驗是否通過、徽章）——照鐵則走 schema 白名單＋欄位所有權表補列＋隔離 DB 測試。
- **互動**：vanilla JS module（`public/modules/learn.js`），不引框架，遵守現有 UI 規範（色票、.stat/.num/.empty…）。
- **降級**：斷網或 youtubeId 未填時顯示白話空狀態（「影片還沒上架」／「目前離線，附 YouTube 連結」），不能整頁壞掉。屬可接受的本機優先例外——與報價抓取、SEC 基本面、CAPE／實質殖利率同級。
  〔遷入時更正：原文寫「全 app **唯一**需要網路的顯示區塊（跟報價抓取同級）」——同一句自己打架，
  而且 HOSTED 上線後整個 app 的資料顯示都走網路。那句是 2026-07-22 寫的，遷入時若照抄就等於
  把一個過期的絕對句變成**現行**契約語句（`Grok 掃 #6`）。〕
- **同步點**：實作 PR 必須同步更新 AGENTS.md（YouTube 嵌入慣例、欄位所有權表、學習專區段落）。
- EP01 的測驗題目在影片 repo 的 `scripts/ep01-survival-first.md`「三、本集配套測驗」節。
  〔遷入時更正：原文寫的 `EP01-生存優先-腳本.md` 已隨分家改名搬走。這一行**直接改成現址**，
  不採「保留原文＋另段更正」——那會讓同一份規範先指空、再撤回自己（`Codex #514 r1` 中②）。〕

## 三、另外兩條跨線流動（不是「交付」，但同樣經過本檔）

前兩節是「影片線交成品給 app」。分家後還有兩條**方向不同**的流動，原本寫在被刪的規則書裡，
如果不寫進來就會變成沒人接的孤兒（`Grok 掃 #1／#2`）：

### ① 影片線 → app 文案：「看不懂的句子」

工讀生製作時的**讀者測試站**會產出一欄「看不懂的句子」（記在 Notion 生產看板）。
原規則書明訂：那些回饋**同時餵回 app 的就地解釋文案**。

- 這不是 YouTube ID、不是三題測驗——是**文案輸入**，收件人是本 repo 改就地解釋的人。
- ⚠️ 它與 **Grok 的讀者測試員**那一職**射程不同、互不取代**：工讀生測的是影片看不看得懂，
  Grok 測的是 app 的就地解釋文案看不看得懂。原規則書特別寫過這句區分，別把兩者混成一件事。

### ② app → 影片線：投資規則數字改了

`AGENTS.md`「投資領域語意」節的規則數字（**個股 5%／單一國家 15%／槓桿 1.3 倍**等）是本 repo 的正本。
原規則書的影片鐵則第 3 條寫明：**改了規則，要回頭改還沒發布的腳本。**

- 這條**必須點名那組數字**，不能只寫「共用界線兩邊都要改」——EP01 場 4 的台詞就逐字念著這三個數字，
  泛稱撐不住（這個 repo 一向是**沒點名就會漂**）。
- 收件人＝在本 repo 改上限的那個人；動作＝去影片 repo 檢查未上架腳本。
- ⚠️ 一樣**沒有機械閘**：本 repo 的考題掃不到對面的腳本。
