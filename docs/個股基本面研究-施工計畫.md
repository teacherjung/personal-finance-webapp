## 一、這次要解決什麼

現有個股研究頁已能放持股、論點、五項評分、估值、風險、檢查點與交易，但還有兩個缺口：

1. 使用者知道「要研究一家公司」，卻沒有一套固定問題協助自己從生意、財務到風險逐步檢查。
2. 關鍵基本面仍靠手動抄寫，容易漏期間、單位與來源，也不容易每季用同一口徑重看。

本主線的目標是：

- 建立一套不依賴特定公司的研究方法。
- 自動取得美股公司向 SEC 申報的官方 XBRL 基本面資料。
- 清楚區分「公司申報的原始數字」與「NotEasy 依公式計算的比率」。
- 把現有長頁改成像 Chrome 的頁籤，讓各種研究工作各有固定位置。
- 外部資料失敗時，使用者自己的論點、評分、估值與交易仍可完整使用。

## 二、範圍裁決建議

| 項目 | Codex 建議 |
|---|---|
| 第一版市場 | 只做美股 SEC；台股另開 P7，不共用解析器 |
| 第一版公司 | 先支援使用 US-GAAP、申報 10-K／10-Q 的一般營運公司 |
| 特殊產業 | 銀行、保險、REIT 顯示「需專用框架」，不硬算自由現金流或負債健康度 |
| 外國公司 | 20-F／IFRS 先顯示有限資料與原因，另開相容階段 |
| 自動化邊界 | 自動整理證據，不自動評分、不產生買賣建議、不自動改研究狀態 |
| 更新方式 | 頁面載入時讀快取；無資料或超過 24 小時則背景更新，另保留手動更新按鈕 |
| 資料保存 | 官方快取獨立於 `research`，由服務層擁有、前端唯讀 |

這個收斂是刻意的。AAPL、GOOGL 可先完整驗證；若第一版同時承諾台股、金融業、REIT 與 IFRS，欄位語意會在一開始就混成一套看似通用、實際不可靠的公式。

## 三、研究一家公司要回答的八組問題

### 1. 公司靠什麼賺錢

- 客戶是誰，付錢買什麼？
- 收入來自哪些產品、地區或客群？
- 收入是一次性、週期性，還是可重複？
- 最重要的成本與產能限制是什麼？

自動資料只能先回答總營收與整體趨勢。產品／地區拆分常使用公司自訂 XBRL tag，第一版不假裝能跨公司一致解析，仍由使用者閱讀 10-K／10-Q 後寫入投資論點。

### 2. 護城河是否真的存在

- 客戶為什麼不換別家？
- 優勢來自品牌、網路效應、轉換成本、成本結構、規模還是法規？
- 這個優勢是在增強，還是在被競爭侵蝕？
- 毛利率與營業利益率是否支持這個說法？

### 3. 成長從哪裡來

- 成長是價格、銷量、新產品、併購還是景氣循環？
- 營收成長是否也帶來營業利益與現金流成長？
- 成長是否需要愈來愈高的資本支出？
- 稀釋後每股成果是否跟公司總額一起成長？

### 4. 利潤是否能變成現金

- 淨利與營業現金流長期是否同方向？
- 自由現金流是否穩定，或只在單一年份看起來很好？
- 應收、存貨或預付款是否吃掉現金？
- 股票薪酬是否讓現金流好看，卻持續稀釋股東？

### 5. 資產負債表能不能讓公司活過壞年

- 現金與債務各有多少？
- 利潤下滑時，現金流能否負擔利息與必要投資？
- 是否依賴短期融資或不斷發新股？
- 帳上負債的風險是否符合這個產業的正常結構？

金融業的負債本身就是營運原料，不能套一般公司的「債愈少愈好」，所以第一版不自動下結論。

### 6. 管理層怎麼分配資本

- 現金拿去再投資、併購、還債、股利還是回購？
- 回購是否真的降低稀釋後股數，還是只抵銷股票薪酬？
- 高資本支出有沒有換來後續營收與利潤？
- 併購後商譽、減損與報酬是否合理？

### 7. 現價需要多好的未來

- 保守、基準、樂觀三種情境各需要哪些成長與利潤假設？
- 現價相對情境合理價值的距離是多少？
- 目前估值是否已經要求公司長期維持非常高的成長？
- 估值變便宜，是價格波動還是基本面真的變差？

估值仍由使用者填三情境；官方基本面只提供可查證的輸入，不產生單一「正確目標價」。

### 8. 什麼證據會證明自己看錯

- 哪三件事一旦發生，原始論點就不成立？
- 哪些是短期價格波動，哪些是企業本質惡化？
- 下一份財報要檢查哪 3–8 個指標？
- 何時重新評分，什麼情況需要降部位而不是加碼？

這組問題承接既有 `thesisBreakers`、`watchMetrics`、`checkpoints` 與研究狀態，不新增第二套研究筆記。

## 四、第一版基本面指標

### 官方原始值

| 類別 | 指標 | 主要用途 |
|---|---|---|
| 成長 | 營收、營業利益、淨利、稀釋後 EPS | 看公司總額與每股成果是否同方向 |
| 現金 | 營業現金流、資本支出 | 看帳面利潤有沒有變成現金、成長需要多少投入 |
| 生存 | 現金及約當現金、流動／非流動債務 | 看壞年承受力；不替金融業下通用結論 |
| 股東 | 稀釋加權平均股數、股票薪酬、回購、股利 | 看稀釋與資本分配 |
| 來源 | 申報表單、期間結束日、申報日、accession、原始 taxonomy／tag／unit | 讓每個數字可追回原申報 |

### NotEasy 衍生值

| 指標 | 公式與限制 |
|---|---|
| 3 年營收複合成長率 | 同口徑年度營收 `(最新／最早)^(1/年數)−1`；期間不足不算 |
| 毛利率 | 毛利／營收；公司沒有可比毛利 tag 時顯示尚未取得 |
| 營業利益率 | 營業利益／營收 |
| 淨利率 | 淨利／營收 |
| 自由現金流 | 營業現金流−資本支出；畫面明標「NotEasy 計算」 |
| 自由現金流率 | 自由現金流／營收 |
| 現金轉換 | 營業現金流／淨利；淨利小於等於 0 時不硬解讀 |
| 股票薪酬占營收 | 股票薪酬／營收 |
| 稀釋股數變化 | 最新稀釋加權平均股數相對前期 |

第一版不自動算 ROIC、EBITDA、淨債務／EBITDA、PEG 或單一合理價。這些項目涉及更多會計選擇、產業差異或市場價格來源，先求口徑能被逐筆重現。

## 五、官方資料契約

### 官方來源

- SEC EDGAR APIs：`company_tickers.json` 做 ticker／CIK 映射。
- `data.sec.gov/submissions/CIK##########.json` 取得公司與申報歷史。
- `data.sec.gov/api/xbrl/companyfacts/CIK##########.json` 取得 entity-level 標準 XBRL facts。

[SEC Developer Resources](https://www.sec.gov/about/developer-resources) 說明這些 JSON API 不需 API key、`data.sec.gov` 不支援瀏覽器 CORS，因此必須由後端呼叫。自動請求必須宣告可識別 `User-Agent`，官方目前 fair-access 上限是每秒 10 次；本案自己的佇列上限採每秒 2 次，留足餘裕。

官方依據：

- https://www.sec.gov/search-filings/edgar-application-programming-interfaces
- https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data

### 回傳形狀

```js
{
  symbol: "AAPL",
  market: "US",
  company: {
    cik: "0000320193",
    name: "Apple Inc.",
    sic: "3571",
    fiscalYearEnd: "0926"
  },
  source: {
    provider: "SEC EDGAR",
    fetchedAt: "2026-07-28T00:00:00.000Z",
    stale: false
  },
  periods: {
    annual: [],
    latestQuarterBasis: "per-metric",
    latestQuarter: null
  },
  metrics: {},
  warnings: []
}
```

每個 fact 必須保留：

```text
value
unit
periodStart
periodEnd
form
filedAt
accession
taxonomy
tag
filingUrl
```

畫面所顯示的衍生值另保留 `formula` 與 `inputs`。不能只回一個數字，否則無法知道兩家公司是不是用了不同 tag 或不同期間。

### 期間選擇

- 年度趨勢只選 10-K／10-K/A 的 FY facts，最多五年。
- 季度只選可辨認為單季的 10-Q／10-Q/A facts；YTD 累計值不能冒充單季。
- 同一期間若有修訂申報，以較晚 `filedAt`／accession 為準，仍保留來源。
- 不把不同 unit、不同 taxonomy 或不同期間長度混成一條趨勢。
- Q4 單季值第一版不靠「全年減前三季」推算；無官方單季 fact 就顯示尚未取得。
- fiscal year 不假設等於曆年，標題使用實際 period end。

### Tag 策略

每個指標使用有順序的候選標準 tag，但命中時仍回傳真正使用的 taxonomy/tag。候選都沒有時顯示缺值，不用公司名稱或產業猜數字。公司自訂 extension tags 第一版不自動映射。

## 六、抓取、快取與失敗退路

### API

```text
GET  /api/stock-fundamentals/:symbol
POST /api/stock-fundamentals/:symbol/refresh
```

- `GET` 只讀最後成功快取並回報新鮮度。
- 頁面在快取不存在或超過 24 小時時，自動呼叫 `POST refresh`。
- 手動更新按鈕也走同一支 `POST`，不另做第二套抓取。
- `symbol` 先走 `normalizePortfolioSymbol()`；CIK 與 SEC URL 由伺服器自己組，不接受任意外部 URL，避免 SSRF。

### 快取

沿用前案的服務層唯讀集合 `stockFundamentals`：

- 不進通用 CRUD 白名單。
- 不混入使用者手寫的 `research`。
- LOCAL 與 HOSTED 都走 `repo.js`；每位受邀使用者先保存自己的公開資料快取，避免在 C4b 初期新增跨 tenant 的 RLS 例外。
- 使用者數量擴大後，才另案搬成全站共享公開快取。
- 網路失敗、timeout、429 或解析失敗時保留最後成功值，只更新錯誤狀態，不寫空值覆蓋。

### 對 SEC 的護欄

- `SEC_USER_AGENT` 必須是 `產品名稱 聯絡信箱`；正式值為 `NotEasy hsiangsenjung@gmail.com`（William 2026-07-28 定；理由見 C6 部署手冊「三」節）。
- 每次請求從連線到 response body 完整讀完都有 timeout，另有 25MB 串流回應上限、全域佇列與每秒 2 次上限。
- 429／5xx 有有限次數退避重試；4xx 映射錯誤不無限重試。
- 不在 log 印整份回應；錯誤只記 symbol、CIK、狀態碼與階段。
- 即使 SEC 失敗，`/research`、持股與交易仍能正常載入和編輯。

## 七、Chrome 式頁籤

### 六個頁籤

```text
總覽｜基本面｜評分｜估值｜論點與追蹤｜交易
```

| 頁籤 | 內容 |
|---|---|
| 總覽 | 公司名稱、研究狀態、目前部位、論點摘要、反證摘要、最近檢查點 |
| 基本面 | 八組研究問題、官方指標、五年趨勢、最新申報與來源 |
| 評分 | 現有五構面分數、理由與歷史 |
| 估值 | 現價、保守／基準／樂觀情境、假設與距離 |
| 論點與追蹤 | 完整論點、風險、催化劑、反證條件、檢查點、研究來源 |
| 交易 | 現有同代號原幣交易表，不跨幣別加總 |

### 互動與網址

- 頁首與六頁籤固定在內容頂部；選中頁籤視覺上與下方內容相連，使用 6–8px 上圓角與底線，不做膠囊按鈕。
- 網址保存頁籤，例如 `#stock?symbol=AAPL&tab=fundamentals`；重新整理、複製網址與上一頁都能保留位置。
- 不另外保存 `localStorage` active tab，避免網址與畫面走散。
- 桌面一列顯示；手機採水平捲動的穩定寬度頁籤列，不縮字、不讓長字重疊。
- 使用連結式分頁與 `aria-current="page"`，沒有 JavaScript 時仍可依網址導航。
- 空研究仍可開「總覽」「基本面」「交易」；需要手寫研究的頁籤顯示既有建立研究入口。

## 九、驗收考題

### 研究方法

- 每組問題都說明「要回答什麼」與「自動資料能／不能回答什麼」。
- 金融業、REIT、IFRS 不會被一般公司公式硬套成看似精準的分數。
- 官方資料不會自動修改使用者評分、研究狀態或估值。

### 數字與期間

- 0 是合法數字，缺值是 `null`／「尚未取得」，兩者不混。
- 10-Q 的六個月／九個月 YTD 營收不會被顯示成單季。
- 修訂申報會取代同期間舊值，但來源仍指向新 accession。
- 不同幣別、unit、期間長度或 taxonomy 不會混成一條趨勢。
- 自由現金流與所有比率可由回傳 inputs 重算得到相同結果。
- Q4 沒有官方單季 fact 時不靠減法猜值。

### 安全與韌性

- 任意 symbol 不能控制外部 URL；`__proto__`、斜線、查詢字串與超長代號被擋。
- 未登入不能讀或刷新端點；A 看不到 B 的快取列。
- SEC timeout／429／壞 JSON 不會清空最後成功資料。
- SEC 回應中的公司名稱、label 與來源文字進 HTML 前都經 `esc()`。
- 更新按鈕連點只合併成一個 in-flight 請求，不形成放大攻擊。

### 頁籤接縫

- `#stock?symbol=AAPL&tab=valuation` 重新整理仍在 AAPL 估值。
- 非法 tab 回到總覽，不白屏、不讀原型鏈。
- AAPL 基本面慢回來時切到 GOOGL，不會蓋回 AAPL。
- 手機 390px 的頁籤可水平捲動，頁面本身沒有橫向溢出。
- 交易仍依原幣逐筆顯示，切頁籤不改交易排序與數字。
