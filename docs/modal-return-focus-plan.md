# 共用彈窗關閉後的焦點回復：施工計畫

本階段修正共用彈窗關閉後的焦點回復與舊外殼關閉新窗問題。本人於 2026-10-17 指派先做本項，Claude 工具驗收待額度恢復另補。施工從已合併主幹起，專屬暫存樹與正常複審、掃描程序依本支紀錄；不改 Gemini 掃描接線。

## 問題與依據

原工程待辦第 2 項。隔離 DOM 診斷載入正式 app 與 modal-shell、攔截所有 API 為合成回應，確認原入口仍存在時能回焦；替換原頁 DOM 使入口消失後，關窗焦點落到 BODY。另確認舊 shell 的 close 能清掉後開彈窗及其輸入。這些不是實際瀏覽器或真換頁驗證，後續仍須補齊。

技術裁示：[原入口消失時以目前頁面標題回復焦點](https://github.com/teacherjung/personal-finance-webapp/pull/679#issuecomment-6147689635)。由原目標授權的 GPT-6.1 Sol／xhigh 技術代裁，並非 William 本人原話；實際畫面仍須本人依 E10 定案。

## 定案行為

- 彈窗真正關空、焦點沒有有效歸屬時，原入口若仍能接焦點則優先回到原入口。
- 入口已不可用時，選目前頁面可見的主要 h1；沒有可用標題才選目前導航項，兩者都不可用就不猜其他控制項。
- 延後回焦前重核彈窗代次與使用者焦點。新彈窗即使已開過又關空，較舊的回焦工作也不得生效。
- 標題需要時暫加 tabindex=-1，焦點離開後還原；原本已有的屬性不改。
- modal-shell 的 close 以對話框身分防止舊回呼清掉新窗，同時保留跨頁後由使用者手動關閉當前窗的能力。

## 驗證

- 保留既有 Esc、Tab、初始焦點、owns、handoff 及接管鏈回復題。
- 用真路由切換及同頁重畫移除入口，驗 activeElement、標題與導航優先序；原入口仍可用的情境不得退化。
- 驗暫時 tabindex 在 blur 後移除、既有屬性保持、新使用者焦點不被搶走。

## 接線與驗證注意事項

- 延後回焦的代次需與每次新窗綁定；舊觀察器先核身分，再清回焦記錄，避免新窗也關空時由舊觀察器刪掉新記錄。新窗仍開著與已開又關空分開驗，記錄實際 focus 呼叫次序，不能只驗最後落點。
- 可接焦點不只表示仍連在 DOM：原入口若 disabled、hidden、祖先隱藏或 inert，需驗無法接收後的退路。先檢查使用者是否已有有效焦點，不可因舊入口還在就搶回。
- h1 暫加 tabindex 僅限原本沒有屬性，離焦時還原；既有值保留。若 focus 沒有成功，當次就收回新增屬性，不能留一個無效暫存標記。
- stale shell close 依實際 dialog 身分防後開新窗；不能只用 owns() 阻擋，因為真換頁後仍要讓本人關掉目前窗。
- DOM 題須自行建立每題起點並清空、等待前題觀察器落定；路由與重畫分開測。真正按鍵／原生焦點行為另用瀏覽器驗，不把 jsdom 合成事件冒充瀏覽器預設動作。
- 舊鍵盤驗收僅為部分流程代驗：#648 的 10/10 紀錄驗了信用卡上傳與訂閱新增兩種彈窗，明載未驗原生下拉內部、其餘彈窗、讀屏與其他瀏覽器；本項不沿用全面通過的說法。

## 真瀏覽器發現的晚重畫補正

正式新增訂閱儲存會先關窗、回到舊入口，非同步讀取稍後重畫又移除入口。依 [GPT‑6.1 Sol 本支技術裁示](https://github.com/teacherjung/personal-finance-webapp/pull/694#issuecomment-6220249789) 併修，不改訂閱等待、儲存或重送流程。共用 helper 僅為成功初回焦建立一次移除補償；任何後來的有效焦點與新窗均優先，候選之間、focus 同步事件後及觀察回呼均重核，補償後不再追蹤其目標。

解除事件：document capture 的 pointerdown／keydown／touchstart／wheel、focusin 到其他節點；已回焦節點的 blur（依下方分類補正延後一個微任務核連線與持焦）；window hashchange／blur／pagehide；document 隱藏的 visibilitychange。新窗代次、root 失效、換頁世代及完整 hash 另作守門。不宣稱識別所有使用者意圖。暫加 tabindex 由真正離焦或節點移除清理，保留既有及他方改動；撤銷補償不提早破壞仍持焦節點屬性。

工具只提供 IAB 與 MCP Apps，沒有 Chrome 入口；依同份技術裁示以實際 IAB 原生 Tab／Shift+Tab／Esc 及唯讀 DOM 核對，不宣稱 Chrome、其他瀏覽器或讀屏已驗。本人已確認焦點順序與原生細框，見 [E10 定案](https://github.com/teacherjung/personal-finance-webapp/pull/694#issuecomment-6220112096)。晚重畫修法保持相同已定焦點結果。

### blur 分類補正與保留的反例

IAB 正式儲存實測在列表重畫移除按鈕前先發出 blur，當時 isConnected 仍為 true。立即取消會錯失正常儲存的一次補償。依[補充技術裁示](https://github.com/teacherjung/personal-finance-webapp/pull/694#issuecomment-6220346277)，只把目標自身 blur 的分類延後一個微任務；仍連線且不持焦才取消，已移除留給原觀察器。其他解除維持立即。沒有其他接管訊號時，同回合主動 blur 再同步移除也可補償一次；保留這個原反例並更正斷言，另驗 blur 完成檢查點後才重畫會取消，不能把兩題混同。
