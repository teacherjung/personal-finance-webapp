## 訂閱續費日自動推進

**改這裡**：**訂閱續費日自動推進**（使用者定 2026-07-26）

**記得同步這裡**：`nextCharge` 是使用者手填的固定日期、不會自己走——日期一過那筆就從續費時間線（只畫未來 30 天）消失（使用者實測 26 筆有 5 筆卡在過去）。**開 app 每次都會把過期的續費日推到下一期**：判準與新日期＝`subscriptions-model.js rolledNextCharge()`（純函式、有考題），寫入＝`lib/services/subscriptions.js rollDueSubscriptions(todayIso)`，掛在 `snapshot.js takeSnapshotIfDue()`（＝既有的「開 app 每日維護」入口，回傳多一個 `subsRolled`；**刻意不改 `lib/routes/core.js`**——沿用既有入口就不必動路由；`public/app.js` 則**必須改**：推進成功要重繪，見下）。**月底錨點 `chargeAnchorDay`**（服務層擁有的欄位，Codex 複審 2026-07-26）：推進用「原本約定的號數」算，不是拿收月底後的結果再加——1/31 推成 2/28 後，下個月若從 28 起算會變 3/28、一路縮回不來。**使用者一改 `nextCharge`（CRUD PUT）＝新舊值真的不同時，後端才把錨點換成新日期的號數；清空日期一併清錨點**（`lib/routes/crud.js` 的 subscriptions beforeSave，用 `prev` 比新舊值）——⚠️ **不可只看「請求有沒有帶 nextCharge」**：訂閱表單儲存會回送日期（即使日期沒改），只看「有帶」會讓「只改信箱」也把錨點蓋成當下日期的號數（2/28→28），下個月又縮成 3/28（Codex 複審 2026-07-26 第二輪實測）——⚠️ 只靠「錨點對不對得上現在的日期」推斷**不夠**：1/31 的錨點 31 遇到使用者手動改成 4/30 時 `min(31,30)=30` 剛好對得上、舊錨點會復活，下個月變 5/31（Codex 複審 2026-07-26 實測；使用者選的是 30 號）。`chargeAnchorDay` **不在 CRUD 白名單**，前端送不進來，只由該處與自動推進服務寫（HTTP 全鏈路考題在 `test/server.test.js`）。**不推的情況**：終身、已停用／已結束、**使用者手動填了停用日或標成即將停用**（使用者原話「除非我手動輸入停用日」）、沒有合法續費日、日期還沒到（含今天）。逾期多期＝一次推到「第一個未來日期」，不補記過去每一期（本 app 不記錄過去的扣款）。⚠️ **只動日期、不動任何金額**：攤提看 `since/endsOn/amount/cycle`，與 `nextCharge` 無關（考題直接比對推進前後每月 `costForMonth` 與總覽訂閱月費）。⚠️ 月底錨定：每期都從**原始日期**加 N 個月，否則 1/31 會一路縮成 28 號。沒有任何一筆要推就**不寫檔**。**推進後前端要重繪**（`app.js` 依 `subsRolled.length` 觸發 `router()`；2026-09-30 起不跳 toast，推進了幾筆寫在總覽最下面的「開 App 自動更新檢查」區塊——裁示 #651 留言 5903711899）——今天已記過快照、報價也還新鮮時，原本兩個重繪條件都不成立，訂閱頁會停在舊日期直到切頁（Codex 複審 2026-07-26）。**推進時同一次寫檔記 `settings.subsLastRolledAt`**（ISO 時間、服務層擁有、匯入不保留；#653 留言 5905965930「開始記錄」）：那一塊在這次沒有要推時用它寫「上次推進」；時間只在真的推了的分支裡寫，「沒得推就不寫檔」不變。時鐘倒退時整段每日維護已被既有護欄擋掉，這裡自然也不跑。⚠️ 對應的**過期提醒（`derive.js`）2026-07-26 拿掉「只提醒 30 天內」的下限**——原本過期超過 30 天就同時從時間線與提醒牆消失＝愈久沒處理愈安靜；現在自動推進處理常態、提醒當推不動時（時鐘倒退／每日維護沒跑到）的安全網。

## 訂閱表單成功後確認與呈現順序

**改這裡**：`public/modules/subscriptions.js` 的 `openSubForm`、訂閱讀取與呈現登記、表單確認提示及重讀焦點。

**記得同步這裡**：完整表單成功與畫面呈現權分開。開始等待 PUT／POST 前捕捉呈現 owner 及表單的正常交棒資格；較新操作、取消、新窗或換頁撤銷舊續行的呈現權。既有 API 回報成功後，表單專用版次仍記住成功事實；失敗不記成功，不保留 payload、不把回應插回列表，也不納入標記寫入佇列或刪除確認帳。

每個實際 GET 開始時記下已涵蓋的表單成功版次；具資格且成功交付的讀取才消化該範圍。後到成功不能被較早讀取、錯誤或 finally 清掉。辨識出較早快照後，拒收且不新啟動該快照的 autoExpire／freezeCompletedMonths 維護；已開始的自動寫入及同筆並行寫入不由這項契約排序或回滾。

失去資格的成功不自動 GET、不改目前頁殼、列鈕、成功通知或焦點。當前有效訂閱頁另以「資料已儲存，請重新載入確認更新」與「重新載入」提供確認途徑；它只表示尚待確認，不保證畫面必定過期。空清單也登記有效呈現，刪除同步須保存這個獨立提示而不復活已刪資料。其他視窗開著時不新增提示或移焦；頁面持有的有限觀察在關窗後交付提示，頁面失效、提示交付或成功事實已消化即清理。離開訂閱時保留最小成功事實，回來的有效新讀取可以確認。

重讀只走既有讀取鏈，不重送原表單；待讀期間停用按鈕，較早終態不得解鎖較新讀取。確認失敗且有效頁面仍在時保留原頁與可重試入口；首次讀取遭較新成功作廢時，交付可重新載入的終態，不自動循環 GET。確認按鈕的有限回焦只給仍持有資格的本次工作；移焦、新窗、導覽或較新呈現接管優先。共同視窗自己的合法關閉回焦仍依既有契約。

圖表清理跟隨實際畫面替換：載入卡、合法成功頁及普通錯誤頁取代舊頁前清理原訂閱圖表；保留頁面的在途讀取與確認失敗不先清理。舊工作失格後不得清理較新呈現所建立的實例。

驗證分工：`test/subscriptions-row-focus.test.js` 使用合成 fetch 與真 DOM，比對操作次數、節點身分、待確認版次的行為、刪除／標記及焦點接縫；`test/subscriptions-form-preservation.test.js` 與 `test/helpers/subscriptions-form-case.js` 以本題合成 LOCAL HTTP 帳本分別延後送出與延後回應，核對實際寫入及後續 GET 回讀。合成證據不代替原生瀏覽器驗收、外部寫入或跨視窗一致性。資料欄位、schema、API payload 與日期／金額口徑未因這項呈現契約改變。

## 每日洞察引擎書籤 insightState

**改這裡**：**每日洞察引擎書籤 `insightState`＋差異引擎**（D3，2026-07-22）

**記得同步這裡**：`lib/services/insights.js getInsights()` 是唯一寫入口，`GET /api/insights` 呼叫它——**讀取＝視為「看過了」→ 當下更新書籤**（有寫檔副作用，故只有總覽呼叫）。差異＝現在 vs 書籤：🆕新出現/✓已解除（留 title 供顯示）/持續中、跳檔（估值檔位 0/1/2，**null↔值不算跳**）、自上次 Δ、固定窗 Δ（今天/本週，從 `dailyValues` 找最接近既有日、不足不顯示）、平靜判定（無🆕/✓/跳檔且今日Δ% 的絕對值小於 0.3%）。**首次執行（空書籤）全當持續中、不標🆕**——「有效書籤」需**同時有 `lastSeenAt`(字串)＋`reminders`(陣列)**（缺任一＝退回首次，免殘缺書籤把當下每條都謊報🆕，D3 自審#2/#5）。⚠️**新增/改提醒（`derive.js`）鐵律**：**同一顧慮的升級必須共用同一把 key**（如訂閱/保險「將至」→「已過」都用 `sub-charge-{id}`／`ins-pay-{id}`，不可拆 `-overdue-`；差異引擎純比 key，拆 key 會在升級當下把仍在惡化的顧慮謊報成「✓已解除 👍」＋🆕，保險漏繳是 danger＝生存級，D3 自審#1）——比照 `card-due-{id}` info→warn 同 key。固定窗 Δ% 用 **abs(基期)**（淨值為負時方向才不反轉，D3 自審#4）；基期 0 但有變動＝不平靜（D3 自審#3）。⚠️**read-await-write**：先 await 報價（`getCape`/`getRealYield` 算 ECY，失敗靜默 null）、**await 之後才 `getDb`→算→`saveDb`**（同 D1/syncIb r3#1）。`insightState` 是**頂層 map 型鍵**：`lib/store.js` 的 **`KV_KEYS` 與 `KV_MAP_KEYS` 都要有它**（漏了 save 不寫、靜默丟失，實測踩到）＋`schema.js sanitizeInsightState`（接進 sanitizeDbForWrite，防壞形狀）＋`emptyDb`＋`types.js InsightState`。服務層專寫、非 CRUD 白名單。總覽最下面「開 App 自動更新檢查」的「更新洞察」一行讀的是**同一次**抓取（`fetchInsightsOnce`，不另外呼叫）：回了 `seenAt` 才算成功，路由接住錯誤回的 200（帶 `error`）算沒成功；那一行有自己的 30 秒等待上限，只管那一行，洞察這一區的退回邏輯不受影響。

## async render 與路由序號 guard

**改這裡**：**async render 寫 `#view` 前要 guard 序號**（Codex r10#6）

**記得同步這裡**：⚠️ **async render 寫 `#view` 前要 guard 序號**（Codex r10#6）：render 一進場 `const seq = currentRouteSeq()`，`await` 完、**動任何 DOM/圖表（含 `destroyCharts`）之前**先 `if (seq !== currentRouteSeq()) return;`——不然快速切頁時慢頁 resolve 會蓋掉新頁（router 的事後檢查太晚，寫入發生在 render 內部）。有遞迴重載（如 `renderSubscriptions` 的 autoExpire）也要在遞迴分支前 guard。**表單儲存後的重畫也必須先確認仍在原路由**，不可把裸的 `renderXxx` 傳給 async action；同一頁可同時啟動多代 render 時，再加頁面 generation，外部資料晚回來只能寫入目前 generation 的容器。

**訂閱標記鈕回焦**：`public/modules/subscriptions.js` 的「考慮停用」標記鈕，只有原鈕發起時確實持焦、仍在自己的列表，且等待期間未被接管，才在本次最新正常列表接好事件後回焦一次。依穩定訂閱身分找同筆標記鈕，再退同列編輯鈕，最後才是「訂閱與近期扣款」h2；身分重複不猜列，候選須唯一、連線、可見、非停用／inert且實際接得住焦點。標題暫加tabindex僅在離焦／移除後還原自己未被改寫的值，既有屬性保留。

焦點工作與PUT分開：建立後的鍵盤、指標、觸控、滾輪、外部移焦、原鈕非自身同步替換造成的blur、完整hash／nav變更、視窗失焦、文件隱藏、新窗世代或較新呈現會撤銷回焦；不撤銷或重送已接受的寫入。新窗即使開後關閉，也不能復活舊工作；候選focus事件接管後停止。單純移焦或新窗不取消仍有完整呈現權之最新作業的既有GET／重畫流程，不碰新窗輸入或主動移焦。PUT失敗保留既有錯誤；目前作業的GET失敗、空清單或沒有可用候選時沿既有畫面，不新增聚焦錯誤、重試或新增鈕的退路。

標記作業在按鈕啟動時取得私有呈現序號，不依焦點工作是否仍活著決定順序；較新標記或外部render接管後，舊PUT晚回不得重新取得整頁呈現／通知權或另起GET。相同id的已接受PUT局部序列，不同id獨立；每筆目標依接受當時的可見已確認值取反後凍結，不以未確認目標實作樂觀反向。正式PUT回音的id、嚴格布林與原目標符合時，才確認該flag；目前正常列表的同id資料與列均唯一且頁面身分仍有效，則原地更新同一模型物件、圓點及既有按鈕外觀，保留頁面、列、按鈕、通知與焦點。其他欄位不採舊回音；缺列、重複身分、錯誤或空白頁不新增或搬回列。

仍有效的完整讀取以開始時的確認修訂為界，只在返回列id唯一時合併其後已確認的flag，讓DOM與事件閉包使用同一份資料；已在讀取前確認的值由該次正式GET提供，不永久用本機紀錄壓住新讀取。確認紀錄只保護仍可提交的在途讀取，讀取收尾或失去呈現權後清理。完整提交同時核啟動呈現序號及讀取代次；舊GET的成功／失敗均不提交新頁，自動校正遞迴沿原有效讀取鏈，不改校正、攤提、拖曳或歷史資料規則。本模組之外的表單、視窗與外部寫入一致性不在保證內。本人定案、[交錯修正裁示](https://github.com/teacherjung/personal-finance-webapp/pull/699#issuecomment-6243688583)及未涵蓋的刪除、表單儲存與其他入口見[施工計畫](../subscriptions-row-focus-plan.md)；真DOM考題在 `test/subscriptions-row-focus.test.js`，不將jsdom視為瀏覽器版面證據。

**訂閱刪除回焦與確認**：刪除有獨立私有工作，不加入標記 PUT 尾鏈或標記確認修訂。原鈕持焦且通過原生確認前後的身分／新窗檢查，才取得回焦資格；確認取消不送 DELETE，失去焦點資格不取消已接受刪除。仍在原呈現的成功讀取接好頁面後，只考慮唯一可用的「訂閱與近期扣款」h2；成功全空才考慮「訂閱追蹤」h1，失敗及候選不可用時不另猜落點。等待期間的接管條件沿上述焦點界線，臨時 tabindex 只還原自己的值。共用關窗回焦依其自身生命週期運作，不能把其回焦算成刪除工作復活。

DELETE 接受時取得呈現 owner；較新標記、刪除或一般呈現接管後，舊 ACK 不另 GET、不覆寫成功通知、不整頁重畫或回焦。已確認刪除只保留至本次在途作業／交接及相關有效讀取消化；當前唯一模型及唯一列可原地移除，保留同一 subs 陣列、其他列／按鈕、通知與頁面外殼，按原公式更新摘要、時間線、卡片提示與分析。全空可換既有空狀態但保留仍適用頁首與歷史，不由晚確認補發焦點。身分不唯一或局部同步失敗須留明確重載入口，不猜列、吞錯或自動由舊 ACK 發新讀取。

確認前已開始的實際有效 GET 回合排除期間確認的刪除，於 autoExpire 前及其 await 後消化；確認後才發出的新 GET（含校正遞迴的新回合）接手，不繼承永久 ID 遮罩。已 ACK、自有 GET 等待時遭下一操作接管，即使該操作失敗也須消化刪除。標記確認只合併存活列，不插回已刪列；不回溯取消已發校正寫入，也不新增歷史／freeze 補寫、跨種類佇列或通用一致性承諾。範圍及驗證狀態見[刪除施工計畫](../subscriptions-delete-focus-plan.md)，原生量測與真 DOM 競態證據分開記錄。

**銀行收支連續選年月**：年月事件在同步段讀同組另一個 select 的當下值，避免前次 GET 未完成時沿用 render 閉包的舊配對。年份事件仍依該年可用月份保留原月或回退清單首月，完整讀取後仍沿既有 fallbackMonth；沒有目標月份或空資料時不承諾永遠維持中途選值。兩組既有控制項各讀自己配對，原 render／route guard、失敗恢復、金流與排序保持；不增加帳本寫入或手機版面改動。正式行為題與有限原生射程見[年月選擇計畫](../cashflow-period-selection-plan.md)。

**銀行收支重讀失敗**：`public/modules/cashflow.js` 在五個列表資料 GET 全部成功後，私有保留一份實際工作區節點、年月、金流、排序與讀取開始時的修訂。同次進頁的頁內讀取或同頁 `router()` 先清空再讀取失敗，可恢復相符的成功列表與摘要；真換頁、快速離開再返回、完整 hash／nav／host 身分失效則不復活前次節點。節點已移到其他容器時不能取回；較慢舊成功／失敗不得覆蓋新版、條件或提示。等待中的 router 載入畫面照舊，不承諾節點從未脫離或焦點從未中斷。

提示放在標題下、列表上方：確認匯入後 GET 失敗，有同次成功列表用「資料已儲存，畫面尚未更新」，無成功列表用「資料已匯入，暫時無法載入列表」；一般重畫失敗則分別用「畫面暫時無法更新，以下是上次成功載入的內容」及「暫時無法載入銀行收支」。無列表不能把錯誤畫成成功零筆。沒有合格快照的失敗及同頁router清空後恢復的失敗，其必要提示與重試不受桌機隱藏限定；同一失敗工作區後續重試、在途確認或pending更新只能保持或提升可見性。有效成功讀取建立新工作區後不繼承前次提升；新的普通頁內失敗仍用原桌機橫幅及toast。既有手動表單成功提示與不完整回音的優先順序保留，錯誤詳情仍過 `esc`。四態定案見[本人留痕](https://github.com/teacherjung/personal-finance-webapp/pull/698#issuecomment-6228743934)，限定可見性修復依[技術裁示](https://github.com/teacherjung/personal-finance-webapp/pull/700#issuecomment-6233474503)，不改手機排列、共用樣式、版位或焦點。

「重新讀取」只讀既有資料端點，不保存或重送表單／匯入 callback、票、檔案或密碼。入口核對目前工作區、提示、按鈕身分及頁面／讀取世代；脫離、替代或在途重試不多發讀取。一般篩選讀取失敗回復成功快照的條件；讀取開始時已涵蓋確認修訂的成功結果，才清待更新事實。已送出後跨頁的手動或匯入確認，先記修訂；目前已返回銀行收支且有落後列表時只補提示與唯讀重試，不自動重讀、改篩選或動新窗；無本次列表時由最新讀取與確認事實呈現。單筆與匯入批次刪除依下段另列；其他頁刪除、跨視窗與外部寫入不在此保護範圍。機制與邊界見[第二階段計畫](../cashflow-recovery-phase2-plan.md)。

**銀行單筆刪除恢復**：單筆列入口在模組私有續行使用原生確認與原 DELETE 端點，確認句及金流／金額格式保持；單筆路徑不改共用 `confirmDelete`；批次管理依下段另列。確認返回前後核對原工作區、列與按鈕實體、完整頁面／讀取世代及唯讀彈窗世代；同 id 在確認及請求在途防重，資料 id 不唯一時不猜列。只有正常回應且 `ok === true` 才先遞增本模組修訂、記刪除修訂及同 id 確認，再判是否可通知及自動重讀；換頁、較新作業／讀取或新窗接管不抹確認，也不取得舊續行的呈現資格。失敗或異常回音不冒稱已刪或必定未刪，不自動重送或回滾；後續 GET 失敗不退回刪除失敗路徑。

未涵蓋確認時，有成功列表提示「資料已刪除，畫面尚未更新」，無可用列表提示「資料已刪除，暫時無法載入列表」；既有不完整欄位回音優先，其次刪除，再沿原匯入／普通儲存提示。後續普通寫入或匯入不洗掉未涵蓋刪除。舊列表仍出現已確認同 id 時不再 DELETE，其他 id 不被全頁鎖住；「重新讀取」沿原 GET-only 與回焦契約。有效完整成功 GET 的開始修訂涵蓋確認後，才清待更新事實及已涵蓋同 id 紀錄；斷開或替代的舊控制項不能因紀錄清理而復活。舊編輯表單沿原修訂拒絕整筆 PUT，不升級未存欄位。本人定案、技術裁示、合成／原生證據及未涵蓋邊界見[單筆刪除計畫](../cashflow-delete-recovery-plan.md)；不新增刪除回焦、手機樣式、外部寫入或全站刪除保證。

**銀行批次刪除恢復**：`cashflow.js` 以模組私有續行處理原生確認與原POST，不透過共用確認函式綁定後續GET／router；完整確認句與批次名稱口徑保持。`ok === true` 才記刪除確認；非負安全整數的removed才進筆數通知，異常筆數不撤銷確認或猜數字。已送出卻未取得嚴格確認，另記需重新確認修訂，主列表與批次窗說明「刪除結果尚未確認，請重新讀取後確認資料」，不追認已刪、不自動重送或回滾。確認／未知結果先推進修訂，使舊表單失效，再判通知與呈現資格；不完整欄位回音仍優先，其次未知刪除、確認刪除，再沿匯入／普通儲存提示。

主列表與批次清單分開記讀取開始修訂及提交代次，一邊成功不能替另一邊清pending；確認前啟動的回覆不冒稱已涵蓋。主列表沿既有兩態刪除提示及五端點「重新讀取」；批次窗保留舊表與「資料已刪除，匯入紀錄尚未更新」，「重新讀取匯入紀錄」只GET batches。錯誤仍esc，讀取失敗／不完整批次身分不畫成成功零批次。最新有效且涵蓋必要事實的空批次GET，才關自己的原窗。正常後續讀取各自收尾，一域失敗不阻斷另一域，也不退回POST重送。

初開批次GET核原按鈕／工作區、完整hash／nav／host、唯讀彈窗世代與開窗序號；窗內核自己的root／dialog／內容及讀取代次，只更新原內容，不延後重開shell或直接清root。換頁、關窗、新窗即使開後關閉，舊續行不得接管；同頁主列表背景重畫不撤銷有效原批次窗，仍可手動關閉跨頁的舊窗。批次與單筆的已接受刪除共用呈現序號，較舊ACK只記事實，不另起舊通知／讀取。

同batchId在原生確認及POST在途防重；已確認／待確認而讀取未涵蓋的舊批次控制項不重送，舊主列表的同source／importBatch也不能改走單筆DELETE繞過。不同批次不設全頁寫入鎖；取得有效新批次清單後可按新資料重新確認，不永久封鎖id。Map只留必要身分／修訂及兩域覆蓋狀態，清理不代清另一域；斷開或替代的舊控制項即使紀錄已清也不能復活。原重試回焦與舊編輯PUT防覆寫保持，原後端連帶刪除範圍、餘額及金額公式不變。產品推薦依本人自動代選授權採用，非本人實看；技術、回歸／原生射程及暫行Grok複審／跳掃見[本項計畫](../cashflow-batch-delete-recovery-plan.md)。其他頁與外部寫入、手機及全UI7不在本項。

**銀行預覽續行**：延後綁定、勾選及 apply callback 只認原預覽節點、原控制項及 `watchModalRoot()` 唯讀世代，不能借新窗同名 ID。apply 成功確認先遞增本模組修訂，再判原頁與原窗；離頁或換窗不撤銷確認。原窗仍有效才走它的既有關閉入口；新窗接管或曾開過再關閉，舊續行不清 root、不解鎖新鈕或寫入它的輸入與提示。確認後讀取與 apply 的 catch 分開，GET 失敗不能讓同張確認可重送；有效同頁的背景讀取不以原窗是否仍開著為條件。

**銀行重試回焦**：只有目前工作區的原「重新讀取」鈕確實持焦、入口及讀取資格均有效，才建立模組私有一次性焦點工作。原鈕停用前，在明確的同步scope內先呼叫原鈕blur；返回後核實已釋焦及原工作仍有效，不因單見BODY而認領。blur的同步事件可開新讀取、換頁或替換入口，故停用與發GET前重核原state、notice、button、generation、route／nav／hash及在途讀取；只取消焦點而未失去原讀取資格時仍完成原GET，不能重送寫入。

只在本次最新有效GET的最終DOM及提示接妥後嘗試一次：唯一且可用的重試鈕優先；成功且提示消失（含空列表）才回本工作區可見的「銀行收支」h1。候選重複、不可見、停用、inert或拒焦時停止，不猜導航或手機標題。h1原先無tabindex才暫加-1，失敗、離焦或移除後僅還原自己的值；既有或外改值保持。

原鈕scope外blur、建立後的鍵盤／指標／觸控／滾輪、外部focusin、真正window失焦、文件隱藏、換頁、較新render、新窗世代或入口／工作區失效會撤銷；新窗開後又關或節點移除再放回均不復活。自己的釋焦／停用與最終DOM提交使用分開的窄同步scope，不能吞等待中延後blur；最終提交前先核待處理的外部移除紀錄。等待中寫入確認重建提示直接取消焦點，不追中途新鈕；合法GET、修訂及必要提示仍完成。focus事件重入接管後停止，工作完成／取消收掉自己的監聽及觀察器。本人定案與技術時序補正見[施工計畫](../cashflow-retry-focus-plan.md)，真DOM及受控延後事件題在既有重讀卷；原生與跨瀏覽器射程分開記錄。

**舊快照編輯**：手動表單、銀行 apply 或單筆刪除收到確認回應後，以較舊列表快照開啟的編輯表單不得再送出整筆資料。這包括確認到達前已開啟的表單；列表成功重讀也不會更新它的欄位，須關閉並從新列表重新開啟。送出時比對該列表讀取開始時的修訂與本模組確認修訂，拒絕時不發出 PUT。此保護只管同一個前端工作階段；不宣稱處理其他視窗或外部寫入的並行衝突。非預設控制狀態、寫入與重試次數、提示清除、舊表單送出及競態由 `test/cashflow-reload.test.js` 驗證。

**編輯未改欄位保存**：普通編輯以本窗 onMount 完成選項初始化後的固定 primitive 值為基準；文字與選項用實際字串，數字空字串為 null、其餘 Number(raw)。日期、帳戶、金額、摘要、備註各自只送相對基準改變的值，清空仍須送出；缺席欄位、後備文字與預設選項未改就不回填。金流／分類／子分類視一組，任一改動完整提交該組，全未改則整組省略；嚴格 true 的 applyAll 且有銀行學習鍵也強制提交整組，同一次 PUT 完成既有學習與傳播。相同摘要／備註套用只對各自已改文字送旗標。新增仍用完整 payload；無變更編輯可送空 patch。基準不可因可變交易列、送出或重試改寫；基準或本窗身分無法確認時不發 PUT並保留輸入。改過再回同值算未改，明確改同欄或同分類組仍採既有後寫語意；本段保護未改欄位，不是跨視窗版本衝突偵測。上段同工作階段拒收及下段回音確認仍適用，回音只核本次送出的文字。驗證範圍見[保存計畫](../cashflow-edit-preservation-plan.md)。

**回應與確認分開**：PUT／POST 回應經同一登記使舊快照失效；PUT 在登記後才核對摘要／備註回音。回音不符保留原錯誤與表單輸入，工作區提供「部分欄位尚未確認儲存，請重新讀取後確認資料」及唯讀恢復，不沿用完整成功的「資料已儲存」提示、不重送或回滾。後續另一筆完整成功，也不能蓋過尚未被有效重讀涵蓋的不完整結果。成功讀取以開始時的修訂判定，不能從回傳列看起來已新推論涵蓋所有回應。

**換頁表單失效**：手動表單在真正換頁後不得再發出新的 PUT／POST；保留輸入、取消／關閉入口，當下說明須關閉、回銀行收支重讀確認並重新開啟。已送出的請求不取消、不重送，後續結果只依目前工作區的修訂規則提示，不恢復舊 owns、不放寬共用 catch。處理綁定原表單身分，已關閉或被新窗替代的表單不得操作新窗；同頁背景重畫不算換頁。

⚠️⚠️ **兩個序號不可混用（r9 用兩個真實 bug 換來的）**：`currentRouteSeq()`＝**重繪世代**，`router()` 每跑一次就前進（含同一頁重繪），用途是「我算完的東西還該不該寫進 `#view`」；`currentNavSeq()`＝**換頁世代**，只有**使用者眼前的網址（完整 hash）**改變才前進，用途是「使用者還在同一頁嗎」。⚠️ 鑰匙用完整 hash 而不是去掉 query 的 route：個股研究頁的身分本來就含 query（`#stock?symbol=AAPL&tab=…`），只比 route 的話「從 AAPL 上一頁跳到 GOOGL」不算換頁，AAPL 表單的舊 continuation 會在 GOOGL 畫面上關窗／報錯（Codex r10 抓到）。用完整 hash 反而更單純：背景重繪不會動到網址，原本要防的「同頁重繪不可誤判成換頁」照樣成立。`router()` 的呼叫點裡**只有 hashchange 是真換頁**（刻意不寫死有幾個——鐵則 10）——開機報價更新／自動快照／帳戶改名對齊／店名規則整理／刪除後重繪都在**同一頁**呼叫它，而 `router()` **根本不碰 `#modal-root`**（彈窗還在畫面上）。拿重繪序號當「換頁」用會出兩種事：①彈窗擁有權被誤撤 → **存檔成功卻不關窗、儲存鈕永遠灰**（r7 自己種的）；②匯入流程 `onPage` 變 false → **密碼窗靜靜不開**，使用者上傳完加密帳單什麼都沒發生（P0.5 頭號功能）。所以彈窗擁有權、匯入流程的 `onPage`／`bankUploadGate`／`runCardUpload`、設定頁的「全部清除帳單密碼」一律吃 `currentNavSeq`；各頁 renderer 寫 DOM 前的自主體檢維持 `currentRouteSeq`。**逐點判準**：這一行問的是「該不該寫進 `#view`」（留 `routeSeq`）還是「使用者還在不在這一頁」（用 `navSeq`）；兩者混在同一個函式裡時要拆開。⚠️ **誠實劃界**：`assets.js`／`cards.js`／`insurance.js`／`portfolio.js`／`securities.js`／`subscriptions.js` 還有一批「問還在不在原頁卻用 `routeSeq`」的既有消費點（origin/main 就有、非 P0.5 種的），列在候選 8-17，本契約不保證它們。

**開窗前後還有 await 的兩種情況，各有專用把手（r16／r18，都是實際踩到的產線競態）**：
- **開窗之前**還要等（先問 `/api/mode` 再開密碼窗、先載卡片名單再開上傳窗）→ 用**唯讀**的 `watchModalRoot()`：只回報「從我看的那一刻起沒人接管／撤銷這一格、也沒換頁」。⚠️ 這裡**不可**用 `claimModalRoot()`——那會把當下開著的那個窗的擁有權**搶走**，它之後連自己都關不掉（＝r7 那顆「存檔成功卻不關窗、儲存鈕永遠灰」）。
- **送出之後**再開下一窗（密碼窗送出→等 preview→開預覽窗）→ 用 `onSubmit(out, ctx)` 拿到的 `ctx.owns.handoff()`。⚠️ 這裡**不可**用 `owns()` 或 `watchModalRoot()`：正常交接本來就會蓋兩次章（自己 `close` 時 `release`、下一窗 `claim`），用那兩個判會把**正常流程整個誤擋**。`handoff()` 只放行**兩種**狀態：①還是我的（還沒關，例如剛在 `onSubmit` 裡排程）②就是我**送出成功那次**關窗之後的章。其餘一律擋：**使用者按 ×／取消／背景關窗＝撤銷不是交接**（r20：他都把窗關掉了，在途 preview 回來還彈下一窗＝把他剛丟掉的東西又推回他面前）、章比那更新＝別人接管了、以及我根本沒 `release` 成功（早被搶走）。所以 `openForm` 的兩種關窗**必須分開**：`close`（使用者撤銷）走 `owns.release()`、`closeAfterSubmit`（送出成功）走 `owns.release({ handoff: true })`；`release` 的 `handoff` **預設 false**＝沒指名就當撤銷（保守預設：新呼叫端忘了指名時，寧可少開一個窗）。判準寫在 `modal-ownership.js`（純邏輯有考題）。**P0.5 的排窗點**（新增一個就照同款接）一律組成 `canOpenNext = () => onPage() && ctx.owns.handoff()` 再交給 `openWhenOnPage`；⚠️ **誠實劃界**：`securities.js` 的預覽窗與 `transactions-import.js` 整批改卡後的管理窗是 `origin/main` 就有的同型排窗點、**還沒接**（候選 8-16）。

規則：**任何直接把 `modal-bg` 外殼寫進 `#modal-root` 的開窗點，都要在那次寫入之前 `claimModalRoot()`**（中央外殼 `app.js` 的 `openForm`／`openInfo`、`modal-shell.js` 的 `openModalShell` 內部已 claim；手刻的 `assets.js` 再平衡／目標配置、`settings-store-rules.js` 規則預覽也各自 claim）；**關窗即 `owns.release()`**——`release` 是**有主才撤**，舊窗的 close 若已不是主人就不准蓋章，否則會把後開那個窗的擁有權一起洗掉；`openForm` 的 async `onSubmit` 只在 `owns()` 為真時才 `close()`／`toast`。純邏輯在 `public/modules/modal-ownership.js`（`makeModalOwnership`，零依賴可測），考題＝`test/modal-ownership.test.js`（世代／有主才撤／**同頁重繪不撤銷、真換頁才失效**行為題＋接線形狀題＋**關門題**）。關門題的掃法是四輪審查改出來的，**它守得住什麼、守不住什麼要照實說**（誇大比缺口更糟）：**守得住**＝①**開窗寫入點的總數被釘住**（`EXPECTED_OPEN_WRITES`）——**偵測面內**不管新開窗點寫成哪種形狀（頂層函式／箭頭／物件方法／class 方法／巢狀）、用哪種引號、用 `innerHTML` 或 `insertAdjacentHTML`，多一個就轉紅，逼人來登記並補 claim；⚠️ **偵測面＝原始碼裡直接看得到 `class=…modal-bg`**，動態組字串（`'modal-' + 'bg'`）、用變數帶 class 名、`className` 指派、或 `public/` 以外開的窗**都在偵測面外**（r16）；②點名表上**每一個**開窗點的「claim 在寫入之前」（名字錨定，改名或拿掉 claim 都會紅——r10：否則 `openInfo` 的 claim 會被 `openForm` 代打）；③頂層函式與**頂層箭頭函式**的新開窗點（r12）。**守不住（已知盲點，r14 實測）**＝段落只依**頂層**大括號深度切，所以物件字面值／class 裡的兩個方法、或同一外層函式裡的兩個巢狀函式會共用一段，前一個的 claim 會替後一個未 claim 的開窗背書（attribution 會錯，但**總數那題仍會先轉紅**）。真正的解法是 AST 依函式節點掃、或把 `#modal-root` 收斂成唯一寫入 API＝**候選 8-16**；在那之前**不可**宣稱「逐函式切段」這種撐不住的保證。掃描器本身也有考題（合成原始碼直測），並在深度收不平時**大聲失敗**——它是保證的承重點，假綠的話上面兩題都守不到東西。⚠️ **誠實劃界**：手刻彈窗裡「await 回來才動 UI」的 continuation 尚未驗擁有權（候選 8-16），那是 origin/main 就有的既存缺陷，不在本契約保證範圍。

**鍵盤與焦點（2026-09-29）**：六個既有開窗點都要呼叫 `bindModalAccessibility(root, fallbackClose, returnFocusTo, closeLabel?)`。它只負責共用互動：補 `role="dialog"`、`aria-modal` 與標題關聯；× 預設讀成「關閉」，實際是返回的窗必須用 `closeLabel` 明確寫出返回語意；初始焦點**只認開窗者明確標記**的 `[autofocus]` 或 `[data-modal-initial]`（前者優先），都沒有就聚焦 dialog 本體，預設由 `.modal:focus` 提供品牌橘色外框（銀行收支的收入、支出、內轉說明窗例外，見 [UI 現行慣例](../ui-conventions.md)）——不可再從 input／select／textarea／按鈕／連結的種類或 DOM 順序猜「主要」目標。`openForm` 產生的每個真正編輯欄位都帶 `data-modal-initial`，所以仍會聚焦第一個可見欄位；送出／取消鈕不帶標記。資訊、預覽與手刻窗若沒有明確標記，就停在 dialog，動作列的勾選框或按鈕不會因為排在前面而吃到初始焦點。在 document 層把 Tab／Shift+Tab 收在仍連線的窗內（包含焦點落在 dialog 本體或意外跑到背景的情況）；非輸入法組字中的 Esc 會啟用**按下當下**的 `.x-close`，沒有 × 才走 `fallbackClose`。因此手刻窗要先接好 ×；`openModalShell` 的呼叫端可在外殼回傳後覆寫 ×，Esc 會跟著最新的取消／返回語意，不會繞過等待中的 Promise。真的關空 `#modal-root` 後，延後回焦工作須核對所屬彈窗代次；使用者已有有效焦點時不搶回。原入口仍連線、可見、非停用、非 inert 且能接焦點時優先；否則選當下 `#view` 內第一個可用的 h1，再退到 `#nav [aria-current="page"]`，均不可用就不猜其他操作。標題原本沒有 tabindex 時暫加 -1，聚焦失敗立即移除，離焦時僅移除仍為 -1 的暫加值；既有屬性保持。另一個彈窗直接接管同一 root 時，舊窗不回焦，原入口記錄留給接管鏈；新窗即使已開過且關空，舊回焦工作仍須作廢。`openModalShell` 的 close 只清除同一 dialog 身分，舊回呼不得清掉新窗或未儲存輸入；跨頁後仍可手動關閉目前窗。初次回焦成功後，同頁非同步重畫移除該目標時，只允許一次按標題／導航退路補償；不連鎖追焦，不等待網路或猜延遲。補償資格在列舉的輸入、外部焦點、視窗／可見性、換頁、新窗及 root 失效時撤銷；每次 focus 後及候選之間重核身分與有效外部焦點，過期觀察不得接管新記錄。暫加屬性在真正離焦或移除後還原，不因只撤銷補償而提早移除仍持焦節點的屬性。精確事件、重入與一次性界線依[本支技術裁示](https://github.com/teacherjung/personal-finance-webapp/pull/694#issuecomment-6220249789)。回焦節點自身 blur 的分類延後一個微任務；仍連線且不持焦才取消，已移除交原觀察器。沒有其他接管訊號的同回合「主動 blur 再同步移除」亦採一次補償，不能區分為主動讓焦；其他解除條件立即生效，依[時序補正裁示](https://github.com/teacherjung/personal-finance-webapp/pull/694#issuecomment-6220346277)。送出、背景點擊、返回與世代擁有權仍由各功能原本的程式負責，不得藉這個 helper 偷換語意。手機導覽只在完整 hash 真的改變時把目前頁捲進可視範圍；同頁資料重畫不得搶走使用者手動捲動的位置。考題在 `test/modal-ownership.test.js`：真 DOM 行為題（含真正的 `openModalShell` 覆寫 × 後按 Esc）加上六個開窗點逐一接線題。

**資產目標配置的儲存接續**（共用彈窗生命週期在此保存入口的具體套用）

目標配置送出前與保存回應後，核對原彈窗節點、擁有權及完整網址；過期成功／失敗不清窗、不通知、不另起頁面重讀。正常成功仍提示、關窗及重讀；正常失敗仍留輸入、解鎖及提示，重試會撤銷上一輪重讀的呈現資格。手動關窗只核對節點，原窗跨頁後仍能關閉，舊 close 不清新窗。

保存後的重讀除了既有重繪世代，還須在動 DOM／圖表前核對操作資格；成功關窗後用唯讀觀察戳接棒，期間新窗即使開過又關掉也作廢。重讀失敗獨立處理，只有仍有效的原操作可提示畫面更新失敗，不把成功保存說成寫入失敗。此範圍不包含其他手刻窗，亦不保護原窗按儲存後才追加的編輯；關窗／換頁不撤回已送出的保存，傳輸失敗不能推定後端沒寫入。驗證範圍與證據見[施工計畫](../asset-target-save-plan.md)。

**信用卡匯入預覽的保存接續**

`transactions-import.js` 的帳單預覽以整個預覽實例保有在途鎖；匯入及改卡重解析互斥，等待期間不排序重繪，取消／×／Esc 仍可關閉。每次重繪的事件綁定原彈窗節點與觀察戳，入口及回應核對換頁世代、完整 hash 與原預覽資格。改卡失敗保留原卡與原編輯；有效的匯入失敗可重試。匯入成功後原預覽終止保存，即使列表刷新失敗也不重新送出。

有效成功同步交棒完成窗或關窗後，另取唯讀觀察戳保護列表刷新。本次完成窗的完成／×／Esc 正常關閉，僅在關閉前資格有效且原 dialog 相符、原 close 後關空時同步延續觀察；不得讓失效資格藉舊關閉事件復活。換頁後原完成窗仍可關閉，但不恢復刷新。`renderTransactions(canCommit)` 在發 GET／推進重繪世代之前，以及成功或失敗更動頁面、月份、排序或提示之前核對額外資格；未傳參數的列表操作維持既有行為。期間換頁或新窗開過又關，舊刷新不提交。重讀錯誤不冒充匯入失敗。

從本次完成窗進入改卡時，載卡在途防重，回應核原完成窗、觀察戳及完整 hash／nav；取消自己的有效改卡窗後另起受資格保護的列表讀取，原匯入 GET 不復活。取消、×、Esc 與背景按下／放開均在背景的手勢同路，拖出不關。新取消刷新遇換窗、開後關空、導航或較新 render 仍作廢。成功改卡的排程與執行核表單 handoff 及同頁資格；過期接續不關窗、不通知、不重畫。跨頁後原改卡窗仍可手動關閉，但不刷新。

此項不改解析、金額、分類、去重、AI 同意或後端帳務判準；其他批次管理入口不在此範圍。關窗／換頁不撤回已送出的保存或改卡，取消後的新 GET 也不保證涵蓋較晚完成的改卡；傳輸失敗不代表後端未寫入。不保證保存按下後追加的編輯，也不提供跨預覽或跨分頁冪等性。驗證範圍及待完成證據見[施工計畫](../credit-import-save-plan.md)。

**證券匯入紀錄的批次接續**

`securities.js` 的批次初載以唯讀彈窗觀察戳、完整 hash／nav 及開啟代次核對成功與失敗；較新開啟失敗不讓舊開啟復活。刪除前核原窗、原列、唯一台新批次與確認前後資格，同批次在途鎖跨表格更新；已接受的另一批次不因舊列被重畫而撤銷。有效成功只更新原窗表格，主頁重讀獨立核同頁資格與最新讀取代次。過期回應不另開窗、不通知、不啟動重讀；關窗或換頁不撤回已送出刪除。

確認成功須有嚴格成功值及相符批次身分，異常筆數不猜數字。未知結果不能推定後端沒刪，不自動重送；仍有效時提示未確認並各自唯讀重讀批次與主頁，不冒稱刪除成功。舊快照不能再次刪除該批次，按鈕停用與此資格一致；有效新批次快照可恢復操作，不以主頁讀取成功為前提。確認或未知結果先推進私有修訂，批次與主頁分別以讀取開始修訂拒收過期快照；兩域各自確認覆蓋，不由一域成功代替另一域。讀回快照不保證原請求已停止或不會較晚完成。仍有效但修訂過期的讀取，分別提示重開批次窗或主頁重試，不永久停在載入中。此項不改後端帳務、同步、上傳預覽或外觀，也不提供跨分頁冪等性；驗證證據與限制見[施工計畫](../securities-batch-lifecycle-plan.md)。

**設定頁管理入口的初次讀取**

支出分類、收入分類、版面規則卡、銀行收支學習、摘要與備註套用、內轉分類共用最後有效開啟意圖。入口先核原按鈕、設定頁完整 hash、導覽世代及頁面身分；卸載入口不發 GET，也不撤銷已接受意圖。等待期間唯讀觀察彈窗，不先搶占；成功與失敗續行核意圖、hash／nav、頁面及彈窗根身分與觀察戳。過期回應不開窗、不通知、不另起重讀，最新失敗不復活較早成功。

同頁背景重畫不撤銷已接受讀取，續行不要求舊按鈕仍連線；有效失敗保留原提示並可重新點擊重試。同步開窗取得自身所有權後的例外，不用開窗前觀察戳誤判為過期。各管理器端點、資料投影與外觀保持。此範圍只管初載到開窗，分類／內轉保存、管理器內刪除及其他設定流程不在本項保護內；驗證與限制見[施工計畫](../settings-manager-entry-plan.md)。

**銀行收支學習與摘要／備註套用的刪除**

兩窗各自序列化確認與刪除，原列必須仍屬原視窗，確認前後核 root／dialog、完整 hash、導覽與彈窗觀察資格。取消不寫入；在途同列或不同列不增加確認與 POST。成功只更新原窗表格，不重開外殼；舊列不可再次操作，連續刪除不復活較早列。銀行以 key、文字以 part 與 key 刪除，不回改舊交易。

晚成功與失敗不通知、不更新新窗、不追加讀取；關窗不撤銷後端已接受的刪除。同頁背景重畫不撤銷有效原窗。有效傳輸未知以既有唯讀端點核對，不自動再送刪除或冒稱成功；核對失敗顯示未同步並停用舊列，關閉後可由既有入口重新讀取。讀回只是快照，不保證原未知請求不會較晚完成。此範圍不含其他管理器、分類／內轉保存或跨分頁冪等性；驗證與限制見[施工計畫](../settings-manager-delete-plan.md)。

**支出與收入分類的保存**

共用分類編輯器保存前核原 dialog、root、控制項、完整 hash、導覽、彈窗觀察及較新管理意圖。在途序列化保存並凍結快照編輯，保留取消與關閉；後開視窗、較新入口（含等待或失敗）、換頁皆不得被舊成功或錯誤接管。同頁背景重畫不撤銷原窗，但分類保存的整頁重讀另核讀取代次與呈現身分。設定呈現後的編輯事件只記未存事實，不收集欄位值；未存輸入阻止本分類保存的自動整頁重畫。

POST 與成功後的 GET 錯誤分開。共用 API 缺乏可靠狀態分類時，POST rejection 保留原輸入及舊保存鎖，不假報寫入狀態、不自動重送或 GET；使用者關閉後經既有入口重新讀取核對。即使 HTTP 400 也需重開是本支明列退讓，關窗草稿不自動帶入新窗，可能需重新編輯；未送 POST 的前端驗證仍可原窗修正。讀回快照不能證明原請求已停止。端點、payload 與後端分類連動不變；內轉、其他設定保存、跨分頁及整樹寫入衝突不在此範圍，驗證與限制見[施工計畫](../settings-category-save-plan.md)。

**記得同步這裡**：`server.js` 只在 LOCAL 初始化 `lib/local-index.js` 的單檔投影，再沿現成靜態供應器供應；未命中落回原 public。共享 `public/index.html` 保持，唯一完整 foot-note 只將 code 的固定檔名換成通用 SQLite 文字，其餘位元組、節點與按鈕保持。投影不接收定位、不開庫，不新增模式或資料位置 API。原來源接受的根、index、query、編碼、斜線與大小寫入口須仍取得新版表示，原負例保持；不加 SPA fallback 或全 URL 小寫。GET／HEAD、投影表示的條件式快取與單一 bytes Range 由原靜態供應器處理，切片／長度以 UTF-8 Buffer 核對。其他資產與 HOSTED 原身分牆、內容及入口保持。

派生目錄僅含公有 index，啟動時建立完整表示；目標缺失／重複或初始化失敗不得靜默回舊文字，已取得的自身產物立即盡力清理，原錯保留。成功後 exit 同步盡力清理，只用自身目錄歸屬；不接管信號、listen 或 close，不掃他人／舊前綴目錄。信號、強制退出、崩潰及清理失敗可能殘留不含帳本或定位的公有產物；不承諾任意退出零殘留。正常重啟依來源重建，不提供來源熱更新保證。`test/local-index.test.js` 與 `test/helpers/local-index-case.js` 驗真 HTTP、有限入口、Buffer 協定及生命週期；`test/hosted-auth.test.js` 驗離線 HOSTED 保存。各已測環境以自身原來源為基線，異質掛載未覆蓋；如實測不相容須修正，不以未測聲明遮蔽。原生桌機與有效突變證據另見[施工計畫](../local-store-guidance-plan.md)。
