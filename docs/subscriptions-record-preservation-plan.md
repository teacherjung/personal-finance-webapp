# 訂閱記帳入口的操作與保存驗證

## 目的與來源

承接原第 24 項的「記一筆到銀行收支」入口，依 [GPT‑6.1 Sol／xhigh 完整裁示](https://github.com/teacherjung/personal-finance-webapp/pull/724#issuecomment-6284510835)及[標準配對](https://github.com/teacherjung/personal-finance-webapp/pull/724#issuecomment-6284511285)，在前支完成合併與乾淨交接後補有限直接覆蓋。這是既有操作的保存驗證，不預先認定產品缺陷。

## 有限範圍

- 真正 app 開機、訂閱 renderer、列表按鈕及處理函式；使用中、即將停用、已停用列表各驗取消、單次成功與明確失敗。
- 每題以獨立子程序、專屬合成 LOCAL 帳本與新哨兵開始；成功走真正 HTTP CRUD，另從 HTTP 回讀交易與訂閱。確認窗接受／取消、開機維護及歷史圖資料使用明示合成邊界；不算原生確認窗、鍵盤或版面驗收。
- POST payload 與落庫欄位用獨立列明的預期核對，不從受測回應反算。取消零 POST；單次接受一個 POST；成功新增一筆預期交易且保留原交易及訂閱；明確失敗不新增交易、不顯示成功回音。
- 真 DOM 比對原頁殼、列、按鈕、通知、圖表實例及焦點。等待回應時，另驗外部移焦、實際切頁與新表單接管；成功與失敗均不得取代接管後內容或搶回焦點。原有 toast 自行新增的語意保持，不把新通知一概判成覆寫。
- 單次啟動的請求計數不代表重複啟動去重或完整並行一致性。

固定合成時鐘只隔離本題的日期及歷史月份，日期預期直接列明。本地 HTTP 只連本題動態 loopback 位址，前端與伺服端其他外部請求拒絕；不用真實帳本、帳號、密碼或券商能力。

## 保存反控與分流

先證基準綠，再在外置副本保留真正確認、POST 與完成續行，強制破壞頁面、通知、圖表、焦點或保存結果；目標 assertion 必須紅，還原後綠。替換前 assert 原文存在，語法／環境失敗不算有效反控，刪除受測操作也不算。

若取得產品反例，先帶實際輸入、請求、回讀與節點身分回交實際 Sol 裁定修法及必要路徑；不自行增加產品修改。沒有反例時只交付必要測試與本項範圍對帳，不改分類、金額、日期、週期、帳戶認定、後端、共用視窗、同步或排程。

## 怎麼驗收

這支只補考題與文件，不改畫面。交付核對以直接考題、實際 HTTP 回讀、保存反控及正式程序為證，驗收級別以合併後工具結果為準。不要求使用者以真實財務資料重做合成案例，也不把推薦代選寫成本人實看。

## 有限驗證紀錄

本支直接題覆蓋上述三列表與接管矩陣；15 題以專屬合成庫通過。外置副本另作 10 組保存反控：頁殼、舊通知、連線圖表、外部焦點、新窗輸入、換頁後頁殼、落庫金額、既有交易、訂閱資料及失敗回覆後焦點。每組先綠、保留真正確認與 HTTP POST 完成後指定 assertion 紅、還原再綠；完成標記核對本題 nonce、狀態及請求次數。這些是有限工程證據，不表示所有欄位、所有競態或原生瀏覽器通過。

明確失敗由測試伺服器在真正 HTTP 入口回 503；用來核對失敗續行與不新增交易，沒有模擬 SQLite 寫入故障。成功另以真正 CRUD 寫入及 HTTP 回讀核對獨立預期欄位。正式 Grok、推送及當版 CI 收據保留於 [PR #725](https://github.com/teacherjung/personal-finance-webapp/pull/725)。
