# 銀行收支重讀失敗處理計畫

## 目的與授權

工程待辦第 6 與第 4 項一起處理：確認寫入成功但重讀失敗時，保留上次成功畫面，讓使用者知道畫面尚未更新並可唯讀重試；一般篩選讀取失敗須回復上次成功的年月、金流與排序。

技術範圍依 [GPT-6.1 Sol 代裁（Codex 轉述）](https://github.com/teacherjung/personal-finance-webapp/pull/679#issuecomment-6140043513)。實際提示畫面完成後由 William 看過定案，才送 Claude 正式複審。只處理本機桌機；不改金額公式、手機版面或 HOSTED。

另一個工作階段正在修改信用卡、共用樣式、收支契約與既有收支行為題；本支避開這些檔案。開工前查公開 PR 與本機修改清單，送審前再查一次。

## 行為

- PUT 或 POST 成功後重讀失敗：保留成功讀取過的列與摘要；桌機頁內持續顯示「資料已儲存，畫面尚未更新」，提供「重新讀取」。
- 重試只發出讀取，不重送 PUT／POST；有效且屬於目前頁面的成功重讀才能清掉提示。
- 一般篩選重讀失敗：回復上次成功的年月、金流與排序，保留舊畫面並持續顯示讀取失敗。
- 舊請求或已離開頁面的儲存／重試完成，不得蓋掉新畫面或錯誤狀態。
- 動態錯誤訊息以文字顯示，不當成 HTML。

## 驗證與復原

用每題獨立的合成資料，直接操作真表單及篩選控制項，核對讀寫次數、非預設控制狀態、成功清除、請求交錯與換頁結果。對各保護做有效突變，證明考題轉紅；另跑既有相鄰考題、三關及各路由 reload 檢查。不得以真實資料測試寫入。

復原是回復本支程式提交，沒有資料格式搬家。正式程序仍依共同入口；畫面尚未經 William 定案前保持草稿、不送正式複審。
