# 銀行收支重讀失敗處理計畫

## 目的與授權

工程待辦第 6 與第 4 項分階段處理：本支涵蓋「記一筆／編輯收支」表單，以及原頁工作區仍存在時的篩選與唯讀重試。表單確認寫入成功但頁內重讀失敗時，保留上次成功畫面，提示畫面尚未更新；一般篩選讀取失敗須回復上次成功的年月、金流與排序。

技術範圍依 [GPT-6.1 Sol 代裁（Codex 轉述）](https://github.com/teacherjung/personal-finance-webapp/pull/679#issuecomment-6140043513)。實際提示畫面完成後由 William 看過定案，才送 Claude 正式複審。只處理本機桌機；不改金額公式、手機版面或 HOSTED。

第一輪複審後，代裁者[明確修訂第一階段範圍](https://github.com/teacherjung/personal-finance-webapp/pull/689#issuecomment-6148552512)，並非原裁示本來就只限表單。匯入成功後的重讀提示、同頁 `router()` 重畫清除提示與舊畫面，仍屬原目標未完成的後續工作。另依[舊值覆寫修復裁示](https://github.com/teacherjung/personal-finance-webapp/pull/689#issuecomment-6148553105)，本支合併前須攔住較舊快照的編輯送出，新增限制的畫面再依 E10 定案。

第二輪複審後，[技術代裁明確修訂跨頁界線](https://github.com/teacherjung/personal-finance-webapp/pull/689#issuecomment-6150412614)：已返回銀行收支且列表尚未涵蓋確認寫入時，立即補同版提示及唯讀重試，不能等再次送出被擋才補救。只限本模組工作區狀態，不改後端並行架構；新增觸發情境的實際預覽仍交 William 定案。

## 行為

- 記一筆／編輯表單的 PUT 或 POST 成功後，原頁工作區仍存在時的重讀失敗：保留成功讀取過的列與摘要；桌機頁內持續顯示「資料已儲存，畫面尚未更新」，提供「重新讀取」。
- 頁內重試只發出讀取，不重送 PUT／POST；此流程須等讀取開始時已涵蓋確認修訂、且屬於目前頁面的成功重讀才清掉提示。匯入、刪除及同頁 `router()` 先清空工作區的路徑不在保護內，離頁也會移除提示。
- 手動寫入確認後，不得送出較舊列表快照的編輯資料；確認前已開啟的表單也須守。成功重讀不代表舊表單的欄位已更新，須關閉並從新列表重新開啟，再送出。只管同一前端工作階段的手動表單，不擴充後端並行架構。
- 一般篩選重讀失敗：回復上次成功的年月、金流與排序，保留舊畫面並持續顯示讀取失敗。
- 舊讀取與重試不得接管新畫面。表單開著離頁返回後才儲存，或寫入等待中離頁返回後才確認，若返回頁列表落後，只補持續提示與唯讀重試，保留目前列、摘要、篩選、讀取錯誤與彈窗，不自動重畫或重讀；停在其他頁不動它。返回頁在確認前開始的讀取成功晚回，也保留待更新提示。
- 動態錯誤訊息以文字顯示，不當成 HTML。

## 驗證與復原

用每題獨立的合成資料，直接操作真表單及篩選控制項，核對讀寫次數、非預設控制狀態、成功清除、請求交錯與換頁結果。另驗證合成金額 21,000 存成 35,000 後重讀失敗，再編輯摘要不得送回舊金額；重讀成功後的舊表單仍拒絕，新開表單可保留 35,000 儲存摘要。對各保護做有效突變，證明考題轉紅；另跑既有相鄰考題、三關及各路由 reload 檢查。不得以真實資料測試寫入。

返回情境以「先等待、後真正寫入」的假櫃檯驗證，不只延遲已寫入後的回應；另讓返回頁的舊快照讀取在確認後才回覆。保留舊跨頁考題的列表、篩選及所有權斷言，依本次明確修訂更新提示條件；重試後新表單可保存新值，舊表單仍拒絕。

復原是回復本支程式提交，沒有資料格式搬家。正式程序仍依共同入口；畫面尚未經 William 定案前保持草稿、不送正式複審。
