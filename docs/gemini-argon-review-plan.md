# Argon High 正式複審前置

## 目的與範圍

依 AGENTS.md 的 2026-10-24 本人指示，先讓正式複審明確使用 Argon High，再另支修正資產配置目標保存的過期畫面回應。本支不改產品畫面、金額、資料保存或交易能力，不恢復 Grok 掃描。

Google [模型文件](https://ai.google.dev/gemini-api/docs/models/gemini-4-argon/)列明官方識別值 `gemini-4-argon`；[遷移文件](https://ai.google.dev/gemini-api/docs/latest-model?hl=en)列出 low、medium、high，預設 medium。因此不能只改人讀名稱或依賴預設推理。

## 最小方案與停止條件

- 優先沿既有 Gemini 原生正式複審入口，保留官方備樹、F3 提示、基底規則、獨立測試與突變副本、完整回覆、當版結論核收及合併閘；不把舊網頁掃描重新命名為複審。
- 先以不含專案／私人資料的合成請求核對既有登入是否支援官方模型；不得新購服務、建立 API key 或啟用額外付費點數。實測前必須在真 Config 核實本輪 `billing.overageStrategy` 為 `never`；若上層設定覆蓋、資料缺失或任何核對失敗，請求前停止。不得修改全域帳號／付款設定。
- 在既有真 Config、每次主請求模型與 HIGH 的觀測外，補服務端回應的 `modelVersion` 觀測。CLI 統計可能以請求名稱補缺值，不能取代服務端模型證據；未知、缺失、錯誤或混用的主審模型不得採計。串流終態與失敗必須如實保存，不讀模型思考內容或認證參數來猜身分。
- 專案 reviewer 登記與入口固定值同步；掃描設定與歷史授權分開，不因複審升版啟動掃描。新舊請求及回應如何對帳、旁錄終態與驗收口徑先經技術核定，再實作。
- 若既有登入不提供 Argon、回應缺必要模型證據或 CLI 協定不相容，停在草稿並提出具體證據；不自動換模型、改用付費 API、削弱必過檢查或另造網頁通道。

## 驗證、獨立核收與回復

新增行為題先見紅；覆蓋合法 Argon/HIGH、舊模型與降級拒收、服務端模型缺失／錯誤、串流部分回應與失敗、用途與角色分離、設定被覆蓋及點數策略拒收。各保護分別以有效突變證明，再還原實跑綠；保留既有三關與同版 CI。

真模型合成驗證只證接線，不代表本支已正式複審。固定受審版本後由獨立 Gemini 進行正式複審，Codex 逐項核實發現與檢查證據；缺有效當版結論不得自放行。若接線本身無法供獨立核收，先回報必要的審查安排，不把 Codex 自審或合成樣本當作正式通過。

回復為回復本支提交，保留失敗的私有原始證據；回復不授權以舊模型完成本次指定 Argon 的審查。接線合併後才接資產配置保存保護，其他優化仍須先說明並取得同意。
