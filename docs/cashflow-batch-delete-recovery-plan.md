## 產品推薦：依本人授權代選

刪除取得嚴格成功確認後，主列表仍落後時沿用「資料已刪除，畫面尚未更新」；無成功列表沿用「資料已刪除，暫時無法載入列表」。主列表的「重新讀取」只讀既有五個資料端點。

批次窗尚未更新時保留舊批次表，提示「資料已刪除，匯入紀錄尚未更新」及「重新讀取匯入紀錄」。此重試只GET批次清單，不重送刪除；讀取失敗不能畫成成功零批次。最新有效批次GET成功且為空，才關閉仍屬自己的原批次窗；其餘成功只更新自己內容區，不反覆開shell。

已送出但未取得嚴格確認，用「刪除結果尚未確認，請重新讀取後確認資料」，不宣稱已刪或必定未刪，不自動重送或回滾。舊清單仍有已確認／待確認同批次時不再POST；新有效清單取得後，由使用者重新選擇及原生確認，不能自動執行原操作。較新視窗、換頁或讀取接管，不重開舊窗、清新root或插入過期通知；確認事實仍保存。

沿既有樣式與版位，不改手機排列或新增刪除回焦。原生確認完整外層句與 `bankBatchDeleteConfirmText(b)` 的名稱、金額／筆數口徑保持。

## 技術接法與雙域契約

批次非同步續行私有化，不再由共用 `confirmDelete` 包POST、GET與router；不改 `app.js` 或共用確認介面。只有 `ok === true` 取得刪除確認；`removed` 是非負安全整數才顯示「已刪除 N 筆，可重新上傳」。成功確認但筆數異常仍保存事實，使用不含筆數的說明，不猜測或顯示undefined。取消或入口失效等零請求情況不記結果。

確認先遞增模組修訂、記刪除及batchId，再判呈現、通知及重讀資格；送出後未知結果另記需重新確認修訂，使舊表單失效，不能冒用已確認刪除。主列表保留不完整欄位優先，其次未知刪除／確認刪除，再沿匯入及普通儲存；後來普通寫入不抹未涵蓋事實。

主列表與批次窗各有讀取開始修訂及提交代次，一邊成功不替另一邊清pending；確認前啟動的GET晚回不能冒稱已涵蓋。仍各自合格時啟動兩域正常讀取，各自收尾；一域失敗不阻止另一域合法讀取，也不退回POST失敗處理。

主列表核同次進頁、完整hash／nav／host、原工作區、generation與較新呈現；批次與單筆作業協調既有刪除呈現序號。批次窗核自己的root／dialog實體、唯讀彈窗世代、完整頁面身分及批次讀取代次；正常同頁背景重畫不撤銷有效原窗，真換頁不得發新刪除。初開GET在await前取唯讀彈窗及頁面／開窗請求代次，晚回再核，新窗接管時不開；失敗不能當空清單。窗內只更新自己的內容區並重綁控制項；關窗走自己的 `close()`，不用setTimeout重開或直接清root。

確認框前以私有Map防同步重入，同batchId在途鎖不得因換頁或關窗提早解除，不同批次不設全頁寫入佇列。已確認批次的舊主列表列也不能改走單筆DELETE繞過防重，依既有source／importBatch與修訂核對，不猜未知交易id；其他無關列仍可操作。既有舊編輯PUT防覆寫與重試回焦接管規則保留。

長期只留必要batchId／修訂，不保存POST callback、舊DOM或整份表單。清理只解除自己的作業；一域成功不能提前解除另一域舊控制項保護，也不永久禁止同batchId。完整清理與過期控制項邊界依完整技術裁示，不將本計畫摘要擴為全站並行框架。
