# 投資資料與文字防護施工計畫

## 目的與範圍

承接 PROJECT.md 的 GS-F01／GS-F02，依 AGENTS.md「理財優化續作」授權由 Codex 實作、Grok 正式複審；暫停掃描。只處理投資純函式的幣別聚合、分層查表與價格文字 HTML 邊界，不改布局、金額公式、資料庫或輸入規則。

## 基線證據

在合成子程序直接呼叫正式函式：`fxExposure` 收到 `currency:'__proto__'` 後會新增 `Object.prototype.stockTwd`；測完還原子程序原型。`buildPortfolioPageState` 收到 `layer:'toString'` 後分層值變字串，主表漏列該持股。合法分層配無事件的 `<b data-probe>TXT</b>` 幣別文字時，主表 HTML 原樣保留標記。這是函式／呈現邊界證據，不代表正常 schema 輸入可植入，不讀真實帳本。

## 修法邊界

依 [Sol 技術裁示](https://github.com/teacherjung/personal-finance-webapp/pull/741#issuecomment-6394316527)，四個既有模組同支最小修正。記憶體原型名稱 bucket 保留金額，不放寬資料庫拒收；分層查自有欄位仍保留有效值判斷。

- `portfolio-exposure.js` 的幣別聚合改用無原型容器；不改已算好的曝險數字或匯率判定。
- `portfolio-state.js` 分層聚合採無原型容器；state、tables、report 的分層只查自有欄位，未知值延用衛星層退路。
- `portfolio-tables.js` 主表／願望清單及 `portfolio-report.js` 的純價格文字在插入 HTML 前經既有跳脫器；格式器與數值運算保持。
- 不擴到其他聚合器、輸入驗證、估值與投資決策；無新模組或新服務。

## 驗證與交付

- 四份對應考題涵蓋原型鍵、未知／合法分層、每個價格出口、無事件標記、正常格式與來源保存。異常原型鍵測試避免污染其他考題。
- 新題先在舊實作重現，再修正；有效突變逐一拿掉防護，先斷言替換點存在，確認對應行為題變紅。
- 跑型別、格式與完整考題；以隔離合成資料和原生桌面 Chrome 驗主表、願望清單及列印內容，重載現行路由，禁止外部請求與真實帳本。
- 正式 Grok 複審及逐項獨立對帳後才轉正式、跑合併關卡；合併後工具驗證不冒稱本人實看。
