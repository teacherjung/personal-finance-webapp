# 發布前檢查清單（把一個私有倉庫轉成公開之前）

> ⚠️ **這張清單自己不准寫出任何實際值**：不寫機器名、不寫家目錄路徑、不寫信箱、不寫擁有者的個人狀況。
> 理由——**這張清單會跟著倉庫一起公開**。一張為了防洩漏而寫、自己卻把要防的東西抄一遍的清單，是最貴的那種錯。
> 要記某一筆的實際值，記在**不會公開的地方**（擁有者的私人紀錄、對話裡），這裡只寫「怎麼查」。

## 先搞清楚：轉公開會一起公開什麼

不是只有現在看得到的那些檔。**這四樣都會跟著公開**，而且是很多人忘記的：

1. **整個歷史**：每一顆提交的內容、訊息、作者名字與信箱。**曾經加進去又刪掉的檔案，還在歷史裡。**
2. **討論串**：issue、PR說明、每一則留言，含已關閉的。
3. **雲端檢查的紀錄**：跑過的日誌與它印出來的東西。
4. **分支與標籤**：沒刪乾淨的舊分支。

所以下面每一項，**查的範圍都要含歷史，不能只查現在的檔案**。

## 動手之前：先把要查的範圍抓齊

**沒有指定範圍的 `git log`，預設只沿著目前這一支的歷史走**，未合併的分支、只有標籤指得到的提交，統統查不到。所以先做兩件事：

1. `git fetch --all --tags --prune` — **依你的設定**抓取遠端分支與標籤。
2. 之後每一條歷史查詢都帶 `--all`（或自己明列要查的 ref）。

⚠️ **第 1 步不是「抓齊」的保證**，這一點要講準：
- `fetch --all` 的 `--all` 指的是**所有遠端**（而且會跳過設定成不參與的那些），**不是所有 ref**；實際抓到哪些 ref 由你的 fetch refspec 決定。
- `--tags` **不會**補齊任意命名空間底下的 ref（例如平台放 PR 用的那種）。
- 淺層複本**不會**因此被補完歷史。
- 實測：在只抓單一分支的複本上跑完這一行，**遠端另一支與平台的 PR ref 仍然沒有取得**。

所以第 1 步之後要**自己核對「我要查的那些 ref／歷史真的都在本機了嗎」**。

⚠️ **射程**：`--all` 只涵蓋**本機已經取得的 ref**。別人的複本、平台上已經刪掉但還在快取裡的東西、以及你沒抓到的，這些指令**都查不到**。

## 七項檢查

每一項寫三件事：查什麼、怎麼查、查到了怎麼辦。

### 1. 提交的作者信箱

- **查什麼**：有沒有**自動編出來的**信箱。沒有設過信箱時，版本控制會自己用「登入名＠電腦名」湊一個——那會洩漏你的登入名與電腦名。
- **怎麼查**：`git log --all --format='%ae' | sort | uniq -c | sort -rn`，逐一看每一種是不是你真的要公開的那個。順便看名字：`git log --all --format='%an' | sort -u`。
- **查到了怎麼辦**：先**止血**（設好倉庫層的信箱，往後不再產生），再由**裁示者決定**舊的要不要改。⚠️ 改舊的代價要講準：**被改的那幾顆、以及沿著親子關係重建的它們的後代，編號都會變**；在第一顆被改之前的祖先、還有沒被改到的旁支，編號不變。⚠️ 那些引用到舊編號的地方（別的倉庫、討論串）**仍然指著舊的那一顆、不會自動改指到新的**；至於**點下去還打不打得開，要看舊物件與舊引用有沒有被保留**（實測：把分支的指標移走之後，舊提交仍然讀得到）。⚠️ 而且**改掉不等於消失**：舊的物件可能還留在別人的複本、平台的快取、或舊的 PR 引用裡。所以這是裁示，不是實作者自己決定。

### 2. 擁有者的個人狀況（規矩 B5）

- **查什麼**：身體、健康、家庭、財務細節。⚠️ **最容易漏的不是引用他的原話，是替規矩寫「為什麼要有這一條」時順手把他的理由寫進去**。
- **怎麼查**：先列出這個專案會出現的那幾類詞（**列在不會公開的地方**），再**分三個面**各查一次——⚠️ 這三面是不同的東西，少查一面就是沒查到：
  - **工作樹（還沒提交的也算）**：`grep -rn '<詞>' .`
  - **歷史裡每一顆提交的檔案內容**：`git grep -n '<詞>' $(git rev-list --all)`（這是逐顆翻內容，慢但查得到；**不要用 `-S` 代替**，理由見下）
  - **提交訊息本身**：`git log --all --grep='<詞>'`
  ⚠️ **`git log -S` 不是全文搜尋**：它是看「某個字串在某次變更前後的出現次數有沒有變」來挑提交。所以它**不查工作樹**、**不查提交訊息**，而且**同一次變更裡把一個值換成另一個、次數沒變，它就挑不出來**。它的零命中**不能**當成「這個詞不存在」。

  ⚠️ **上面那三條自己也有邊界，先知道再用**（每一條都可能讓你「以為查過了」）：
  - **參數會爆**：`$(git rev-list --all)` 是把每一顆提交都展開成參數，歷史一大就會超過系統的參數長度上限、直接失敗（實測會得到「參數列太長」）。⇒ **分批或逐顆跑**；而且**只要有一批是失敗結束的，那一輪就不算查完**。
  - **子模組預設不查**：實測對只存在於子模組裡的詞，原查法**沒有命中**；要加上遞迴子模組的選項才查得到，而那也要那些子模組的物件真的在本機。⇒ 有子模組就**另外查一次**。
  - **二進位檔不是「跳過」而是「只說有、不給內容」**：實測會印「Binary file … matches」但不列出是哪一行。⇒ 命中二進位檔**等於還沒核對到實際值**，要另外處理。壓縮或其他編碼的內容同理。
  - **要在倉庫根目錄跑**；工作樹那條 `grep -rn` 會連**未追蹤與被忽略的檔**一起掃（這通常是好事），但也可能掃到版本控制自己的目錄——⚠️ **那不是歷史的解碼器**，掃到它不等於查過歷史。
  - **這三條的搜尋詞預設當成「規則式」解讀**（不是字面字串）。要查字面值（含 `.` `*` `?` 這類字元）就用各自的「固定字串」選項，或正確跳脫。單引號只擋 shell，擋不了這一層。
  討論串要另外查，那不在版本控制裡（見第 6 項）。
- **查到了怎麼辦**：⚠️ **講清楚一件事再動手**：已經公開過的東西，改掉不等於收得回來。而且**修正的方式本身可能是第二次洩漏**——如果你在公開的地方寫「某某內容曾經出現在哪一顆、哪個檔」，那等於指引別人去找。正確寫法是只說「曾有不應公開的資訊進入歷史，目前版本已移除，不保證既有副本已清除」，**不附任何版本編號、檔名或行號**。

### 3. 機器路徑與登入名

- **查什麼**：某一台電腦上的絕對路徑（家目錄底下那種）。它同時洩漏登入名與資料夾結構。
- **怎麼查**：對家目錄前綴的形狀（例如 `/Users/`、`/home/`、`C:\Users\`）照第 2 項那三個面各查一次（工作樹用 `grep -rn`、歷史內容用 `git grep -n '<前綴>' $(git rev-list --all)`、提交訊息用 `git log --all --grep`）。⚠️ **只看「最早引入那個前綴」的那一次變更不夠**——後來換進去的別的路徑不會因此被看到。**工具印出來、被人原樣貼進說明或留言的那一行最常中**。
- **查到了怎麼辦**：公開的地方一律遮蔽，並標明「個人路徑已遮蔽、其餘逐字」——**不要遮了還說整行逐字**。⚠️ 如果某個範本要求某一行「逐字照抄」，那個要求**不凌駕**這一條：逐字屬實與可以公開是兩件事。

### 4. 站外私人產物的網址

- **查什麼**：只有你進得去的那種連結（私人文件、私人報告、雲端硬碟）。網址本身就是識別碼。
- **怎麼查**：對工作樹與歷史查 `https://` 開頭的連結，逐一判斷哪些是公開的、哪些是私人的。
- **查到了怎麼辦**：拿掉網址，改寫成「要看請在對話裡問」；它的結論該留下的話，用自己的話寫進公開檔案。

### 5. 真實憑證、連接器識別碼、真實資料

- **查什麼**：金鑰、權杖、外接服務的識別碼、真實的帳務或個資樣本。
- **怎麼查**：先確認忽略清單真的有擋住那些檔（而且**從第一顆提交就擋住**），再對歷史查一次。
- **查到了怎麼辦**：**憑證類一律當成已外洩處理——先去換掉那把金鑰，再談要不要清歷史**。順序不能反。

### 6. 討論串與雲端日誌

- **查什麼**：留言裡有沒有第 2〜5 項的東西。⚠️ **留言不在版本控制裡**，前面那些指令查不到它們。
- **怎麼查**：⚠️ 這裡有**五種不同的載體**，它們**各自有各自的取得方式，互相取代不了**——少抓一種就是沒查完：
  1. **issue 與 PR說明的本文**（含**已關閉**的）。
  2. **一般留言**（issue 與 PR 底下那種）。
  3. **審查的整體意見**——另一個端點（`/pulls/{編號}/reviews`），前兩種抓不到。
  4. **審查的行內留言**——又是另一個端點（`/pulls/{編號}/comments`），跟第 3 種也不是同一個。
  5. **掛在提交上的留言**（`/repos/{帳號}/{倉庫}/comments`）——⚠️ **最容易整個忘掉的一種**；前面四種、加上提交訊息本身，**都代替不了它**。

  另外還要抓**雲端檢查的執行紀錄與日誌**（轉公開之後**所有人都看得到**）。

  ⚠️ **每一種都要翻頁**（平台預設只給第一頁，沒翻完＝沒查完）——翻頁是**取得方式**，不是第六種載體。

  抓下來之後，用第 2 項那組詞再查一次。

  ⚠️ **這個清單只涵蓋上面列出的載體**。平台若另外開了討論區那類功能，那是**獨立的載體**、要另外查——本清單目前沒有涵蓋它。
- **查到了怎麼辦**：⚠️ 編輯舊留言會留下修訂紀錄，**可能反而多指一次**。要不要改是裁示，不是實作者自己決定。

### 7. 分支、標籤、殘留檔

- **查什麼**：沒刪的舊分支、暫時放進去又忘了拿掉的檔（備份、探針、輸出檔）。
- **怎麼查**：列出所有遠端分支與標籤；對歷史查**曾經被刪除過的檔名**：`git log --all --diff-filter=D --name-only`。⚠️ 那印出來的是「**刪除事件**」，不是「現在不存在」——刪掉後又加回來的也會列出來，所以命中之後要再確認現在的樹裡有沒有。
- **查到了怎麼辦**：⚠️ **不要直接刪分支**。先確認那一支**還要不要、內容能不能丟**；**要不要刪是裁示，不是實作者自己決定**（跟下面「收口」那一條一致）。而且**刪分支不等於清掉它的提交**——別的 ref 或 PR 引用可能還指著。檔案落在第 2〜5 項的話，照那一項處理。

## 收口

- 七項**每一項都要留下「查了、結果是什麼」**，寫在**不會公開的地方**。沒留紀錄＝那一項沒查。
- 只要有任何一項查出東西，**先停下來問裁示者**，不要一邊改一邊公開。
- 清單跑完**不等於安全**：它只涵蓋列出來的七類，而且每一項的射程只到你實際查過的範圍（規矩 K4）。

## 誠實劃界

- **沒有任何考題、閘或複審在看這張清單有沒有被跑過。** 它靠人。
- 它**驗不到**：平台端的快取與別人早就複製走的副本；轉公開之後才加進來的東西；你沒有列進詞表的那些詞；**本機沒有 fetch 到的 ref**；以及平台上已經刪掉、但紀錄可能還在別處的東西。
- **每一條指令的射程就是它自己的射程**：`--all` 只到本機已取得的 ref；逐顆翻內容的查法只查檔案內容、不查提交訊息；翻頁沒翻完的留言等於沒查。**零命中只代表「用這個方法、在這個範圍內沒找到」**，不代表不存在。
- 它**不保證**「跑完就可以公開」——要不要公開是裁示者的決定（個人狀況那一類由擁有者決定，規矩 B5），這張清單只是把該看的先看過一遍。
