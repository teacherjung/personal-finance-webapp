# 進度回報的版面與發出前的核對（本文 J1）

七段的標籤、順序、空段寫什麼，以本文 J1 為準；最後一行「進度摘要」怎麼寫、摘要怎麼維護，以本文 J5 為準。這裡只放本文沒寫的版面細節與發出前的核對，不複述。

- 被問進度（「好了沒」「做到哪」）也算進度回報，照七段寫；不是進度的解釋、確認、選項，直接答
- 七個標籤各自一行，用【】框起來（例如【目標】），不加粗體、不加圖示，照 J1 的順序；段與段之間空一行
- 每一段的內容一律寫成清單（`- `），只有一條也是；子項目縮排成第二層（畫面上是空心圓點）。最後一行「進度摘要」照 J5，不加清單符號
- 合併指令如果紅過：在 `要你注意的` 寫第幾趟、紅在哪一道（不另貼留言）
- `達成了沒有`：寫實際做到哪一步；還沒達成，第一句寫 `還沒`，標籤不換；下一步在等誰、做什麼，也寫在這一段
- 審查點、要 **裁示者** 決定的問題，用編號清單（`- ①`、`- ②`…）；每一題的形狀照 I1，要附的留言網址見 `templates/ruling-record.md`
- 前六段裡的審查點只寫一句白話判定（逐條對帳照 J1 放 `附件`）
- 一次報好幾件事：在同一套七段裡按主題歸類，每件講它對 **裁示者** 有什麼用；其餘細節他問才講（J2 要照報的照報）
- `附件` 裡的每個連結、留言編號，發出前實際打開查一次；查不到照 J4 寫 `沒量過`，不憑印象寫
