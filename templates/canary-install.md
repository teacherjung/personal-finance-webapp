# 測試鈕的裝法（禁區攔截器的驗收工具，B1）

攔截器沒裝好、沒按信任、或載入就崩的時候，看到的畫面跟「它好好地在擋」一模一樣。要證明它活著，只能叫一個**照清單該擋**的工具、親眼看到那一組的拒絕理由；而任何會動到禁區的真工具一律**絕不可以**叫來試（連唯讀的查詢也不行）。所以清單上刻意放一個就算真的執行了也無害的名字，本體＝`tools/canary-server.js`（裁示者 2026-09-15 裁「8a」）。

工具的完整名字（三個地方要一字不差）：

```
mcp__guard_canary__ping
```

## ① Claude 側登記

專案根目錄的 `.mcp.json`（沒有就新建；已經有就把 `guard_canary` 那一列加進 `mcpServers`）：

```json
{
  "mcpServers": {
    "guard_canary": {
      "command": "sh",
      "args": [
        "-c",
        "root=\"$(for v in $(env | sed -n 's/^\\(GIT_[A-Za-z0-9_]*\\)=.*/\\1/p'); do unset \"$v\"; done; git rev-parse --show-toplevel)\" && exec node \"$root/tools/canary-server.js\""
      ]
    }
  }
}
```

⚠️ **不可以寫成相對路徑**（`"args": ["tools/canary-server.js"]`）：伺服器的工作目錄跟著「你從哪個目錄開 Claude」走，不是專案根目錄；平台給的專案目錄變數也一樣跟著走（2026-09-16 實測：從專案的子目錄開，兩者都指到那個子目錄，`.mcp.json` 卻仍被找到）。從子目錄開的那幾次，伺服器就起不來、工具從清單上消失——而這正是驗收時最會被誤判成「被擋住」的樣子。所以這裡跟 Codex 專案層鉤子用同一招：先清掉 `GIT_` 開頭的環境變數（規矩 E4），再問版本控制的根目錄。專案不在版本控制裡的話，改填伺服器的絕對路徑。

第一次啟動時介面會問要不要信任這個專案的伺服器，要按同意，工具才會出現。

## ② Codex 側登記

家目錄的 `~/.codex/config.toml` 加一段（全域設定看不到「現在在哪個專案」，所以這裡要寫絕對路徑）：

```toml
[mcp_servers.guard_canary]
command = "node"
args = ["<專案根目錄的絕對路徑>/tools/canary-server.js"]
```

專案不會一直停在同一個位置（例如常切到別的分支、或路徑會搬）的話，改成把 `tools/canary-server.js` 複製到家目錄底下一個固定的地方（例如 `~/.local/share/ai-collab-kit/canary/`）再指過去；代價是複本不會跟著套件更新——它本來就什麼都不做，所以舊複本照樣能用。

## ③ 名字加進禁區清單

`settings.json` 的 `forbidden.deny` 加上 `mcp__guard_canary__ping`，**永久留著**（每次改清單、換複本、重按信任都要再按一次這顆鈕）。

⚠️ **不要**把它加進 AI 平台自己的拒絕清單（Claude Code 的 `permissions.deny`；**這一條只講 Claude Code**，別的平台沒去核過）：設定檔裡針對外接工具的拒絕規則**只能寫光名字**（帶括號的那種會被整條跳過），而光名字的效果是**那顆工具在規則存在的期間不可呼叫**——官方權限文件逐字（2026-09-21 讀）：「A bare tool name like Bash removes the tool from Claude's context entirely, so Claude never sees it.」。所以放進去的後果不是「按下去量到的是平台、不是攔截器」，是**根本按不到**。
（這裡說「不可呼叫」而不是「所有清單上的定義都消失」，是因為官方快取那一頁另寫：已經在進行中的對話與工具搜尋可能仍留著定義。要的結論一樣——按不到就驗不到攔截器。）

⚠️ **受管設定層（系統那一層）更不可以放**：那一層的規則在的期間這顆鈕一樣不可呼叫，而且**要管理員把那個檔改掉或刪掉才恢復**。那一層的裝法、驗收與守不到＝[managed-deny-install.md](managed-deny-install.md)。

⚠️ 原本已經有別的攔截層並存時，這個名字要**只有新那一層擋得住**：別的層的清單裡不要有它。這樣看到拒絕才代表新那一層在跑。

## ④ 驗收

照 `tools/guard-copy.js` 檔頭⓪〜⑥做（Claude 側活讀裝法與 Codex 專案層沒有固定複本那幾步，其餘一樣；Claude 側釘指紋裝法另有自己的順序，寫在同一個檔頭裡）：裝好、按信任之後叫這個工具，要看到**那一組**的拒絕理由（含「在拒絕清單上」）。叫一般工具照常能用證明不了什麼——鉤子沒跑時它也能用。

⚠️ 任何會動到禁區的真工具，不論在不在清單上、不論攔截器擋不擋得住，一律絕不可以叫來試；驗收只准用這一支。

## 守不到的

- 它只證明「那一刻、那一組、那一個名字」有被擋；別的名字擋不擋得住，靠攔截器自己的考題。
- 它是**每個 session 啟動時都會被執行**的一支程式，所以本體刻意什麼都不做（不讀檔、不連網、不看環境變數、不執行別的程式）。考題 `tests/canary-server.test.js` 把這個檔的位元組釘住（改一個字元都要重算雜湊、重算的人要負責看過），另外掃原始碼有沒有出現取得能力的那幾個字串——**掃描只是絆線**，換個寫法一樣做得到；兩樣都不證明 node 自己沒做什麼。
- 登記在兩家 AI 的設定裡這件事沒有機器看著：設定檔被改掉、或這支被換成別的程式，要靠人核對。
