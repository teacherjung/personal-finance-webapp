# 問裁示者、裁示落地與驗收留痕（本文 I1〜I3、H6）——形狀要對得上待裁清單工具的解析器；解析器認的裁示者識別值、撤回自報句裡的識別值、貼文帳號都讀 `settings.json` 的參與者登記（`PROJECT-SETTINGS.md` 第一節是它產生的表，改要改 `settings.json`），不寫死（見 MACHINES.md D1 列）

## 先確認裁示者（A1）

擁有者是人，裁示者是他指定負責判斷的人或 AI；沒有指定就由擁有者判斷。這是既有角色分工，不需要每道題重新申請委任。實作者先找可查證的擁有者指示，核對涵蓋的專案／工作範圍，再登記。AI 的自行宣告、工作階段名稱、模型名稱或共用貼文帳號都不能代替指派來源。

設定唯一正本是 `settings.json`，人讀的 `PROJECT-SETTINGS.md` 由 `node tools/build-settings.js` 產生。`owner` 放擁有者的參與者識別值；`participants` 登記各裁示者識別值與實際貼文帳號。AI 使用共用帳號轉貼時，標頭仍寫真正作判斷的 AI，原話行寫實際轉述者，不冒充本人。

選填 `rulingAssignments` 是指派時間表，每筆恰有以下六欄；例如（範例不是實際授權）：

```json
{
  "id": "engineering",
  "decider": "Sol",
  "scope": "擁有者指定的本工作線工程與必要前置",
  "source": "https://example.com/owner-instruction",
  "from": "2026-10-14T05:54:25Z",
  "until": null
}
```

- `id`：穩定的路由名稱，用英數字起頭，後接英數字、點、底線或連字號，最多 80 字。`default` 專指全專案預設裁示者；其他名稱是明列範圍，例如 `engineering`。路由不綁人名，換人沿用它。
- `decider`：參與者表裡唯一登記的識別值。`scope`：照本人指示寫出涵蓋的專案／工作與排除事項，不擴張授權。`source`：可查證的本人指派完整 HTTPS 網址。工具只驗來源形狀，原話真偽與範圍仍要人核對。
- `from` 與 `until`：帶時區的生效時間，包含開始、不包含結束；未結束填 `null`。依裁示／撤回留言的**建立時間**取當時有效期，不以今天或標頭日期重判歷史。同一路由的期間不能重疊；相接或有空窗可以。具名路由在空窗無人可裁，`default` 空窗回擁有者。

**舊設定與換人**：沒有非空指派表的舊專案，`owner` 缺席、未填或無法唯一辨認時，可沿唯一已填的舊裁示者，但沒有本人優先權；啟用非空指派表必須先正確登記擁有者。還沒有任何 `default` 時間表時，工具相容參與者角色以「裁示者」開頭的唯一一位；沒有則回擁有者，多位則退 2，不能拿排列第一位當答案。只改角色文案會使舊預設的歷史無法辨認，換人要改用時間表。第一次遷移若舊預設 A 不是擁有者，保留 A 的歷史段（`id: "default"`、`from: null`、`until: 換人時刻`），再加 B 的新段（同一 id、`from: 換人時刻`、`until: null`）；`from: null` 只准 default 的最早歷史段，表示舊制未載起點。若起點有證據，填真實時間。已有 default 時間表之後，角色描述不再決定預設；舊期、指派來源與參與者身分都要保留，不能刪掉舊期或把 A 那筆直接改成 B。具名範圍換人同樣關舊期、加新期，開始時間必須明確。同一路由的範圍若實質改變，另立 id，不改舊期的用途。角色表仍唯一登記非擁有者的舊預設時，時間表若完全沒有該人的 default 期間，工具拒絕產生與採計。這只查仍可見的舊候選，不能證明所有歷史都已帶齊。首次登記前後比對 D1 的舊裁示配對，確定未遺漏歷史；送審提供這份比對，工具不會替你復原被刪掉的舊設定。

**本人保留事項**：擁有者可以直接裁示；他的有效直接裁示優先作為同題配對依據，建議留痕不加指派行；附帶指派行寫錯會列提醒，但不會把本人裁示變成需要受指派者許可。指派不會放寬錢與禁區、A5 本人保留決定、或 H6 的本人實際驗收。明確要求暫停的工作也不能因指派而續做。有衝突、範圍不明或裁示者失聯，依規則回到擁有者，不自己假設有答案。

新問題與指定答案在標頭下一行填 `裁示指派：engineering`（換成實際 id），讓讀者知道交給誰。預設路由可寫 `裁示指派：default`；沒有指派行的舊裁示依當時預設判斷。 疑似欄位的辨認只看有效開頭與第一停止行（停止行僅能拒收，其後不讀）：前綴可由 Unicode 空白（White_Space）、標點（P）、符號（S）、數字（N）、組合記號（M）、預設可忽略碼點（Default_Ignorable_Code_Point）構成；中文數字（零〇一二三四五六七八九十百千萬兩壹貳參肆伍陸柒捌玖拾佰仟）或 ASCII 單字母列號須緊接 `.．、)）` 之一，才可當前綴。去掉候選前綴後，須以固定「裁示指派」接行尾或上述 Unicode 類別起首；一般正文提及欄名不算。這只辨認要拒收的疑似行，合法指派仍只認原始、唯一且精確的 `裁示指派：id` 整行，不能把去除修飾的結果當授權；縮排、半形冒號、尾文、重複等候選列為格式錯誤，不當成未指定；格式錯誤請照一題一則原則補清楚，不能靠預設答案略過。舊問題未寫指派行，可由既有受指派裁示者用標準新留言引回原題，實作者與複審核對題目確在範圍內，不重問本人、不改舊留言。原題明列路由時，答案／撤回必須走同一路由；只有擁有者直接裁示可跨路由處理，撤回沒有此例外。

舊題沒有指派行、卻出現不同路由的合法答案或撤回時，工具保留待裁並提示衝突，不任選最早一則；有擁有者直接裁示時以本人為準。

機器會核標頭、帳號、原話行、指派、時間與原題引用。它不理解自然語言範圍，也不能驗證引號內容真的是該裁示者說的；「已裁」仍是可檢查的配對推導。實作者先核來源與範圍，再跑待裁清單；獨立複審再核一次。設定壞了＝算不出來，不是零待裁。

## 問

貼在**這個問題所屬的PR**上（沒有所屬PR＝貼在提出它的那支）；貼出後**不編輯**，改題＝另貼一則新的。第一行逐字：

## ❓ 待裁（YYYY-MM-DD）：〈一句白話問題〉

若走明列路由，標頭下一行填 `裁示指派：〈id〉`；一行只填一個，不能重複。

內文：選項（最多三個）／建議的預設／類別聲明（屬不屬於錢、金額口徑、閘變鬆、明確指派、畫面驗收、事故通報這幾類）。給裁示者的七段回報裡「要你裁示的」照常問，並附這則留言的網址。沒有時限，問了就等。

## 裁示落地（一題一則，貼在同一支PR；原 ❓ 留言的網址**寫在開頭那一段**——任何引用、程式碼、表格、HTML、圖片、連結定義、縮排之前；機器讀到第一個那種行就停）

第一行逐字（識別值與「裁示」之間**一個半形空白**）：

## ⚖️ 〈裁示者識別值〉 裁示（YYYY-MM-DD）：〈標題〉

若走指派路由，標頭下一行先填 `裁示指派：〈id〉`。接著逐字照下面這行填，只換角括號裡的字、前後不加任何字（角色包粗體、包底線、多一個引用符號，解析器都判不合）：

原話（對話中，<轉述者識別值> 轉述）：**「逐字」**

原話可摘錄一個完整結論句，須逐字、標明「原話節錄」並附完整答覆來源；不得把實作者整理的摘要放進引號冒充原話。需要多行的完整原文可放在來源連結，解析器這行仍用單行完整句。

開頭有效段落只列本題的原 ❓ 網址，不提其他題的 ❓ 網址或裸留言編號；其他題引用放在第一個引用區塊之後。機器仍沿既有編號配對，若違反此寫作要求，仍可能誤配其他題；這項已知風險不是本次角色路由所能消除。

第二段起：原 ❓ 留言的網址、落點（改在哪裡的連結）；操作化（實作者的推論，分開標明、不混進原話）。要引用上一輪、貼程式碼或表格，放在這些之後。

## 合規撤回（只有發問方可以撤，而且只在「題目已經沒有對象可以回答」時）

第一行逐字：

## 🚫 撤回（YYYY-MM-DD）：〈標題〉

若原題明列路由，標頭下一行先填同一路由的 `裁示指派：〈id〉`。自報句寫撤回當時該路由的裁示者，不固定寫擁有者。內文三行都要有：

撤回理由：〈題目依附的東西沒了｜問題本身問錯了｜跟另一則 ❓ 重複〉（非空的具體依據）
〈撤回者識別值〉 撤回、〈裁示者識別值〉 未回；他隨時可以要我重問
〈原 ❓ 留言的網址（寫在開頭那一段）〉

理由三選一是解析器的**逐字枚舉值**，連「❓」那個記號都要照抄，改成同義詞＝不認。理由行與自報句管「形狀」：缺一＝解析器判成疑似（near）、原題仍待裁；網址管「配對」：缺網址、或寫在第一個引用／程式碼／表格分隔列／HTML／圖片／連結定義／縮排的行之後＝形狀雖合規但關不了題。撤回成功＝那題進「已撤回」，不是「已裁」；兩者都離開待裁。

## 收口只有兩種：裁示落地、或合規撤回。**不可自行當作已結**。

貼在本支還沒回的待裁＝本支不能按合併鍵（本文 A5）；純待辦照常。把範圍調整到那題跟本支無關，**那題仍然待裁、不可因此撤回**，本支也照樣要等它回。

## 驗收留痕（本文 H6：合併後要 **擁有者** 驗收的那一支，驗收做完貼在那一支PR；一支一則，貼出後不編輯）

第一行逐字：

## ✅ 驗收（YYYY-MM-DD）：〈標題〉

日期寫他驗收的那一天（不是貼留言的那一天）。第一段逐字照下面這行填，形狀跟裁示落地那一行相同：

原話（對話中，<轉述者識別值> 轉述）：**「逐字」**

第二段起：照哪幾步驗（照「PR說明」的「怎麼驗收」，寫第幾步、做了什麼）、看到什麼（他說的話、他傳的畫面上看得到的字；不貼含「個人狀況」的圖，B5）。

照實寫它證明到哪：這一則是 **實作者** 用共用帳號貼的轉述；它證明的是驗收紀錄「可找、可數、不會被刪」（不像進度摘要過了保留天數就清掉），不是「**擁有者** 真的看過」。待裁清單工具把它另列成「驗收留痕」，不算待裁、不算疑似；哪一支該貼卻沒貼，它不看。
